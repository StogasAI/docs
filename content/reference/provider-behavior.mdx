title: Compatibility notes
description: Where the API differs from calling a provider directly.
---

The gateway accepts the OpenAI Chat Completions and Responses formats for every provider. It checks
each request against the selected deployment before it calls the provider. A field that the
deployment cannot accept, or that the gateway cannot price, returns `400` and costs nothing. Each
[provider page](/docs/providers) lists the fields and tools that only that provider accepts.

## Rejected fields

| Endpoint         | Field                                  | Use instead                                                          |
| ---------------- | -------------------------------------- | -------------------------------------------------------------------- |
| Both             | `fallbacks`                            | A [routing policy](/docs/policies/routing)                           |
| Both             | `container`                            | Not available. See [Tools](/docs/model-tools#unavailable-tools)      |
| Both             | `speed`                                | A `-fast` deployment ID, such as `anthropic-claude-opus-5-fast`      |
| Both             | `inference_geo`                        | A `-us` deployment ID, or a [routing policy](/docs/policies/routing) |
| Both             | `moderation`                           | Not available. Requests and responses are not moderated              |
| Chat Completions | `functions`, `function_call`           | `tools` and `tool_choice`                                            |
| Chat Completions | `audio`                                | Not available. Output is text only                                   |
| Chat Completions | `prompt_cache_isolation_key`           | [`prompt_cache_key`](/docs/prompt-caching)                           |
| Chat Completions | `instructions`                         | A `system` or `developer` message                                    |
| Chat Completions | `max_output_tokens`                    | `max_completion_tokens`                                              |
| Chat Completions | `text`                                 | `response_format` and `verbosity`                                    |
| Responses        | `previous_response_id`, `conversation` | Send the whole conversation in `input`                               |
| Responses        | `prompt`                               | Send the prompt text in `instructions` and `input`                   |
| Responses        | `background`                           | A normal request, or a [stream](/docs/streaming)                     |
| Responses        | `stop`                                 | `stop_sequences`, where the provider accepts it                      |
| Responses        | `max_tokens`, `max_completion_tokens`  | `max_output_tokens`                                                  |
| Responses        | `reasoning_effort`                     | `reasoning.effort`                                                   |
| Responses        | `reasoning_max_tokens`                 | `reasoning.max_tokens`                                               |
| Responses        | `response_format`, `verbosity`         | `text.format` and `text.verbosity`                                   |
| Responses        | `web_search_options`                   | A `web_search` tool                                                  |

## Fields that the gateway changes

- Unknown top-level fields and unknown headers are ignored, and never sent to the provider.
- `null`, and the defaults that SDKs send, such as `n: 1` or a plain-text `response_format`, count
  as omitted. So do `parallel_tool_calls`, and `tool_choice` set to `auto` or `none`, in a request
  without tools.
- `store` accepts only `false`. The gateway never asks a provider to store a response.
- `safety_identifier` and `user` tell the provider which of your users sent a request, so the
  provider can act on that user instead of your whole account. Send an opaque value, such as a hash
  of your user ID: redaction doesn't change these fields. With your own credential:
  - OpenAI and Azure OpenAI receive both fields. Azure OpenAI rejects a `user` longer than 64
    characters on the Responses API.
  - Anthropic models receive `safety_identifier`, or `user` when it is the only one, as
    `metadata.user_id`, which accepts at most 512 characters.
  - Chutes receives neither.

  With a Stogas-managed credential, the gateway removes both.

- [`metadata`](/docs/request-records#metadata) and [`session_id`](/docs/request-records#sessions)
  go to the request record, not to the provider.
- `max_tokens` is another name for `max_completion_tokens` on Chat Completions.
- Streamed Chat Completions always include usage.
- Sampling values, such as `temperature`, go to the provider unchanged. The provider decides which
  values its model accepts.

## Conversation state

The gateway keeps no conversation state, so each request must contain the whole conversation. Every
tool call needs its result in the same request, before the next message. Function arguments
must be a JSON object encoded as a string.

## Output

Models return text, tool calls and citations. Image and audio output are not available. See
[Images and files](/docs/input-files) for the input that each provider accepts.

## Streams and cancellation

Errors before the response starts use an HTTP status. Later errors arrive as an event in the
stream. A cancelled request can still be billed for the usage that the provider reports. See
[Streaming](/docs/streaming) and [Errors](/docs/reference/errors).
