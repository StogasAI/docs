title: Compatibility Notes
description: The small set of Stogas behaviors that differ from a direct provider API.
---

Stogas supports the cataloged interfaces for OpenAI, Anthropic, Azure, and Chutes deployments. Operation pages show accepted fields; rejected compatibility fields are collected here.

## Routing

Choose a public model ID from `/v1/models`. If a slug is available from more than one provider, use `provider` or its `rules` alias:

```json
{
	"provider": { "only": ["anthropic"] }
}
```

Do not send both fields. Routing hints are removed before upstream dispatch.

## Service tiers

Service tiers are deployment capabilities, not portable promises across providers.

| Provider  | Accepted values                               | Behavior                                                                                                                                                                        |
| --------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI    | `auto`, `default`, `fast`, `flex`, `priority` | `fast` and its accepted legacy spelling `priority` select the same Fast deployment. `scale` and `provisioned` are unavailable.                                                  |
| Anthropic | `default`, `standard`, `standard_only`        | All values select the cataloged Standard Tier and are sent upstream as `standard_only`. `auto` and `priority` require a separate Priority Tier contract; `flex` does not exist. |

An exact deployment slug rejects a `service_tier` value that selects a different deployment.

## Prompt caching

Prompt caching remains at the selected provider. Stogas does not store complete model responses.

| Provider  | Implicit caching | Client controls                                                                                                                                                                     |
| --------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI    | Yes              | Chat and Responses accept `prompt_cache_key` and model-specific legacy retention. GPT-5.6 uses `prompt_cache_options` and content-block `prompt_cache_breakpoint`.                  |
| Anthropic | Opt-in           | Chat and Responses accept top-level and supported content-block `cache_control`; TTL is `5m` or `1h`.                                                                               |
| Azure     | Yes              | Chat and Responses accept `prompt_cache_key`; cataloged GPT-5.6 deployments accept `prompt_cache_retention: "24h"` but not options or breakpoints.                                  |
| Chutes    | Yes              | No client cache-control fields.                                                                                                                                                     |

Cache reads and writes appear in the endpoint's input-token usage details when the provider reports them. Provider-specific breakpoint formats are not translated across deployments. See [Prompt caching](/docs/prompt-caching) for the complete contract and Azure accounting limitation.

## Rejected fields

These familiar provider fields are intentionally outside the current Stogas surface:

| Endpoint         | Rejected fields                                                                                                    | Use instead                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Chat Completions | `audio`, `container`, `fallbacks`, `function_call`, `functions`, `prompt_cache_isolation_key`, `safety_identifier` | Text content; `tools` and `tool_choice`; server-owned routing, retention, and safety identity                               |
| Responses        | `background`, `container`, `conversation`, `fallbacks`, `previous_response_id`, `safety_identifier`               | Synchronous requests with complete client-supplied conversation state; server-owned routing, retention, and safety identity |

Unknown or rejected top-level fields return `400`; they are never forwarded opportunistically.

## Other differences

- Requests are strict: unknown top-level fields return `400` instead of being forwarded.
- `store` may be omitted or set to `false`. `store: true` is rejected, and Stogas never enables provider response storage.
- The current public surface accepts text content only.
- `stream: true` uses the endpoint's normal Server-Sent Events format.
- OpenAI `max_tokens` is accepted as an alias for `max_completion_tokens` on Chat Completions.
- Anthropic deployments reject requests that set both `temperature` and `top_p`.
- Provider-specific speed and inference geography are selected with an exact deployment slug, not request parameters.
- Provider-specific cache controls and hosted tools are accepted only where the catalog can route and bill them correctly.

See [Model Tools](/docs/model-tools) for supported function, MCP, and provider-hosted tools.

## Errors

Errors use an OpenAI-compatible `error` object. Common status codes are:

|        Status | Meaning                                    |
| ------------: | ------------------------------------------ |
|         `400` | Invalid or unsupported request             |
|         `401` | Missing or invalid API key                 |
| `402` / `403` | Billing or key policy rejected the request |
|         `413` | Request body too large                     |
|         `429` | Stogas or provider rate limit              |
|         `502` | Invalid or unavailable upstream response   |
|         `503` | No provider route was available            |
|         `504` | Upstream request timed out                 |
|         `529` | Provider overloaded                        |

Provider validation messages may be returned when useful. Provider credentials, topology, and internal failures are never exposed.

## Cancellation and billing

Disconnecting does not guarantee that the upstream provider stopped. A request may still be billed for usage the provider reports after the client disconnects. Streaming responses may remain open long enough to receive final usage needed for accurate settlement.
