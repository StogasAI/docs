The SDK works with the OpenAI client you already use. Before it sends your API key or a
prompt, it checks on your device that the gateway runs an approved release on confidential
hardware. Then it opens a connection that ends inside that gateway. Your code keeps calling Chat
Completions and Responses.

Published packages trust production gateways only. Native packages need a 64-bit x86-64 or ARM64
processor. To check a download, see [Verify an SDK download](/docs/reproducible-builds#verify-an-sdk-download).

## How the SDK connects

| SDK                                          | Connection                                                                                                      | Protection                       |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Rust, Python, Go, C, Java, .NET, Ruby, Swift | Runs the Rust connection engine in your process, and gives your client a local URL protected by a random secret | Attested TLS, or E2EE on request |
| JavaScript, browsers and Workers             | Gives your client a `fetch` function that runs the same engine as WebAssembly                                   | E2EE                             |

Kotlin, Scala, Clojure and F# use the Java or .NET package. Other languages embed the C library, or
run [`stogas serve`](/docs/cli) on the same machine. [Connection modes](/docs/connection-modes)
compares attested TLS and E2EE, and [Gateway verification](/docs/verification) lists each check.

## Connection settings

Create one transport when your application starts, reuse it for every request, and close it at
shutdown. In async native applications, start and close it away from the event loop or UI thread.

| Setting                         | Native SDKs                              | JavaScript SDKs                                |
| ------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| Protection                      | `tls` (default) or `e2ee`                | E2EE                                           |
| Connection maximum              | `max_connections`, default `4`           | `maxConnections`, default `4`                  |
| Origin                          | `base_url`: an HTTPS origin with no path | `baseURL`: an HTTPS address that ends in `/v1` |
| Retries, timeouts, cancellation | Your OpenAI client                       | Your OpenAI client and `AbortSignal`           |

Each language page gives the exact names. The origin setting cannot change the trusted keys or the
evidence sources.

- The transport opens one connection, and more only when requests wait, up to the maximum. A
  higher maximum does not spread requests across gateways.
- Connection setup, including the wait for a free connection, can take up to 15 seconds of your
  request deadline.
- A request through a native SDK's local URL can run for up to one hour.
- E2EE request bodies can be up to 128 MiB, and response bodies up to 64 MiB.
- JavaScript SDKs keep each encrypted upload in memory until it is sent. Limit how many large
  uploads run at once, especially in browsers.

## Retries

The OpenAI client decides whether to retry. The SDK keeps the HTTP status, the body and headers
such as `Retry-After`.

If a connection drops after a request was sent, the model may already have run, and a retry runs it
again. The examples set retries to zero for this reason. The SDK sends a request once more only
when the gateway refused it before starting it, for example because the gateway closed an idle
connection or began an update as the request arrived. Requests that are already
running when a gateway begins an update finish. [Sessions](/docs/connection-modes#sessions)
explains what happens to later requests.

## Check evidence offline

The Rust core, and its WebAssembly and C APIs, also verify caller-supplied evidence without network
access, with the same checks as the transport. See [JavaScript](/docs/javascript#check-evidence-offline),
[Python](/docs/python#check-evidence-offline) and the [CLI](/docs/cli).
