The SDK works with the OpenAI client you already use. Before it sends your API key or a prompt, it
checks on your device that the gateway runs an approved release on confidential hardware. Then it
opens a connection that ends inside that gateway.

Published packages trust production gateways only. Native packages need a 64-bit x86-64 or ARM64
processor. To check a download, see
[Verify an SDK download](/docs/reproducible-builds#verify-an-sdk-download).

## How the SDK connects

| SDK                                          | Connection                                                                                                      | Protection                       |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Rust, Python, Go, C, Java, .NET, Ruby, Swift | Runs the Rust connection engine in your process, and gives your client a local URL protected by a random secret | Attested TLS, or E2EE on request |
| JavaScript, browsers and Workers             | Gives your client a `fetch` function that runs the same engine as WebAssembly                                   | E2EE                             |

Kotlin, Scala, Clojure and F# use the Java or .NET package. Other languages embed the C library,
or run [`stogas serve`](/docs/cli#serve) beside the application.
[Connection modes](/docs/connection-modes) compares attested TLS and E2EE.

## Options

Create one transport when your application starts, reuse it for every request, and close it at
shutdown. In async native applications, start and close it away from the event loop or UI thread.

| Option            | Default | Effect                                                                                                                                 |
| ----------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `security`        | `tls`   | `tls` for [attested TLS](/docs/connection-modes#attested-tls), or `e2ee` for [E2EE over HTTPS](/docs/connection-modes#e2ee-over-https) |
| `max_connections` | `4`     | The most connections or E2EE sessions. The transport opens one, and another only while requests wait.                                  |
| `base_url`        |         | Another HTTPS origin, with no path. The trusted keys and evidence sources stay the same.                                               |
| `proxy`           |         | A [proxy](#connect-through-a-proxy-or-tor) for every connection, as `socks5h://host:port` or `http://host:port`                        |
| `onion`           | `false` | `true` reaches Stogas at its [onion address](#connect-through-a-proxy-or-tor) through `proxy`                                          |

Each language spells the names its own way, such as `MaxConnections` in Go and .NET and
`maxConnections` in Swift. [`stogas serve`](/docs/cli#serve) takes them as flags.

JavaScript always uses E2EE. Its `baseURL` ends in `/v1`, and these options replace `proxy` and
`onion`:

| Option       | Effect                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fetch`      | The `fetch` function that sends every request, evidence included                                                                                        |
| `onMetadata` | Receives each response's `stogas` object after its [receipt](/docs/receipts) passes the check                                                           |
| `proxied`    | `true` when `fetch` uses a proxy, such as Tor, so that every time limit is four times as long; `true` by default on a page served from an onion address |

The transport loads evidence when it starts, and again only when a session needs newer evidence.
To load it now, call the transport's refresh method, such as `refresh_evidence()` in Python.

### Limits

- Connection setup, including the wait for a free connection, can take up to 15 seconds of your
  request deadline, or 60 seconds through a proxy.
- A request through a native SDK's local URL can run for up to one hour.
- E2EE request bodies can be up to 128 MiB, and response bodies up to 64 MiB.
- JavaScript keeps each encrypted upload in memory until it is sent, so limit how many large uploads
  run at once.
- More connections do not spread requests across gateways.

## Connect through a proxy or Tor

Set `proxy` to Tor's SOCKS port, usually `socks5h://127.0.0.1:9050`, or `9150` for Tor Browser.
Every connection that the SDK opens then goes through Tor: evidence downloads, attested TLS and
E2EE. Stogas sees a Tor address instead of yours, and with `socks5h`, Tor resolves the host names
instead of your DNS server. A username and password give your application Tor circuits of its own:

```text
socks5h://myapp:secret@127.0.0.1:9050
```

An HTTP proxy, such as a company network's, takes `http://host:port`. The SDK asks it to connect to
each host by name, so TLS still runs from your application to Stogas.

Set `onion` to `true` as well to reach Stogas at its onion address, so that your traffic does not
leave Tor. TLS checks the same certificate and attestation. In an environment without an onion
address, `onion` connections leave Tor through an exit relay.

- The SDK ignores proxy environment variables. Your HTTP client talks only to the local URL, so
  turn off proxies for it.
- JavaScript sends every request through the `fetch` that you give it, so a `fetch` that uses your
  proxy sends them all through Tor. Set `proxied` to `true` with it.
- The [CLI](/docs/cli#connect-through-tor) finds Tor itself with `--tor`.

## Retries

The OpenAI client decides whether to retry. The SDK keeps the HTTP status, the body, and the
`Retry-After` and `X-Should-Retry` headers.

If a connection drops after a request was sent, the model may already have run, and a retry runs it
again. The examples set retries to zero for this reason. The SDK itself resends only requests that
the gateway refused before starting them, as [Sessions](/docs/connection-modes#sessions) explains.

## Check evidence offline

The Rust core, and its WebAssembly and C APIs, also verify evidence that you supply, without network
access and with the same checks as the transport. See
[JavaScript](/docs/javascript#check-evidence-offline), [Python](/docs/python#check-evidence-offline)
and the [CLI](/docs/cli#check-evidence-and-receipts).
