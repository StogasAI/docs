Filters, sorts and rule conditions read these fields for each [candidate](/docs/policies/routing):
its author, model, deployment, route and provider, and the request. Deployment fields hold the
deployment's values on the candidate's route. For example, `deployment.contextWindowTokens >= 128000`
keeps deployments with a context window of at least 128,000 tokens.

The [catalog](https://stogas.ai/catalog) shows current IDs and values, and its search accepts these
fields.

## Types

| Type          | Example                      | Available operations                                     |
| ------------- | ---------------------------- | -------------------------------------------------------- |
| `string`      | `'openai'`                   | Equality, ordering, membership, string methods, sorting. |
| `integer`     | `128000`                     | CEL integer arithmetic, comparisons and sorting.         |
| `decimal`     | `decimal('0.001')`           | Exact price comparisons, membership and sorting.         |
| `boolean`     | `true`                       | Boolean logic, equality and sorting.                     |
| `string_list` | `deployment.inputModalities` | Membership and CEL list macros.                          |
| `timestamp`   | `request.time`               | CEL time comparisons and time-zone methods.              |

- IDs and strings are case sensitive.
- Dates are `YYYY-MM-DD` strings, so `<` and `>` compare them in date order.
- A field can be missing on a candidate, as
  [Missing values](/docs/policies/expressions#missing-values) explains.
  `has(field)` checks presence. On a group such as `deployment.pricing`, `has` is true when any field
  in the group is present.
- Unknown fields, wrong types and strings that a field can never hold, such as `'EU'` for a
  location, fail when you save.

### Capabilities

Each field is `true` when the deployment supports the feature on the candidate's route. The
gateway skips candidates that lack a feature that the request uses, and returns `400` when none
remain.

<RoutingFields group="capabilities" />

### Data handling

These fields describe what the provider can do with request and response content. Each value is
the worst case across every configuration and optional feature that the offering allows: a
persistent cache that the offering allows counts even when your request does not use it. A more
private configuration gets a stronger value only when the gateway enforces it on every request. A
location that the provider does not disclose is `unknown`, and an undisclosed retention period or
training use is missing.

<RoutingFields group="data-handling" />

Temporary in-memory prompt caching is compatible with zero data retention and is excluded from
`retentionDays`. Persistent caches are not exempt. `retentionDays` covers routine retention only.
Exceptional retention, such as a legal hold or review of content flagged for abuse, follows the
provider's terms, and a provider that keeps flagged content for review does not have zero data
retention. A promise not to train does not establish zero retention. These facts apply to the
selected offering and do not cover other provider services.

When a request lets the model call [hosted tools](/docs/model-tools#data-handling-of-hosted-tools),
these fields join the deployment's data handling with each tool's. A location becomes the smallest
place that holds both, `retentionDays` becomes the longer period, or missing when either is
unknown, and `zeroDataRetention`, `endToEndEncrypted`, `tee` and `teeVerified` stay `true` only when
every tool keeps them. `trainingUse` becomes `true` when a tool can train on content. For example,
a deployment that processes in `US` with a tool that processes in `DE` reads `world`.

`processingLocation` covers model inference and the hosted tools that the model may call. It does
not cover where the provider's API endpoint receives and routes the request. `tee` and
`teeVerified` describe the provider's inference workload, and `endToEndEncrypted` describes the
connection from the gateway to that workload. None of them is proof that every component that can
read content is trustworthy.

#### Location values

| Value                     | Meaning                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| `US`, `DE`, …             | One country, by uppercase ISO 3166-1 alpha-2 code.                                                     |
| `eu`, `europe`, `apac`, … | A region, such as the European Union, Europe or Asia-Pacific.                                          |
| `world`                   | No narrower boundary. Content can be processed or stored in any country.                               |
| `unknown`                 | The provider does not disclose a usable boundary. Policies match it only as `unknown`, not as `world`. |
| `none`                    | `storageLocation` only. The provider does not keep request or response content after the response.     |

A value names the widest area where the activity can happen. The catalog lists the places where
data can be: those that deployments, headquarters and provider accounts name, with the places that
contain them. Each region lists every country that it covers, including countries that the catalog
does not list, and a place lies in each region that lists all of its countries: `DE` lies in `eu`,
which lies in `europe`, which lies in `world`. A
[place's page](https://stogas.ai/locations/apac) shows its countries.
`processingWithin` and `storageWithin` list a deployment's location with every place that contains
it, so `'europe' in deployment.dataHandling.processingWithin` accepts deployments that process in
`europe`, in `eu` or in a European country. `unknown` and `none` lie in no other place, and `world`
only in itself, so the check refuses them.

Location values are case-sensitive: countries are uppercase and regions lowercase. Saving a policy
fails when it names a location that the catalog does not list, and the error names the place that
differs only in case, such as `eu` for `EU`.

`processingLocation` and `storageLocation` compare as exact text:
`deployment.dataHandling.processingLocation == 'europe'` does not match a deployment whose value is
`eu` or `DE`. Prefer checks that accept places to exclusions:
`deployment.dataHandling.processingLocation != 'US'` also accepts `world` and `unknown`.

## Pricing

Each field is the price of one meter in USD per million tokens, as an exact decimal. Some models
charge more for every token of a request whose prompt is over a size, such as 272,000 tokens. These
fields hold the prices for shorter prompts. To compare prices for a long prompt, use
[`blended_price`](/docs/policies/expressions#blended-price) with a prompt size.

<RoutingFields group="pricing" />

This policy keeps deployments whose output price is at most $2 per million tokens:

```json title="policy.json"
{
	"routing": {
		"filter": "deployment.pricing.output_tokens.per_mill_tokens <= decimal('2')"
	}
}
```

A missing price does not count as zero, so this filter does not match a deployment without an
output price.

Routing cannot read [hosted tool prices](/docs/model-tools#hosted-tools). Prices are catalog
rates, not the cost of a request. To cap spending, use a [spend limit](/docs/policies/limits#spending).
