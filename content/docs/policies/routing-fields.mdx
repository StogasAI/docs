A routing query reads the catalog chain for each candidate: its author, model, deployment,
route, and provider. `request` exposes the caller's selector, route, request time and exact
incoming JSON byte size. These are read-only fields, not settings you assign in policy JSON.

For example, `deployment.contextWindowTokens >= 128000` keeps deployments with a
context window of at least 128,000 tokens. It does not change their context window.

The tables below list every registered field. Unknown paths are rejected. A registered field
can still be missing on a particular candidate; see [Missing values](/docs/policies/routing#missing-values).
Inspect the [catalog](https://stogas.ai/catalog) for current IDs and values. A catalog capability
does not by itself enable a request feature that the Stogas API does not accept.

## Types

| Type          | Example                      | Available operations                                     |
| ------------- | ---------------------------- | -------------------------------------------------------- |
| `string`      | `'openai'`                   | Equality, ordering, membership, string methods, sorting. |
| `integer`     | `128000`                     | CEL integer arithmetic, comparisons and sorting.         |
| `decimal`     | `decimal('0.001')`           | Exact price comparisons, membership and sorting.         |
| `boolean`     | `true`                       | Boolean logic, equality and sorting.                     |
| `string_list` | `deployment.inputModalities` | Membership and CEL list macros.                          |
| `timestamp`   | `request.time`               | CEL time comparisons and time-zone methods.              |

Use `has(field)` to check presence. IDs and strings are case-sensitive. Catalog dates remain
strings; request time is a timestamp. See [Query syntax](/docs/policies/routing#query-syntax).

## Request

<RoutingFields group="request" />

`request.route` is `chat-completions` or `responses`. `request.bodyBytes` includes the exact
incoming JSON, whitespace and request controls before redaction. Token estimates and estimated
request costs cannot be used by routing or conditional rules. They are computed once after
selection for reservations and usage diagnostics. See [Request facts](/docs/policies/routing#request-facts-and-context).

## Pricing

Pricing fields use `deployment.pricing.<meter>.<rate>`. Their type is `decimal` and their
unit is USD per catalog rate unit. For example, `2` means $2 per million tokens when the rate
is `per_mill_tokens`. Comparisons preserve up to 36 fractional digits without floating point.

For example, this policy keeps deployments whose standard output price is at most $2 per million:

```json title="policy.json"
{
	"version": 1,
	"routing": {
		"filter": "deployment.pricing.output_tokens.per_mill_tokens <= decimal(\"2\")"
	}
}
```

The comparison stays exact because the decimal literal is part of the query string. A missing rate does not count as zero. The filter above does not
match deployments that define only context-tiered prices; include the relevant tier explicitly.

For a weighted input/output comparison, use
[`blended_price(inputWeight, outputWeight, 'rate')`](/docs/policies/routing#blended-price).
It uses the same explicit rates below, without estimating or selecting a request's context tier.

### Token meters

Each meter below accepts `per_mill_tokens`, `per_mill_context_lte_272k`, or
`per_mill_context_gt_272k`. Each rate is the price per million tokens in that meter and tier.

| Meter                         | Meaning                                                                     |
| ----------------------------- | --------------------------------------------------------------------------- |
| `input_tokens`                | Uncached input.                                                             |
| `cached_input_tokens`         | Cached input reads.                                                         |
| `cache_write_input_tokens`    | Cache writes without a separate duration tier.                              |
| `cache_write_5m_input_tokens` | Five-minute cache writes.                                                   |
| `cache_write_1h_input_tokens` | One-hour cache writes.                                                      |
| `output_tokens`               | Output tokens.                                                              |
| `reasoning_tokens`            | Reasoning tokens; may use the output rate when no separate rate is defined. |

Only the token meters and rates above are available to routing queries.
Provider-hosted tool charges are described in [Model tools](/docs/model-tools#provider-hosted-billing).

Pricing fields describe catalog rates, not an all-in request estimate or the amount charged to
your Stogas balance. Sorting on output price alone does not account for input, caching, tools,
or BYOK fees. For a spending ceiling, use a [spend limit](/docs/policies/limits#spend-allowances).
