---
title: Routing field reference
description: Every field available to routing filters and sort expressions, with types and pricing units.
---

A routing query reads the catalog chain for each candidate: its author, model, deployment,
route, and provider. `request` exposes the caller's selector and the token estimates for that
candidate. These are read-only fields, not settings you assign in policy JSON.

For example, `where deployment.data.contextWindowTokens >= 128000` keeps deployments with a
context window of at least 128,000 tokens. It does not change their context window.

The tables below list every registered field. Unknown paths are rejected. A registered field
can still be missing on a particular candidate; see [Missing values](/docs/policies/routing#missing-values).
Inspect the [catalog](https://stogas.ai/catalog) for current IDs and values. A catalog capability
does not by itself enable a request feature that the Stogas API does not accept.

## Types

| Type          | Query value                           | Available operations                                                          |
| ------------- | ------------------------------------- | ----------------------------------------------------------------------------- |
| `string`      | `'openai'`                            | Equality, ordering, `in`, substring `contains`, `exists`, sorting.            |
| `integer`     | `128000`                              | Equality, ordering, `in`, `exists`, sorting. No decimal or exponent literals. |
| `boolean`     | `true` or `false`                     | `==`, `!=`, `in`, `exists`, sorting.                                          |
| `string_list` | A list field compared with one string | Exact-item `contains` and `exists`. Cannot be sorted.                         |

Strings and IDs are case-sensitive. Dates remain strings; comparison uses their catalog text,
not date arithmetic. See [Query syntax](/docs/policies/routing#query-syntax) for operators and escaping.

## Route and provider

A catalog route is a connection between a provider and supported interfaces. Its ID is not the
HTTP request path. `request.route` below identifies the inference interface instead.

| Field                           | Type          | Meaning                                                                               |
| ------------------------------- | ------------- | ------------------------------------------------------------------------------------- |
| `route.id`                      | `string`      | Canonical route ID.                                                                   |
| `route.data.providerId`         | `string`      | Provider that owns the route.                                                         |
| `route.data.interfaces`         | `string_list` | Interfaces supported by the route.                                                    |
| `provider.id`                   | `string`      | Canonical provider ID.                                                                |
| `provider.data.name`            | `string`      | Display name.                                                                         |
| `provider.data.aliases`         | `string_list` | Provider aliases.                                                                     |
| `provider.data.credentialModes` | `string_list` | Catalog-supported credential modes. Does not describe this key's assigned credential. |

## Request

| Field                          | Type      | Meaning                                                                                |
| ------------------------------ | --------- | -------------------------------------------------------------------------------------- |
| `request.model`                | `string`  | Model or deployment selector supplied by the caller, before resolving to a catalog ID. |
| `request.route`                | `string`  | `chat-completions` or `responses`.                                                     |
| `request.estimatedInputTokens` | `integer` | Buffered input-token estimate used for admission for this candidate.                   |
| `request.maximumOutputTokens`  | `integer` | Accepted output-token maximum for this candidate.                                      |

These token values are estimates and limits, not final usage. Accepted encrypted reasoning replay
can require reserving the deployment's full input bound because its contents cannot be inspected.
Do not compare these fields to each other: query comparisons require a literal on the right side.

## Pricing

Pricing fields use `deployment.data.pricing.<meter>.<rate>`. They are **integers in USD atoms**:
one dollar is `1000000000000000000` atoms. This differs from spend settings, which use decimal
USD strings. A price of $2 per million tokens is the integer `2000000000000000000`.

For example, this policy keeps deployments whose standard output price is at most $2 per million:

```json title="policy.json"
{
	"version": 1,
	"routing": {
		"query": "where deployment.data.pricing.output_tokens.per_mill_tokens <= 2000000000000000000"
	}
}
```

The comparison uses exact integers even beyond JavaScript's safe-number range because the number
is part of the query string. A missing rate does not count as zero. The filter above does not
match deployments that define only context-tiered prices; include the relevant tier explicitly.

### Token meters

Each meter below accepts `per_mill_tokens`, `per_mill_context_lte_272k`, or
`per_mill_context_gt_272k`. Each rate is the price per million tokens in that meter and tier.

| Meter                         | Meaning                                                                     |
| ----------------------------- | --------------------------------------------------------------------------- |
| `input_tokens`                | Uncached input.                                                             |
| `cached_input_tokens`         | Cached input reads.                                                         |
| `cache_write_input_tokens`    | Cache writes without a separate duration tier.                              |
| `cache_write_5m_input_tokens` | Five-minute cache writes.                                                   |
| `cache_write_1h_input_tokens` | One-hour cache writes.                                                      |
| `output_tokens`               | Output tokens.                                                              |
| `reasoning_tokens`            | Reasoning tokens; may use the output rate when no separate rate is defined. |

### Call meters

These five meters accept only `per_1k_calls`, the price per thousand calls:

| Meter                                                     | Meaning                                                     |
| --------------------------------------------------------- | ----------------------------------------------------------- |
| `anthropic_web_search_calls`                              | Anthropic web search.                                       |
| `openai_chat_completion_search_model_calls`               | OpenAI Chat Completions search-model calls.                 |
| `openai_responses_web_search_calls`                       | Responses web search.                                       |
| `openai_responses_web_search_preview_calls`               | Responses preview web search.                               |
| `openai_responses_web_search_preview_non_reasoning_calls` | Responses preview web search for the non-reasoning variant. |

`openai_chat_completion_search_preview_model_calls` instead accepts
`per_1k_search_context_low_calls`, `per_1k_search_context_medium_calls`, or
`per_1k_search_context_high_calls`. No other meter/rate combinations are valid.

Pricing fields describe catalog rates, not an all-in request estimate or the amount charged to
your Stogas balance. Sorting on output price alone does not account for input, caching, tools,
or BYOK fees. For a spending ceiling, use a [spend limit](/docs/policies/limits#spend-allowances).
