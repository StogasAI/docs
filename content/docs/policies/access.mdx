Every resource that applies to a request must be enabled and unexpired. Enabled state and
expiration are settings of the resource. Deny periods and networks are in its policy, under
`access.deny` and `access.networks`.

## Enable or disable access

A disabled resource, or a disabled parent, blocks new requests, and requests that are running
continue.

## Blocked requests

A blocked request fails with `403` and the code of the resource that blocks it, such as
`folder_disabled` or `grant_expired`. When several resources block it, the code names the first of
the organization, folder, grant, role, member and key. A resource that is both disabled and expired
reports that it expired. A key's status in the dashboard names the same resource, and so does
`denial` in the [dashboard API](/docs/reference/dashboard/api-keys/getApiKey).

## Set an expiration

Set an expiration time on a key, grant or other resource, such as `2026-12-01T00:00:00Z`. From
that time, new requests are blocked and requests that are running continue. The earliest
expiration of every resource that applies wins, so removing a key's expiration does not remove its
grant's.

### Expiration or a rule on `request.time`

A [conditional rule](/docs/policies/rules#conditional-rules) can also change requests from a set
time, because its condition can read `request.time`. From December 1, this rule makes requests skip
OpenAI:

```json title="policy.json"
{
	"rules": {
		"leave_openai": {
			"when": "request.time >= timestamp('2026-12-01T00:00:00Z')",
			"routing": { "filter": "provider.id != 'openai'" }
		}
	}
}
```

Use an expiration when everything under a resource should stop, and a rule when only some requests
or deployments should change:

|                                         | Expiration                                  | Rule on `request.time`                                                             |
| --------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------- |
| Blocks                                  | Every request under the resource            | Only the requests and deployments that it matches                                  |
| Shown                                   | With the resource in the dashboard          | Only in the policy                                                                 |
| Saving                                  | Adds no policy version                      | Adds a policy version, which request logs record                                   |
| [Delegation](/docs/policies/delegation) | Does not apply                              | The scope must be allowed to save the rule's sections, such as `routing.filter`    |
| Error                                   | `key_expired`, `grant_expired` and the like | The error of the rule's settings, such as `schedule_denied` or `model_unavailable` |

## Deny periods

This policy blocks new requests before 08:00 on weekdays in New York:

```json title="policy.json"
{
	"access": {
		"deny": [
			{
				"days": ["mon", "tue", "wed", "thu", "fri"],
				"start": "00:00",
				"end": "08:00",
				"timeZone": "America/New_York"
			}
		]
	}
}
```

Use lowercase day names: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, and `sun`. Every field is
required. The start is included and the end is excluded, so the example permits requests at 08:00
if all other policies allow them. Use `00:00` to `24:00` to deny an entire day.

Outside the deny periods, this setting adds no restriction. To allow only business hours, deny
the hours outside that schedule and deny weekends. There is no separate `allow` schedule.

## Overnight periods

A period cannot cross midnight. Split Friday 20:00 through Saturday 08:00 into two entries:

```json title="policy.json"
{
	"access": {
		"deny": [
			{
				"days": ["fri"],
				"start": "20:00",
				"end": "24:00",
				"timeZone": "UTC"
			},
			{
				"days": ["sat"],
				"start": "00:00",
				"end": "08:00",
				"timeZone": "UTC"
			}
		]
	}
}
```

The second entry uses the following day. Equal start and end times are invalid and do not mean
all day.

## Daylight saving time

IANA time zones follow daylight saving time. A local hour that repeats is denied both times, and a
local hour that is skipped never occurs. Use `UTC` for a schedule that does not shift.

## How periods combine

Every required deny period from every policy applies. An empty `deny` array replaces default
periods only. A permitted [request policy](/docs/policies/request-policies) can add periods.

A deny period in a [conditional rule](/docs/policies/rules#conditional-rules) or a credential's
policy blocks only the deployments and credentials it applies to. The gateway tries the others,
and fails with `schedule_denied` when none remain. If a filter or list also removes a candidate, or
the candidate cannot read an [attachment](/docs/input-files#when-no-candidate-reads-a-file), the
error gives that reason instead.

## Networks

This policy accepts requests only from one address and two ranges:

```json title="policy.json"
{
	"access": {
		"networks": ["203.0.113.7", "198.51.100.0/24", "2001:db8:5::/48"]
	}
}
```

- List IPv4 and IPv6 addresses and CIDR ranges. A range starts at its first address, such as
  `198.51.100.0/24`, and an IPv4 address takes its IPv4 form, not `::ffff:198.51.100.7`.
- The gateway reads the address from the connection, never from headers such as
  `X-Forwarded-For`. For a server behind a NAT gateway or proxy, list the address that the NAT
  gateway or proxy sends from.
- A request from any other address fails with `403 network_denied`, and the message names the
  address that the gateway saw.
- A list can hold as many entries as the [policy size](/docs/policies/editing#document-rules)
  allows.

## How networks combine

Every policy that lists networks must hold the client's address. Two lists that share no address
block every request.

A [default rule](/docs/policies/rules#defaults) can list networks, and they apply until a required
policy lists its own. To replace them without a restriction, list every address:
`["0.0.0.0/0", "::/0"]`.

Networks in a [conditional rule](/docs/policies/rules#conditional-rules) or a credential's policy
block only the deployments and credentials it applies to. The gateway tries the others, and fails
with `network_denied` when none remain.

## Timestamps and time zones

`expiresAt` and recurring `anchor` values are ISO 8601 timestamps with `Z` or an explicit offset
in years 1 to 9999 UTC, for example `2026-12-01T00:00:00Z` or `2026-12-01T09:00:00+09:00`. Local
times without an offset are invalid. Saved timestamps are normalized to UTC with millisecond
precision.

`timeZone` accepts `UTC` or an IANA name with its exact capitalization, such as `America/New_York`
or `Europe/Berlin`, up to 64 characters. Abbreviations such as `CET` and offsets such as `+05` are
invalid. The timestamp's offset identifies an instant, and the time zone determines the local
schedule and its daylight-saving rules.
