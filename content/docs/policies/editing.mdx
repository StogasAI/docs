## Open the editor

| Scope          | Where to edit                                                               | Who can edit                                                                                     |
| -------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Organization   | **API Keys**, then **Organization policy**                                  | Members who manage all API keys                                                                  |
| Folder         | **Manage folders**, then the folder's **Policy**                            | The folder's managers, and members who manage all API keys                                       |
| Grant          | **Grants**, then the grant's **Settings**                                   | The grant's managers, its folder's managers, and members who manage all API keys                 |
| Member or role | **Members**, then the **Members** or **Roles** tab and the row's **Policy** | Members who manage all API keys                                                                  |
| Credential     | **BYOK**, then the credential's **Policy**                                  | Members who manage credentials                                                                   |
| API key        | The key's **Settings**                                                      | The key's owner and managers, its folder and grant managers, and members who manage all API keys |

A parent policy can [limit which sections](/docs/policies/scopes#permission-to-edit-saved-policies)
anyone can save. See the [permission reference](/docs/members#permission-reference).

## Save a policy

<Steps>
<Step>

### Edit the draft

The editor opens the saved policy. A save replaces the whole policy at that scope. Use
[the document fields](/docs/policies#document-fields) to find a setting.

</Step>
<Step>

### Save

The gateway checks the policy together with the other policies that apply at this scope. It checks
[encrypted plugin settings](/docs/customer-encryption#encrypt-plugin-settings) only when a request
or a [policy check](#check-a-policy-before-saving) sends their key.

</Step>
<Step>

### Check the result

On a key, open **Combined policy** to see the result of every policy that applies, and **Overview**
to see each limit and its usage.

</Step>
</Steps>

- If someone else saved the policy while you edited it, saving applies your changes to their
  version. If you both changed the same setting, or the result is not a valid policy, nothing is
  saved. The editor then shows the combined draft with your changes highlighted, and names the
  settings that you both changed. Check it and save again, or select **Use saved policy** to
  discard your draft.
- A parent save can make a policy below it invalid. That policy stays readable so that its manager
  can fix it.
- Enabled state and expiration are settings of the resource, not of its policy.
- See [When changes take effect](/docs/policies/scopes#when-changes-take-effect).

### Editor keys

Suggestions show fields, preset names, allowed values, time zones and catalog IDs as you type.
Inside routing expressions, they also show request facts, operators and catalog values.

| Key                    | Action                         |
| ---------------------- | ------------------------------ |
| `Ctrl` + `Space`       | Show suggestions               |
| `Enter`                | Insert the selected suggestion |
| `Esc`                  | Close suggestions              |
| `Tab`, `Shift` + `Tab` | Indent, outdent                |
| `Esc`, then `Tab`      | Leave the editor               |

**Format JSON** changes only whitespace. Encrypted sections show their key name and size: choose
**Show encrypted blob** to expand one. **Copy JSON** copies the whole saved policy, including
ciphertext.

## Check a policy before saving

[`POST /v1/policies/validate`](/docs/reference/policies/validatePolicy) checks the policies that
would apply to a request, without saving them or calling a model. Send the draft in place of the
saved version of its scope:

```jsonc title="Request"
// POST https://api.stogas.ai/v1/policies/validate
// Authorization: Bearer $STOGAS_API_KEY
{
	"policySources": [
		{ "scope": "organization", "config": { "plugins": { "stogasTextExtraction": true } } },
		{ "scope": "role", "id": "<role ID>", "config": { "timeouts": { "totalSeconds": 120 } } },
		{ "scope": "key", "config": null } // null is an empty policy.
	],
	"encryption_keys": { "default": "<key>" } // Optional. Checks encrypted plugin settings.
}
```

- Include exactly one organization and one key policy, plus each folder, grant, member and
  credential policy that applies. Give each role its own entry with its `id`, up to 30.
- Encrypted plugin settings are checked only with their [key](/docs/customer-encryption#send-the-key-with-a-request).
  Send the key the same way as with inference requests.

```json title="Response"
{ "status": "partial", "uncheckedPlugins": [{ "scope": "organization" }] }
```

| Result                               | Meaning                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| `"status": "valid"`                  | Every policy passed, including conditional rules that would not apply now.                  |
| `"status": "partial"`                | The rest passed. `uncheckedPlugins` lists encrypted settings without a key.                 |
| `400` with `invalid_policy`          | A policy is invalid. The message does not say which one, to keep encrypted content private. |
| `400` with `encryption_key_required` | A key is wrong, or does not match a registered identifier.                                  |

The editor checks spending and rate limits, editing permissions and conflicts with other edits
when you save. Validation counts redaction limits as if every conditional rule applied at once.

## Read inherited policies

Anyone who can read a key can read every policy that applies to it. Plaintext settings are visible
to them, so [encrypt plugin settings](/docs/customer-encryption#encrypt-plugin-settings) that only
some people should read. Reading a policy does not give permission to change it.

## Document rules

- `null` clears a policy. `{}`, or a document with only `$schema`, saves as `null`.
- Leave out settings that you do not use. No field is required.
- Unknown fields, duplicate keys and invalid expressions are rejected.
- Scope and resource IDs come from where you save the policy, not from fields in it.

| Size                                                         | Limit   |
| ------------------------------------------------------------ | ------- |
| A saved policy, as compact UTF-8 JSON                        | 256 KiB |
| A [request policy](/docs/policies/request-policies), as sent | 16 KiB  |
| All policies that apply to one request, combined             | 512 KiB |

Encrypted settings count by their decrypted size. Settings that several policies share count once.
`policy_work_limit_exceeded` means that the policies of all credentials that a request could use
are too large or complex together. Simplify them, or use fewer distinct credential policies.

## Use an external editor

Add the schema URL to get field completion in any JSON editor:

```json
{
	"$schema": "https://stogas.ai/schemas/key-config-v1.json"
}
```

The schema checks the structure. Saving also checks expressions, permissions and how the policy
combines with others.
