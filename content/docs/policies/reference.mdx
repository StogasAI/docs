title: Policy reference
description: Every policy field, accepted value, default, and size limit.
---

Use this reference while writing JSON. For a first policy, start with [Edit a policy](/docs/policies/editing).
The same document works at organization, grant, and key scope; where you save it determines
which requests and shared usage it governs.

## Document

| Field       | Type                                                           | Required | Meaning when omitted                                                                                                                                      |
| ----------- | -------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`   | Integer; must be `1`                                           | Yes      | The document is invalid. This is the syntax version, not a saved-history number.                                                                          |
| `$schema`   | String; must be `https://stogas.ai/schemas/key-config-v1.json` | No       | No editor schema hint. It does not change enforcement.                                                                                                    |
| `limits`    | [Limits object](#limits)                                       | No       | No added limits at this scope. Parent and platform limits still apply.                                                                                    |
| `routing`   | [Routing object](#routing)                                     | No       | No added catalog filter or ordering. Request-policy permission follows the [scope defaults](/docs/policies/scopes#permission-to-supply-request-policies). |
| `expiresAt` | [Timestamp](#timestamps-and-time-zones)                        | No       | No expiration at this scope. Parent expiration still applies.                                                                                             |
| `access`    | [Access object](#access)                                       | No       | No added deny periods.                                                                                                                                    |
| `plugins`   | [Plugins object](#plugins)                                     | No       | Inherit configured redaction; use defaults if no scope configures it.                                                                                     |

All property names are case-sensitive. Unknown fields and `null` settings are invalid. Omit an
unused field rather than setting it to an empty object. The smallest policy is `{"version":1}`.
Saving replaces the complete policy at that scope; it is not a partial update.

Each saved source is limited to **16 KiB of normalized UTF-8 JSON**. Whitespace is not retained.
The combined saved policies and compiled routing must each fit within 64 KiB. Individual field
bounds still apply even when the document fits the byte limit.

## Limits

| Field                       | Type and bounds                                         | Meaning                                               |
| --------------------------- | ------------------------------------------------------- | ----------------------------------------------------- |
| `limits.spend`              | Nonempty object                                         | Lifetime and recurring Stogas spend caps.             |
| `limits.spend.lifetimeUsd`  | [USD string](#usd-values)                               | Maximum lifetime spend at this scope.                 |
| `limits.spend.recurring`    | Map of 1–8 named [spend limits](#recurring-spend-limit) | Independent allowances with reset schedules.          |
| `limits.requests`           | Map of 1–8 named [request limits](#request-limit)       | Continuous request refill rates and burst capacities. |
| `limits.tokens`             | Map of 1–8 named [token limits](#token-limit)           | Token allowances over fixed periods.                  |
| `limits.concurrentRequests` | Integer, 1–10,000                                       | Maximum active request authorizations at this scope.  |

Each limit is optional. A `limits` object must contain at least one setting, and a `spend` object
must contain `lifetimeUsd`, `recurring`, or both. See [Limits](/docs/policies/limits) for accounting,
resets, edits, and rejection handling.

### Limit names

Choose a name such as `daily`, `monthly`, or `short-burst`. It must match
`^[a-z][a-z0-9_-]{0,47}$`: 1–48 ASCII characters, starting with a lowercase letter.
The name identifies a counter within one scope and one kind of limit. It is not an execution priority.

The same name can be used for different kinds or scopes without sharing a counter. Renaming
creates a new counter; changing an amount under the existing name preserves usage.

### Recurring spend limit

Each entry under `limits.spend.recurring` has these fields:

| Field          | Type and bounds                                     | Required or default                                                                         |
| -------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `maxUsd`       | [USD string](#usd-values)                           | Required.                                                                                   |
| `window`       | Object containing `count` and `unit`                | Required.                                                                                   |
| `window.count` | Integer, 1–1,000                                    | Required.                                                                                   |
| `window.unit`  | `minute`, `hour`, `day`, `week`, `month`, or `year` | Required.                                                                                   |
| `timeZone`     | [Time zone](#timestamps-and-time-zones)             | Required; there is no implicit UTC default.                                                 |
| `anchor`       | [Timestamp](#timestamps-and-time-zones)             | Defaults to the first save time. Later saves retain that named limit's anchor when omitted. |

The window is a repeating schedule, not a rolling lookback. A future anchor still defines
the current period; it does not delay enforcement. See [Reset schedules](/docs/policies/limits#reset-schedules).

### Request limit

Each entry under `limits.requests` has these fields:

| Field    | Type and bounds              | Required or default                           |
| -------- | ---------------------------- | --------------------------------------------- |
| `max`    | Integer, 1–1,000,000,000,000 | Required; the numerator of the refill rate.   |
| `window` | [Duration object](#duration) | Required; the denominator of the refill rate. |
| `burst`  | Integer, 1–120               | Defaults to the smaller of `max` and 120.     |

The resulting rate must be between approximately one request per century and 60 per second.
`max: 120` with a one-minute window refills at two requests per second; it is not a strict
120-request counter for each calendar minute. Every key also has a separate platform bucket
of 60 requests per second and capacity 60.

### Token limit

Each entry under `limits.tokens` has these fields:

| Field    | Type and bounds              | Required or default                          |
| -------- | ---------------------------- | -------------------------------------------- |
| `max`    | Integer, 1–1,000,000,000,000 | Required; total tokens available per period. |
| `window` | [Duration object](#duration) | Required.                                    |

Token periods have no `burst`, `anchor`, or `timeZone`. They align to the Unix epoch in UTC.
See [Token quotas](/docs/policies/limits#token-quotas) for input, cache, reasoning, and settlement rules.

### Duration

Request and token limits use the same duration shape:

| Field   | Type and bounds                              | Required |
| ------- | -------------------------------------------- | -------- |
| `count` | Integer, 1–999,999                           | Yes      |
| `unit`  | `second`, `minute`, `hour`, `day`, or `week` | Yes      |

A day is 86,400 seconds and a week is seven days. Months, years, and daylight-saving adjustments
are not part of these durations.

### USD values

Money is a decimal string from `"0"` through `"1000000000000"`, with up to 18 fractional digits
and 64 characters in total. Use `"10.00"`, not `10`, `"$10"`, `"1,000"`, or `"1e3"`.
Negative values and a trailing decimal point are invalid. A zero cap leaves no room for a positive hold.

## Routing

| Field                                        | Type and bounds                                                          | Meaning when omitted                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `routing.query`                              | [Routing query](/docs/policies/routing#query-syntax), 1–4,096 characters | No added filter or sort.                                                                   |
| `routing.allowedCatalogNodes`                | [Allowed-node object](#allowed-catalog-nodes)                            | No added exact-ID restriction.                                                             |
| `routing.requestPolicy`                      | `deny`, `filter`, or `filter_and_sort`                                   | [Scope-dependent permission](/docs/policies/scopes#permission-to-supply-request-policies). |
| `routing.fallbacks`                          | Object containing `maxPreDispatchCandidates`                             | No added maximum at this scope.                                                            |
| `routing.fallbacks.maxPreDispatchCandidates` | Integer, 1–3                                                             | Required if `fallbacks` is present.                                                        |

A `routing` object needs at least one setting. The smallest explicit candidate maximum wins
across scopes; if none is set, the maximum is one. This controls local candidate preparation,
not provider retries. See [Candidate checks](/docs/policies/routing#candidate-checks).

### Allowed catalog nodes

| Field         | Type                 | Matches               |
| ------------- | -------------------- | --------------------- |
| `authors`     | Array of catalog IDs | The model author.     |
| `models`      | Array of catalog IDs | The model.            |
| `deployments` | Array of catalog IDs | The exact deployment. |
| `routes`      | Array of catalog IDs | The catalog route.    |
| `providers`   | Array of catalog IDs | The provider.         |

At least one list must be present, with at most 64 IDs across all lists. IDs must be unique
within each list and match `^[a-z0-9][a-z0-9._:-]{0,127}$`.

Each present list must match. Omission adds no restriction; an empty array denies all candidates.
Use canonical IDs from the catalog, not display names, aliases, wildcards, or HTTP paths.
IDs are resolved against the active catalog when a request arrives.

## Access

`access` contains one required field, `deny`: an array of 1–16 deny periods. Each entry has:

| Field      | Type and bounds                                                                 | Required |
| ---------- | ------------------------------------------------------------------------------- | -------- |
| `days`     | Array of 1–7 unique values: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`     | Yes      |
| `start`    | Local time in `HH:MM`, from `00:00` through `23:59`                             | Yes      |
| `end`      | Local time in `HH:MM`, from `00:01` through `24:00`; must be later than `start` | Yes      |
| `timeZone` | [Time zone](#timestamps-and-time-zones)                                         | Yes      |

The start is included; the end is excluded. Split overnight ranges into two entries.
Every applicable deny period blocks access. See [Access periods](/docs/policies/access).

### Timestamps and time zones

`expiresAt` and recurring `anchor` values are ISO 8601 timestamps with `Z` or an explicit offset,
for example `2026-12-01T00:00:00Z` or `2026-12-01T09:00:00+09:00`. Local times without an offset
and year zero are invalid. Saved timestamps are normalized to UTC with millisecond precision.

`timeZone` accepts a recognized IANA name such as `UTC`, `America/New_York`, or `Europe/Berlin`.
Names are 1–64 characters using letters, digits, `_`, `+`, `-`, or `/`. The timestamp's offset
identifies an instant; `timeZone` determines the local schedule and its daylight-saving rules.

## Plugins

| Field                                   | Type and bounds                                                                    | Meaning when omitted                                             |
| --------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `plugins.stogasRedaction`               | Nonempty object                                                                    | No redaction selection at this scope.                            |
| `plugins.stogasRedaction.<preset>`      | Optional Boolean; see the [complete detector list](/docs/policies/plugins#presets) | Off within a configured plugin; parent requirements still apply. |
| `plugins.stogasRedaction.customPattern` | One nonempty RE2 string, at most 512 UTF-8 bytes                                   | No custom expression at this scope.                              |

Every enabled preset and every custom expression from the applicable scopes runs. Exact
duplicate expressions run once. Up to three custom expressions scan the original text independently,
with a total limit of 4,096 compiled instructions. If no scope configures the plugin, the built-in defaults apply.
See [Redaction](/docs/policies/plugins) for the complete detector inventory, examples, scan
coverage, and limitations.

## Request document

The inference request's optional `policy` field accepts a smaller document:

| Field     | Required | Accepted content                                                 |
| --------- | -------- | ---------------------------------------------------------------- |
| `version` | Yes      | `1`                                                              |
| `routing` | Yes      | `query`, `allowedCatalogNodes`, or both, using the bounds above. |

Request policies are limited to 16 KiB as sent, including whitespace. They do not accept
`$schema`, `limits`, `expiresAt`, `access`, `plugins`, `fallbacks`, or `requestPolicy`.
Saved policies must grant permission first. See [Request policies](/docs/policies/request-policies).
