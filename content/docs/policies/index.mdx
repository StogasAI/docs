A policy is a JSON document that controls which requests an API key may make, how much it may
use, and what text reaches a provider. Save shared settings on organizations, folders, grants,
roles, members and credentials, then add key or request settings. Every request must satisfy
all applicable requirements.

## Start with a policy

This policy requires a no-training declaration and caps lifetime upstream spending at $10:

```json title="policy.json"
{
	"routing": {
		"filter": "deployment.dataHandling.trainingUse == false"
	},
	"limits": {
		"spend": {
			"lifetimeUsd": "10"
		}
	}
}
```

On an organization, that $10 is shared across all its keys. On a grant, it is shared across the
grant's member keys. On a key, it applies only to that key. A key cannot override a parent cap.

Use `null` when no policy is configured. An empty object `{}` is saved as `null`; omitted settings add no
restriction at that scope. They do not remove parent restrictions or platform safeguards.

[Edit a policy](/docs/policies/editing) explains how to save it.
[Scopes and inheritance](/docs/policies/scopes) explains shared rules, permissions, and when
changes take effect.

## Policies for one request

The optional inference-request `policy` field accepts permitted routing, access, input and
redaction settings, including flat conditional rules. It cannot define shared limits. See
[Request policies](/docs/policies/request-policies) for permissions and examples.

A policy governs an existing credential. It does not create keys, grant membership, or add funds.
See [API keys and grants](/docs/api-keys) for credential management and [BYOK](/docs/byok) for
provider credentials.
