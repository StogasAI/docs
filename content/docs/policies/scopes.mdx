You can save a policy on an organization, folder, grant, role, member, provider credential or API
key. Each is a scope. A request must follow every policy that applies to it, and a
[request policy](/docs/policies/request-policies) can add settings for one request.

## Which policies apply

| Key         | Policies that apply                                                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Service key | The organization, the key's folder, the selected provider credential and the key                                                          |
| Member key  | The organization, the grant's folder, the grant, the key's owner, each of the owner's roles, the selected provider credential and the key |

- Every role of a member applies to all of that member's keys. A role that gives access to grant A
  and allows only OpenAI also restricts the member's keys under grant B. To restrict one grant, save
  the policy on that grant or its folder.
- Only the credential that serves the request applies its policy.
- The members who view or manage a service key add no policies to it.

## Scope differences

| Scope                         | `limits` | Sets `delegation` for resources below |
| ----------------------------- | -------- | ------------------------------------- |
| Organization, folder, grant   | Yes      | Yes                                   |
| Role, member, credential, key | Yes      | No                                    |
| Request                       | No       | No                                    |

- Every scope accepts `access`, `input`, `timeouts`, `routing`, `plugins` and `rules`. Only
  organization, folder, grant, key and request policies can
  [set sort criteria](/docs/policies/routing#orders-from-several-policies).
- Credential policies cannot set [fallbacks](/docs/policies/routing#retries-and-fallbacks) or
  `timeouts.totalSeconds`, because one fallback count and one total wait apply to the whole
  request.
- Every saved scope can [permit request policies](/docs/policies/request-policies#grant-permission).
  See [Delegation](/docs/policies/delegation) for which resources each policy covers.
- A saved policy can be up to 256 KiB, and a request policy up to 16 KiB. See
  [Document rules](/docs/policies/editing#document-rules).
- Managed providers have no credential, so they have no credential policy.

## How settings combine

When several policies set the same kind of setting, they combine. Only the order of sort criteria
depends on the scope that sets them:

| Setting                                                               | Result                                                                      |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| [Routing filters](/docs/policies/routing)                             | Every filter must match.                                                    |
| [Catalog ID lists](/docs/policies/routing#allow-and-deny-lists)       | Only IDs in every `allow` list and in no `deny` list.                       |
| [Sort](/docs/policies/routing#orders-from-several-policies)           | Required criteria from the broadest policy, then defaults from the closest. |
| [Deny periods](/docs/policies/access#deny-periods)                    | Every period applies.                                                       |
| [Networks](/docs/policies/access#networks)                            | Only addresses in every `allow` list and in no `deny` list.                 |
| [Countries](/docs/policies/access#countries)                          | Only countries in every `allow` list and in no `deny` list.                 |
| [Connection modes](/docs/policies/access#connection-modes)            | Only modes in every `allow` list and in no `deny` list.                     |
| [Redaction](/docs/pii-redaction)                                      | Every preset, literal and pattern applies to the original text.             |
| [ASCII-only input](/docs/pii-redaction#ascii-only-input)              | Required if any policy requires it.                                         |
| [Classification](/docs/classification)                                | Every classifier that any policy names runs.                                |
| [Retries and fallbacks](/docs/policies/routing#retries-and-fallbacks) | The smallest value of each. Without one, no retries and two fallbacks.      |
| [Timeouts](/docs/policies/timeouts)                                   | The smallest value of each. Without one, 3,600 seconds each.                |
| [Limits](/docs/policies/limits)                                       | Every limit applies. Limits cannot be defaults.                             |

[Rules](/docs/policies/rules) apply settings only to matching requests, or as defaults that apply
only when no policy requires the same kind of setting.

## Request order

<Steps>
<Step>

### Check the key

The gateway checks the key and loads the policies that apply to it.

</Step>
<Step>

### Choose a deployment

Each candidate is a deployment with one credential. The gateway applies each candidate's rules, filters
and sort, then selects one. See [Routing](/docs/policies/routing).

</Step>
<Step>

### Prepare the input

The gateway checks ASCII-only input and redacts the text once, for the selected candidate.

</Step>
<Step>

### Hold

The gateway [holds](/docs/usage#how-a-request-is-charged) funds and tokens against every limit at once.
If one limit fails, no limit is charged.

</Step>
<Step>

### Send and settle

The gateway sends the request, then charges the usage to the limits that held it.

</Step>
</Steps>

## When changes take effect

- Every request checks the current enabled state, expiration, limits and policy versions. Disabling
  a resource blocks new requests at once, and requests that are running continue.
- Saving does not wait for gateways to load the change. A request that reaches a gateway with an
  older version gets `503 key_configuration_changed` and costs nothing. Send it again after a
  moment.
- A change that lets a refused request through, such as assigning a credential, choosing an Azure
  target, registering an encryption key, removing a deny period or fixing policies that do not
  combine, applies within three minutes. Until then, a request that you send may still get the
  earlier refusal.
- A request keeps the limits that it held, even if a later edit changes them.
