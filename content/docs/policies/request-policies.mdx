---
title: Request policies
description: Add permitted restrictions and default overrides to one inference request.
---

A request policy lasts for one inference request. It uses the saved policy syntax for permitted
routing, scheduled access, input restrictions and redaction. It can replace defaults, but it
cannot remove required restrictions.

Request policies cannot define persistent spend, request-rate, token or concurrency counters,
register encryption roots, or delegate permission. This includes stricter limits and limits
inside conditional rules. Save them on the relevant resource instead. The complete
[scope differences](/docs/policies/scopes#scope-differences) also distinguish permissions,
document size, root registration and rule syntax.

## Grant permission

Request policies require an explicit allowance in at least one applicable saved policy.
All explicit allowances intersect; omission adds no restriction. Use `true` to permit every
request-supported section, `false` to deny them, or a list of section paths:

```json title="Saved policy"
{
	"version": 1,
	"delegation": {
		"request": ["routing.filter", "routing.sort", "plugins.stogasRedaction"]
	}
}
```

That example permits filters, sort preferences and plaintext redaction. It does not permit
allowed-node lists or other unlisted settings. A broader path such as `routing` permits that
whole section. Rules require permission for every setting they contain, whether or not their
condition would match this request. See [Delegation](/docs/policies/scopes#permission-to-edit-saved-policies).

## Add a policy to a request

Send `policy` in the JSON body of Chat Completions or Responses:

```json title="Chat Completions request"
{
	"model": "gpt-5.5",
	"messages": [{ "role": "user", "content": "Contact alice@example.com" }],
	"policy": {
		"version": 1,
		"routing": { "filter": "provider.id == 'openai'" },
		"plugins": { "stogasRedaction": { "email_address": true } }
	}
}
```

```json title="Responses request"
{
	"model": "gpt-5.5",
	"input": "Hello",
	"policy": {
		"version": 1,
		"routing": {
			"sort": [{ "by": "deployment.pricing.output_tokens.per_mill_tokens", "direction": "asc" }]
		}
	}
}
```

A request sort replaces sort defaults and must agree with every required saved ordering.
Required saved filters and redaction still apply. Conditional rules use the same
[pre-selection facts](/docs/policies/routing#request-facts-and-context).

## Request document

The document requires `version: 1` and is limited to **16 KiB as sent**, including whitespace.
The saved [expression and node-list bounds](/docs/policies/routing) also apply. There is no policy
header. `enabled` and expiration remain resource settings; `limits`, `delegation` and `encryption`
are rejected, including inside rules.

For permitted encrypted plugins, supply their registered roots in the request's `encryption_keys`
map. The policy cannot register a new root. Empty settings can replace defaults only; they never
clear required restrictions from another policy.

The gateway consumes `policy` before dispatch and does not send it to the provider. Standard
model and provider selectors remain available when request policies are disabled, subject to
the saved restrictions.

## Rejected policies

| Response | Cause                                                                                | Fix                                                        |
| -------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `403`    | A supplied section lacks permission.                                                 | Remove it or ask a policy manager to change the allowance. |
| `400`    | Invalid syntax, unsupported fields, conflicting required orders, or exceeded bounds. | Correct the document or make its required ordering agree.  |
