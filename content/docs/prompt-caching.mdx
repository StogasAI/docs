Providers cache the start of a prompt that they have seen recently. A later request that begins with
the same content reads it from the cache, which is faster and costs less than ordinary input. The
gateway has no cache of its own: every request reaches the provider, and you pay the provider's cache
prices.

To get cache hits, put content that does not change, such as instructions, tools and reference
documents, at the start of the prompt. Put the parts that change at the end.

## Provider controls

Each provider decides what it caches and how you control it. [Compare providers](/docs/providers)
summarizes the controls, and each provider's page has the details.

The gateway sends each cache field only to the deployments whose provider takes it, and does not
convert one provider's controls into another's. Another deployment runs the request without the
field and caches as it does by default, so a request can carry the controls of every provider that
it may reach.

To keep requests that share a prefix on the same cache, pin them to one provider with a
[deployment ID](/docs/models#choose-a-model) or `provider.only`.

## Cache requests that mark nothing

Some deployments cache only the parts of a prompt that a request marks, and most clients mark
nothing. A new organization's policy starts with this [default rule](/docs/policies/rules#defaults),
which has the gateway mark such a request. You can edit or remove it:

```json title="Organization policy"
{
	"rules": {
		"default_caching": { "mode": "default", "plugins": { "promptCaching": "5m" } }
	}
}
```

The gateway then asks the provider to cache the whole prompt, so that each turn of a conversation
reads the turns before it, and to cache the system prompt and tools on their own, so that a new
conversation that starts with them reads them too.

- `5m` or `1h` is how long each cache entry lasts after its last read. An hour costs more to write,
  and pays off when a conversation pauses for more than five minutes.
- `off` is the same as no setting. Set it in a key policy to replace the default where requests
  do not repeat: a cache write costs more than ordinary input, so a prompt that no later request
  reads costs more when the gateway marks it.
- A request that marks anything itself keeps only its own marks.
- The longest lifetime that a policy requires applies.
- A prompt shorter than the deployment's smallest cache entry (`promptCacheMinimumTokens` in the
  catalog) is not cached and costs nothing extra.

A rule's condition decides for each deployment, so a rule can give some deployments a lifetime of
their own:

```json title="Organization policy"
{
	"rules": {
		"long_cache": {
			"when": "model.id == 'claude-sonnet-5-5'",
			"plugins": { "promptCaching": "1h" }
		}
	}
}
```

The catalog lists the deployments that cache only marked prompts with `explicitPromptCaching` and
without `implicitPromptCaching`. A [request record](/docs/request-records) shows `prompt_caching` in
its settings when the gateway marked the request.

## Read cache usage

The response reports cache reads and writes with the input tokens:

```jsonc title="Chat Completions usage"
{
	"prompt_tokens": 12400,
	"completion_tokens": 310,
	"total_tokens": 12710,
	"prompt_tokens_details": {
		"cached_tokens": 12000, // Read from the cache.
		"cache_write_tokens": 0 // Written to the cache.
	}
}
```

Responses reports the same fields in `usage.input_tokens_details`. Where the provider reports how
long each write lasts, `cached_write_token_details` splits `cache_write_tokens` into
`cached_write_tokens_5m`, `cached_write_tokens_1h`, `cached_write_tokens_30m` and
`cached_write_tokens_12h`.

## Billing

Each input token is billed once, as ordinary input, a cache read or a cache write, at the rates in
the catalog. Cache reads cost less than input. Cache writes can cost more.

The [hold](/docs/usage#how-a-request-is-charged) before a request assumes the most expensive input rate,
because the gateway cannot know in advance how much of the prompt the provider will find in its cache.
Settlement charges the actual reads and writes and releases the rest. Each
[request record](/docs/request-records) shows the cache savings and the extra cost of writes.

If a provider reports usage that is missing, negative or inconsistent, the request fails with
`upstream_protocol_error` instead of a guessed charge.
