A service tier sets how quickly the provider processes a request and what it costs. The gateway uses
the same tier names for every provider and converts them to each provider's own controls.

| Tier      | Processing                                   | Price   | Deployment ID suffix |
| --------- | -------------------------------------------- | ------- | -------------------- |
| Standard  | Normal speed                                 | Base    | None                 |
| Flex      | Slower, and can fail when capacity is short  | Lower   | `-flex`              |
| Fast      | Faster output                                | Higher  | `-fast`              |
| Ultrafast | The fastest output, with its own rate limits | Highest | `-ultrafast`         |

Each tier of a model is a separate deployment with its own price. Search the
[catalog](/docs/models#find-a-model) for a model to see its tiers.

The catalog also lists batch APIs as deployments of the `batch` tier, with IDs that contain
`-batch`: OpenAI's Batch API, Anthropic's Message Batches API and batch inference on Amazon
Bedrock. A batch API runs a file of requests as one job, later and at about half the Standard
price. Stogas does not serve batch deployments, because the gateway answers each request as
it arrives, so a request that names one returns `model_unavailable`.

## Select a tier

Send `service_tier` with a model ID:

```json
{
	"model": "gpt-5.5",
	"input": "Summarize this report.",
	"service_tier": "flex"
}
```

Or send the deployment ID of the tier, such as `openai-gpt-5.5-2026-04-23-flex`.

| `service_tier`          | Selects                                                             |
| ----------------------- | ------------------------------------------------------------------- |
| Omitted, `null`, `auto` | The tier of the `model` that you name. A model ID selects Standard. |
| `default`, `standard`   | Standard                                                            |
| `flex`                  | Flex                                                                |
| `fast`, `priority`      | Fast                                                                |
| `ultrafast`             | Ultrafast                                                           |

- Other values return `unsupported_service_tier`. Values are case sensitive.
- If your key can use the model only at other tiers, the request returns
  `service_tier_unavailable`. If it can use the model at no tier, for example because no credential
  serves it, the request returns `model_unavailable`. The gateway never moves a request to another
  tier.
- A deployment ID fixes the tier, so a `service_tier` for another tier returns
  `service_tier_unavailable`.

`service_tier` works the same on every provider, and a provider's own control, such as Anthropic's
`speed`, returns `400`. [Compare providers](/docs/providers) shows which tiers each provider runs.

## When the provider cannot run the tier

- **Flex**: the request can take longer than at Standard. When the provider has no Flex capacity,
  the request fails with `429`.
- **Fast**: some providers run a Fast request at Standard, for example when your Fast traffic grows
  too quickly, and you then pay the Standard price[^fast].
- **Ultrafast**: the request fails with `429` when you reach your Ultrafast rate limit.

## Check which tier ran

The response's `service_tier` is the tier that the provider reports[^reported].
In the [request record](/docs/request-records#catalog-history), `catalog_chain_hash` identifies the
deployment that you paid for. When the provider ran another tier, `resolved_catalog_chain_hash`
identifies the deployment that your request resolved to.

## Block a tier

A [routing policy](/docs/policies/routing) can remove tiers with `deployment.upstream.serviceTier`,
which is `standard`, `flex`, `fast` or `ultrafast`. For example, to block Ultrafast:

```json title="Policy"
{ "routing": { "filter": "deployment.upstream.serviceTier != 'ultrafast'" } }
```

A policy cannot move a request to another tier. The request's `model` and `service_tier` choose it.

[^fast]: OpenAI, and GPT on Azure. Claude returns an error instead.

[^reported]:
    OpenAI and GPT on Azure report `default`, `flex`, `fast`, `priority` or `ultrafast`, where
    `priority` is the older name for Fast, and a Fast request that ran at Standard reports
    `default`. Claude reports Fast as `"speed": "fast"`, with `service_tier` `default`.
