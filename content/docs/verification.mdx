## What a successful check establishes

<Steps>
	<Step>

### Approved code

GitHub build provenance and an independent Stogas counterbuild authorize the same reproducible gateway image.

    </Step>
    <Step>

### Genuine confidential hardware

An AMD certificate chain and signed SEV-SNP report prove that an approved image booted with the required security policy.

    </Step>
    <Step>

### Fresh guest keys

The report binds each gateway's TLS, response-signing, and E2EE keys. A verified drand round proves the evidence was produced recently.

    </Step>

</Steps>

This all happens before the normal request path. Inference does not synchronously call Stogas Control, GitHub, AMD, Sigstore, or drand.

## Connection-time and after-the-fact checks

Connection-time verification authorizes a live gateway through attested TLS, E2EE, or both. The compact response receipt then binds the exact request and response bodies to that gateway's attested signing key.

Current receipts can be checked against the active snapshot. Historical receipts use the permanent node-admission record in the Trust Center, so a gateway can be verified after it has left the fleet.
