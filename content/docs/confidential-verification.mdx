## What gets checked

One successful verification establishes a single trust set:

- the gateway release matches GitHub build provenance and Stogas authorization;
- the node runs that approved release on AMD SEV-SNP;
- the node's certificate and transport keys belong to the attested guest;
- the evidence and bundle satisfy the selected freshness policy.

The cryptographic core is Rust. Native packages call it directly; JavaScript uses the same core compiled to WebAssembly.

## CLI or SDK?

Use the [CLI](/docs/cli) when you want verification without changing application code. It maintains the bundle, pins the upstream TLS connection, and presents a local OpenAI-compatible URL.

Use an [SDK](/docs/sdk) when your application needs the verified releases, nodes, and keys directly. SDK verification is networkless; your application controls retrieval and transport.
