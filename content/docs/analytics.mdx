Analytics shows each request's usage, cost, timing and outcome. It never stores prompts, responses
or credentials. **Analytics → Read own** shows the requests of your own member keys, **View** on a
folder, grant or API key shows its requests, and **Analytics → Read all** or **API keys → Read
all** shows every request in the organization.

## Metrics

| Metric                       | Counts                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cache hit rate               | Requests with input usage that read any input from the provider's [cache](/docs/prompt-caching)                                                        |
| Cached input share           | Input tokens read from the cache                                                                                                                       |
| Reasoning tokens             | Only requests whose provider reports them, so a period without one shows no value instead of 0                                                         |
| Tool call error rate         | Requests with at least one tool call whose arguments do not match the tool's `parameters` schema                                                       |
| Structured output error rate | Requests with a JSON `response_format` or `text.format` whose output is not valid JSON or breaks the schema                                            |
| Refusal rate                 | Requests a provider answered whose [provider result](/docs/request-records#provider-results) is `content_filter`                                       |
| Truncation rate              | Requests a provider answered whose output stopped at the output token limit or a full context window                                                   |
| Recovered requests           | Successful requests that needed more than one provider attempt                                                                                         |
| Retries                      | Provider attempts that called the same candidate again, a [retry](/docs/policies/routing#retries-and-fallbacks)                                        |
| Fallbacks                    | Provider attempts that called the next candidate, a [fallback](/docs/policies/routing#retries-and-fallbacks)                                           |
| Gateway duration             | The [request clock](/docs/request-records#timing) outside provider calls and the wait for the [platform request limit](/docs/policies/limits#requests) |

- A tool without a schema that compiles accepts any arguments. A call to a tool that the request
  does not allow, or arguments that are not a JSON object, fail the request instead.
- Output is checked only when the model finishes normally, without a tool call or a refusal. A
  `format` keyword is an annotation, as in JSON Schema 2020-12, and a schema can refer only to
  itself. A check that would be too large is skipped and counts as neither valid nor invalid.
- A request is refused when the provider rejects it for its content, when the output stops for a
  content filter, or when the response carries a `refusal`. A refusal that the model writes as
  ordinary text is not counted. Filter by `status:content_filter` to list refused requests.

Percentiles are approximate, and every percentile from P0.1 to P99.9 in steps of 0.1 is available.
Averages and percentiles use only requests with a known value, and timing statistics use only
successful requests that were not cancelled. Time to first token (TTFT) also needs streamed
output. Generation speed divides generated tokens by the full request duration.

## Groups

- The chart draws the first seven groups in the breakdown's order and adds the rest together as
  Other. To chart other groups, sort the breakdown by another metric or filter for them, such as
  `key:checkout OR key:search`.
- Hiding a group in the legend only takes it off the chart. Totals and shares still count it.
- Model groups combine revisions of the same model.
- Session and trace groups also show when each one started and how long it ran, from the start of
  its first request in the period to the end of its last.
- A request counts in each role of its key's member and under each of its
  [metadata](/docs/request-records#metadata) keys. Role and metadata key groups can therefore add
  up to more than the total. Each key's values have a breakdown of their own.
- These counts are analytics, not the counters that enforce [limits](/docs/policies/limits).

## Requests

- Each provider call is one attempt, including
  [retries and fallbacks](/docs/policies/routing#retries-and-fallbacks), and keeps its own result.
  A provider can succeed and the request can still fail later in the gateway.
- A request keeps the catalog settings that applied when it ran, even after the catalog changes.
- A row can stand for several identical rejections in the same minute. See
  [grouped rejections](/docs/request-records#grouped-rejections).

### Filters

The search and the API's `filter` parameter take these fields in the
[filter syntax](/docs/reference/filters). Text without a field searches request, API key, grant
and provider credential IDs, model names, providers, results, interfaces, error codes and HTTP
statuses. Filters match whole values, so `:` and `=`
are the same, and names and the listed values ignore case. A name matches every API key, member or
provider credential that has it, so use an ID to match one.

| Filter              | Matches                                                                                                                                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `key:`              | An API key ID or name.                                                                                                                                                                                                 |
| `grant:`, `member:` | Member keys under a grant, or keys owned by a member.                                                                                                                                                                  |
| `role:`             | Member keys whose member held a role, by name or ID, when the request ran.                                                                                                                                             |
| `model:`            | A model ID. Suggestions include current catalog names.                                                                                                                                                                 |
| `provider:`         | Any provider attempt.                                                                                                                                                                                                  |
| `final_provider:`   | The last provider attempt.                                                                                                                                                                                             |
| `byok:`             | A provider credential name or ID used by any attempt, or `stogas` for a Stogas-managed credential.                                                                                                                     |
| `final_byok:`       | The provider credential of the last attempt.                                                                                                                                                                           |
| `interface:`        | `chat_completions` or `responses`, the API that the request called.                                                                                                                                                    |
| `stream:`           | `true` for requests that asked for a stream, otherwise `false`.                                                                                                                                                        |
| `transport:`        | `https`, `attested_tls` or `e2ee`. See [connection modes](/docs/connection-modes).                                                                                                                                     |
| `truncated:`        | `true` for requests that the truncation rate counts, otherwise `false`.                                                                                                                                                |
| `metadata.<key>:`   | A value of a [metadata](/docs/request-records#metadata) key, such as `metadata.team:search`. Keys and values are case-sensitive. Keys with spaces, quotes, parentheses or `:`, `!`, `<`, `>` or `=` can't be filtered. |
| `session:`          | A [session](/docs/request-records#sessions) ID, such as `session:chat-42`. Session IDs are case-sensitive.                                                                                                             |
| `app:`              | The name of the request's [app](/docs/request-records#apps), or its URL when it sent no name, such as `app:"Roo Code"`. App names are case-sensitive.                                                                  |
| `agent:`            | The name of the [agent](/docs/request-records#agents) that sent the request, such as `agent:review`. Agent names are case-sensitive.                                                                                   |
| `subagent:`         | `true` for requests of [agents](/docs/request-records#agents) that a session started, otherwise `false`.                                                                                                               |
| `trace:`            | A [trace](/docs/request-records#traces) ID, such as `trace:4bf92f3577b34da6a3ce929d0e0e4736`.                                                                                                                          |
| `encryption_key:`   | The identifier of a [customer encryption key](/docs/request-records#encryption-keys) in the request's record, or the label it is registered under.                                                                     |
| `tool_call:`        | A tool call ID or its [hash](/docs/request-records#tool-calls), such as `tool_call:call_1`. Matches the request that made the call and the one that sent its result. IDs are case-sensitive.                           |
| `outcome:`          | An [outcome](/docs/request-records#outcomes): `success`, `failed`, `cancelled`, `rejected` or `unknown`.                                                                                                               |
| `status:`           | `success`, a [provider result](/docs/request-records#provider-results), a provider's error code such as `invalid_prompt`, a gateway error code such as `insufficient_balance`, or an HTTP status such as `402`.        |
| `error:`            | A gateway [error code](/docs/reference/errors).                                                                                                                                                                        |
| `id:`               | A request ID.                                                                                                                                                                                                          |
| `redaction:`        | `redacted`, `no_matches` or `not_recorded`. See [PII redaction](/docs/pii-redaction).                                                                                                                                  |

`status:success` matches completed requests with no cancellation or gateway error. Other `status:`
values check every provider attempt, including earlier failed ones.

`none` selects requests without a value in `grant:`, `role:`, `model:`, `final_provider:`,
`final_byok:`, `error:`, `metadata.<key>:`, `session:`, `app:`, `agent:`, `trace:` and
`encryption_key:`. For
example, `error:none` selects requests without a gateway error, and `session:"none"` selects the
session named none.

Compare numbers with `>`, `>=`, `<` or `<=`:

| Filter                                                   | Unit                                              | Example                |
| -------------------------------------------------------- | ------------------------------------------------- | ---------------------- |
| `latency`, `provider_latency`, `gateway_latency`, `ttft` | Milliseconds, or `ms`, `s` and `m`                | `latency>2s`           |
| `input_tokens`, `output_tokens`                          | Tokens, or `k` and `m` for thousands and millions | `input_tokens>=10k`    |
| `tokens_per_second`                                      | Generated tokens per second                       | `tokens_per_second<20` |
| `client_tool_calls`, `hosted_tool_calls`                 | [Tool calls](/docs/request-records#tool-calls)    | `client_tool_calls>0`  |
| `upstream_cost`, `billed_cost`                           | USD, with or without `$`                          | `billed_cost>$0.05`    |

Each member can run 30 queries a minute and download 3 files a minute. An organization's queries
share 30 seconds of query time a minute, and over that they return `429 ANALYTICS_QUOTA_EXCEEDED`
with `Retry-After`. Each query also has time and memory limits. If a query cannot finish, narrow the
time range or filters.

## Download records

Download the filtered requests as NDJSON, CSV or Parquet. NDJSON uses the same record as the raw
request view, and CSV and Parquet keep nested objects and lists as JSON strings. The
[request record reference](/docs/request-records) describes every field.

To send each record to your own service as requests finish, use the [Export plugin](/docs/export).
