Analytics shows each request's usage, cost, timing and outcome. It never stores prompts, responses
or credentials. View access to a folder, grant or API key also shows its requests.

## Metrics

| Metric                       | Counts                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Cache hit rate               | Requests with input usage that read any input from the provider's [cache](/docs/prompt-caching)             |
| Cached input share           | Input tokens read from the cache                                                                            |
| Reasoning tokens             | Only requests whose provider reports them, so a period without one shows no value instead of 0              |
| Tool call error rate         | Requests with at least one tool call whose arguments do not match the tool's `parameters` schema            |
| Structured output error rate | Requests with a JSON `response_format` or `text.format` whose output is not valid JSON or breaks the schema |

- A tool without a schema that compiles accepts any arguments. A call to a tool that the request
  does not allow, or arguments that are not a JSON object, fail the request instead.
- Output is checked only when the model finishes normally, without a tool call or a refusal. A
  `format` keyword is an annotation, as in JSON Schema 2020-12, and a schema can refer only to
  itself. A check that would be too large is skipped and counts as neither valid nor invalid.

Percentiles are approximate. They use only requests with a known value, and timing statistics use
only successful requests that were not cancelled. Time to first token (TTFT) also needs streamed
output. Generation speed divides generated tokens by the full request duration.

## Groups

- Model groups combine revisions of the same model.
- These counts are analytics, not the counters that enforce [limits](/docs/policies/limits).

## Requests

- Each provider call is one attempt, including
  [retries and fallbacks](/docs/policies/routing#retries-and-fallbacks), and keeps its own result.
  A provider can succeed and the request can still fail later in the gateway.
- A request keeps the catalog settings that applied when it ran, even after the catalog changes.
- A row can stand for several identical rejections in the same minute. See
  [grouped rejections](/docs/request-records#grouped-rejections).

### Filters

The dashboard suggests these filters, and the API's `filter` parameter takes the same syntax. Text
without a field searches IDs, names, providers, results, request types, error codes and HTTP
statuses. A space between filters means `AND`, and you can also use `OR`, `NOT` and parentheses.
Quote values that contain spaces, and the words `and`, `or` and `not` when you search for them.

| Filter              | Matches                                                                                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `key:`              | An API key ID or name.                                                                                                                                                                            |
| `grant:`, `member:` | Member keys under a grant, or keys owned by a member.                                                                                                                                             |
| `role:`             | Member keys whose member held a role, by name or ID, when the request ran.                                                                                                                        |
| `model:`            | A model ID. Suggestions include current catalog names.                                                                                                                                            |
| `provider:`         | Any provider attempt.                                                                                                                                                                             |
| `final_provider:`   | The last provider attempt.                                                                                                                                                                        |
| `byok:`             | A provider credential name or ID used by any attempt, or `stogas` for a Stogas-managed credential.                                                                                                |
| `final_byok:`       | The provider credential of the last attempt.                                                                                                                                                      |
| `type:`             | `chat_completion_request`, `chat_completion_stream`, `responses_request` or `responses_stream`.                                                                                                   |
| `transport:`        | `https`, `attested_tls` or `e2ee`. See [connection modes](/docs/connection-modes).                                                                                                                |
| `metadata.<key>:`   | A value of a [metadata](/docs/request-records#metadata) key, such as `metadata.team:search`. Keys and values are case-sensitive. Keys with spaces or `:`, `!`, `<`, `>` or `=` can't be filtered. |
| `session:`          | A [session](/docs/request-records#sessions) ID, such as `session:chat-42`. Session IDs are case-sensitive.                                                                                        |
| `tool_call:`        | A tool call ID or its [hash](/docs/request-records#tool-calls), such as `tool_call:call_1`. Matches the request that made the call and the one that sent its result. IDs are case-sensitive.      |
| `outcome:`          | `success`, `failed`, `cancelled`, `rejected` or `unknown`.                                                                                                                                        |
| `status:`           | `success`, a [provider result](/docs/request-records#provider-results), a gateway error code such as `insufficient_balance`, or an HTTP status such as `402`.                                     |
| `error:`            | A gateway [error code](/docs/reference/errors).                                                                                                                                                   |
| `redaction:`        | `redacted`, `no_matches` or `not_recorded`. See [PII redaction](/docs/pii-redaction).                                                                                                             |

`status:success` matches completed requests with no cancellation or gateway error. Other `status:`
values check every provider attempt, including earlier failed ones.

`none` selects requests without a value in `grant:`, `role:`, `model:`, `final_provider:`,
`final_byok:`, `error:`, `metadata.<key>:` and `session:`. For example, `error:none` selects
requests without a gateway error.

Compare numbers with `>`, `>=`, `<` or `<=`:

| Filter                                | Unit                                              | Example                |
| ------------------------------------- | ------------------------------------------------- | ---------------------- |
| `latency`, `provider_latency`, `ttft` | Milliseconds, or `ms`, `s` and `m`                | `latency>2s`           |
| `input_tokens`, `output_tokens`       | Tokens, or `k` and `m` for thousands and millions | `input_tokens>=10k`    |
| `tokens_per_second`                   | Generated tokens per second                       | `tokens_per_second<20` |
| `upstream_cost`, `billed_cost`        | USD, with or without `$`                          | `billed_cost>$0.05`    |

Each member can run 30 queries a minute, and an organization 60. Each member can download 3 files a
minute. Queries also have time and memory limits. If a query cannot finish, narrow the time range or
filters.

## Download records

Download the filtered requests as NDJSON, CSV or Parquet. NDJSON uses the same record as the raw
request view; CSV and Parquet keep nested objects as JSON strings. The
[request record reference](/docs/request-records) describes every field.

To send each record to your own service as requests finish, use the [Export plugin](/docs/export).
