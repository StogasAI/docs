The Stogas SDK works with the OpenAI client you already use. Before sending a request, it checks the
available gateways and opens a protected connection. It keeps that check current and stops sending
requests if the evidence expires.

## How it works

<Steps>
	<Step>

### Check the gateway

The SDK checks the gateway's software, confidential hardware, freshness, and connection keys on
your device.

    </Step>
    <Step>

### Connect

It opens a protected connection to a gateway that passed those checks.

    </Step>
    <Step>

### Request

Your existing OpenAI client sends normal Responses or Chat Completions requests through that
channel.

    </Step>

</Steps>

## Connection protection

| Mode     | Available in    | Protection                                                            | Default           |
| -------- | --------------- | --------------------------------------------------------------------- | ----------------- |
| **TLS**  | Native runtimes | WebPKI plus a live certificate and public key from the verified fleet | Native SDKs       |
| **E2EE** | All runtimes    | Application encryption directly to the currently verified gateway set | Browser and Fetch |
| **Both** | Native runtimes | E2EE inside the verified TLS connection                               | Optional          |

Browser networking APIs do not reveal the peer certificate, so browser and Fetch-only clients use
E2EE. Native clients can select `tls`, `e2ee`, or `both`.

## Configuration

| Control                 | Default            | Notes                                                            |
| ----------------------- | ------------------ | ---------------------------------------------------------------- |
| Security mode           | Runtime-specific   | Selects one of the modes above                                   |
| Bundle refresh interval | 300 seconds        | Any whole number from 1 through 840                              |
| Manual refresh          | On demand          | Fetches immediately; unchanged bundle bytes reuse verified state |
| API and evidence URLs   | Stogas public URLs | Override only for another deployment using the same Stogas trust |
| Close                   | Explicit or scoped | Stops refresh work and releases the transport                    |

The SDK also fetches shortly before an accepted bundle expires, regardless of the configured
interval. A failed refresh can use the current bundle only until its authenticated expiry.

## OpenAI client integration

Native SDKs run the shared Rust connection engine inside your process. They give the official
OpenAI client a private local base URL, keeping request types, streaming, and error handling in the
official client while Rust owns verification, TLS pinning, E2EE, and bundle refresh.

Browser, Worker, Node, Bun, and Deno integrations instead provide a managed `fetch` function. The
same Rust core runs as WebAssembly and handles E2EE framing before the request reaches the network.

## Verify evidence directly

Each package also includes a networkless `Verifier` for applications that need the verified
gateway set or want to validate response receipts themselves:

- `Transport` manages protected OpenAI-compatible requests.
- `Verifier` checks caller-supplied snapshots, response receipts, and historical gateway records.
