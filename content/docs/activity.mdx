Activity records who changed your organization's settings and when, with each changed field's
values before and after. Changes through the dashboard and the API appear in the same history, and
a change made with an [access token](/docs/reference/dashboard#access-tokens) names the token.
Each event keeps the names it had, so renaming or deleting a resource does not erase its context.

## Refused attempts

Activity also records an attempt that the member's roles, a parent policy or a read-only access
token refused. The event names the resources that the request named, even IDs that do not exist in
the organization. Attempts that fail for other reasons, such as invalid input or a missing resource,
are not recorded. Neither are attempts by people outside the organization, or with an access token
that does not cover it.

## Filters

The search and the API's `filter` parameter take these fields in the
[filter syntax](/docs/reference/filters). Text without a field matches member, access token and
resource names and IDs, and event names.

| Filter      | Matches                                                                                                                |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- |
| `action:`   | Events whose name contains the value, such as `action:key`. `action=key.deleted` matches one event.                    |
| `actor:`    | The member who made the change, by part of their name or by their ID. `actor=` matches the whole name.                 |
| `token:`    | The access token used, by part of its name or by its ID. `token=` matches the whole name.                              |
| `resource:` | A changed resource, by part of its name or by its ID. `resource=` matches the whole name.                              |
| `outcome:`  | `outcome:refused` matches refused attempts, and `outcome:succeeded` matches changes that happened.                     |
| `time`      | A [date or time](/docs/reference/filters#dates-and-times), such as `time>=2026-10-01`. `time:2026-10` matches October. |

`!=` excludes a value, such as `action!=key.updated`. Names match in any case. For example,
`action:key actor="Alex Smith" time>=2026-10-01` shows Alex Smith's API key changes since October 1.

## Access

Activity includes historical setting values. Give **Activity → Read** only to people who should
see those settings, even after they change.

## Recorded changes

Activity covers organization and member names, membership, invitations, roles, folders, grants,
API keys, credentials, single sign-on, billing details, and saved policies. A policy edit shows the
changed fields, their values before and after, and the policy version. Literal dictionaries and
custom redaction expressions show only rule counts and whether the rules changed. An edit whose
values pass 16 KiB is recorded without them, and its policy versions show the edit while we keep
them. An inherited change is recorded once, at the scope where it was made, not for every affected
key.

Activity records when a member creates, rotates or deletes an access token, and where GitHub found
one in public. Each event appears in every organization that the token can act in, and names none of
the others.

Credential tokens, API-key secrets, invitation codes, and inference content are excluded.
A secret rotation records the action without the secret. Export events record that an
export was requested, not whether the file was saved.

## Retention and export

Events are kept for 365 days.

CSV exports keep lists, names and changes as JSON text, and put an apostrophe before text that a
spreadsheet would run as a formula, such as `=SUM(A1)`. For a change that happened, `refusal` is
`null`, or empty in CSV. For a refused attempt it is `permission`, `policy` or `read_only_token`.

We keep the current version of every policy, and your organization's 10,000 newest earlier versions
within 16 MiB of policy text. A save past either limit removes the oldest earlier versions. An event
or request that names one of them then says the version is no longer kept.

Activity is operational history. Delivery can be delayed or interrupted, so it is not a
guaranteed complete compliance record or a backup of every policy version.
