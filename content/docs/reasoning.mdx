The gateway accepts one effort scale on every provider and converts it to the control of the
selected deployment:

`none` · `minimal` · `low` · `medium` · `high` · `xhigh` · `max`

## Set an effort

```json tab="Chat Completions"
{
	"model": "gpt-5.6-sol",
	"messages": [{ "role": "user", "content": "Find the bug in this function." }],
	"reasoning_effort": "high"
}
```

```json tab="Responses"
{
	"model": "gpt-5.6-sol",
	"input": "Find the bug in this function.",
	"reasoning": { "effort": "high" }
}
```

If you omit the effort, the gateway sends no reasoning control and the provider uses its default. This
is different from `none`, which turns optional reasoning off.

Chat Completions also accepts `"reasoning": { "enabled": true }`. `true` selects the level nearest
to `medium`, and `false` means `none`. An `enabled` value that conflicts with the effort is rejected.

## How the gateway converts an effort

| The deployment                       | The gateway                                              |
| ------------------------------------ | -------------------------------------------------------- |
| Lists the effort                     | Sends it unchanged.                                      |
| Lists other levels                   | Sends the nearest level. A tie goes to the higher level. |
| Has reasoning on or off only         | Turns reasoning on for any effort, and off for `none`.   |
| Requires reasoning                   | Rejects `none`.                                          |
| Requires reasoning but has no levels | Rejects any effort.                                      |
| Accepts only a token budget          | Converts the effort to a budget, as described below.     |

For example, `minimal` on a deployment with `low`, `medium` and `high` becomes `low`.

## Check a deployment

Each deployment in the [catalog](/docs/models#find-a-model) has three reasoning fields:

| Field                | Value                                                                                    |
| -------------------- | ---------------------------------------------------------------------------------------- |
| `reasoning`          | `unsupported`, `optional` or `required`.                                                 |
| `reasoningEfforts`   | The levels you can select. Empty when reasoning is only on or off, or not available.     |
| `reasoningMaxTokens` | `{ "minimum", "maximum" }` when the deployment accepts a token budget, otherwise `null`. |

Levels can differ between Chat Completions and Responses on the same deployment.

## Set a token budget

Some deployments accept a maximum number of reasoning tokens:

```jsonc
{
	"model": "claude-sonnet-4-6",
	"messages": [{ "role": "user", "content": "Plan the migration." }],
	"max_completion_tokens": 16000,
	"reasoning": { "max_tokens": 8000 } // Must be below the output limit.
}
```

The budget must be within the deployment's `reasoningMaxTokens` and below the request's output
limit. The model can use fewer tokens. Send a budget or an effort, not both.

When a deployment accepts only a budget, the gateway converts the effort to a position between the
deployment's `minimum` and the output limit:

| Effort    | Position |
| --------- | -------- |
| `minimal` | 2.5%     |
| `low`     | 15%      |
| `medium`  | 42.5%    |
| `high`    | 80%      |
| `xhigh`   | 92%      |
| `max`     | 100%     |

The budget is `minimum + floor(position × (output limit − minimum))`. `none` becomes `0`. If the
provider requires the budget to be below the output limit, `max` uses one token less.

## Show or hide the reasoning summary

Some models can return a summary of their reasoning:

- On Responses, set `reasoning.summary`. Anthropic models accept `auto` or `none`; OpenAI models
  accept OpenAI's values.
- On Chat Completions, Anthropic models accept `reasoning_display: "summarized"` or `"omitted"`.

Omit the field to keep the provider's default. The summary changes what you see, not what you pay.

## Billing

Reasoning tokens are a separate [usage meter](/docs/usage), billed at the deployment's output rate
unless the catalog lists a reasoning rate. The hold before the request covers the full output limit,
including reasoning.
