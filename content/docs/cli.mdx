The `stogas` CLI runs a local endpoint that verifies the gateway and protects each request. Point
any OpenAI-compatible client at it; only the base URL changes. Use it from languages without an
[SDK](/docs/sdk-overview), or from tools you cannot change. It also creates and uses keys for
[customer encryption](/docs/customer-encryption), and it can create an account, add credit and call
the dashboard API.

Only `signup`, `login`, `logout`, `topup` and `api` use your account. `serve` passes on the API key
that your client sends, and the other commands need no key.

## Install

<Steps>
<Step>

### Download the archive

Each [release](https://github.com/StogasAI/stogas/releases) has an archive for each platform,
named `stogas-v<version>-<platform>.tar.gz`, or `.zip` for Windows. The platforms are
`linux-amd64`, `linux-arm64`, `darwin-amd64`, `darwin-arm64`, `windows-amd64` and `windows-arm64`.
On Alpine and other musl systems, use `linux-musl-amd64` or `linux-musl-arm64`.

```console
gh release download v<version> --repo StogasAI/stogas --pattern 'stogas-v<version>-linux-amd64.tar.gz'
```

</Step>
<Step>

### Verify it

Check that the release workflow built the archive from its tag:

```console
gh attestation verify stogas-v<version>-linux-amd64.tar.gz --repo StogasAI/stogas \
  --signer-workflow StogasAI/stogas/.github/workflows/release.yml \
  --source-ref refs/tags/v<version> --deny-self-hosted-runners
```

</Step>
<Step>

### Put it on your PATH

```console
tar -xzf stogas-v<version>-linux-amd64.tar.gz
sudo install stogas-v<version>-linux-amd64/stogas /usr/local/bin/
stogas --version
```

</Step>
</Steps>

With a Rust toolchain, you can instead build it from source with
`cargo install stogas-cli --locked`.

## Start

```console
stogas serve
```

The command prints a private URL such as:

```text
OpenAI base URL: http://127.0.0.1:8787/<random-capability>/v1
```

Use the complete URL as your client's base URL, and turn off the client's automatic retries. The
endpoint accepts only local connections that include the random part of the URL. It installs no
certificate authority. It accepts Chat Completions, Responses and the policy check endpoint; other
routes fail.

## Options

```console
stogas serve --security tls --max-connections 4
stogas serve --security e2ee
```

| Option                  | Effect                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| `--security`            | `tls` (default) or `e2ee`. See [connection modes](/docs/connection-modes).                    |
| `--max-connections`     | The most connections to open, as needed. Default `4`.                                         |
| `--browser-origin`      | Let only this [web origin](#browser-applications) call the endpoint.                          |
| `--upstream`            | Another HTTPS origin, without a path, credentials or query. Trusted evidence does not change. |
| `--exit-on-stdin-close` | Stop when the parent process closes stdin. Use it when another program starts the CLI.        |

The CLI loads evidence when a session starts, and once more if a session needs newer evidence. It
does not poll. A local application can force a refresh with a `POST` to the separately printed
refresh URL. Published packages trust production gateways only.

## Stop

Press Ctrl+C or, on Unix, send SIGTERM. The CLI stops new work and allows up to five seconds for
active streams and sessions to close. A request that was cancelled did not complete, but it may
have run; do not send it again automatically.

## Check gateway availability

```console
stogas probe --security tls
stogas probe --security e2ee --timeout-ms 8000
```

Each call verifies current evidence and a fresh session, then sends a fixed invalid credential
to the inference route. Success requires the expected authentication rejection after the gateway's
readiness and memory admission checks. No API key or provider request is involved.

The command prints a `stogas.probe.v1` JSON report with `security`, `ready`, the verified `node_id`
when available, `http_status`, and a fixed `error_code`. It exits zero only when `ready` is true.
The timeout covers evidence, connection setup and the response. `--upstream` works as for `serve`.

This checks connection and admission availability from the caller's location. It does not measure
provider health, database-backed authorization, or the success rate of all customer requests.

## Browser applications

Give the web page the complete printed URL. Any page that has it can call the endpoint, and a page
without it cannot read any response. The endpoint holds no API key, so the page sends its own. To
let only your application's origin call it, start the CLI with that origin:

```console
stogas serve --browser-origin https://app.example.com
```

The CLI answers CORS and local-network preflight requests itself and keeps its `--security` mode.
The browser can ask the user for local-network permission.

```js
import OpenAI from 'openai';

const client = new OpenAI({
	apiKey: userApiKey,
	baseURL: pastedCliBaseUrl,
	dangerouslyAllowBrowser: true,
	maxRetries: 0
});
```

Local applications can use an HTTP loopback origin; public origins need HTTPS. Never put a shared
API key in browser code that you ship.

## Verify an evidence file

```console
stogas verify evidence.json --json
```

Use `-` for standard input. The command makes no network requests. It checks the root-signed key
manifest, the signed evidence document with its release evidence, hardware policies and AMD
collateral, and both Rekor proofs. It reports the approved software, not a list of live gateways;
only a fresh session proves which gateway you reach. See [Gateway verification](/docs/verification).

## Sign in

```console
stogas signup
stogas login
```

`signup` creates an account and prints its password once. Save the password; it cannot be
recovered. `login` asks for the password and, when the account uses an authenticator app, a code.
An account whose only second step is a passkey must create its token on the **Account** page.

Each sign-in creates an access token named `Stogas CLI on <host>` that can read and change all of
your organizations and does not expire. The CLI keeps it in the system keychain: Keychain on
macOS, Credential Manager on Windows, or a Secret Service such as GNOME Keyring or KWallet on
Linux. Without a keychain, as on most servers, the CLI prints the token instead. Signing in again
deletes the token that the new one replaces, and `stogas logout` deletes the current one.

For servers and CI, create a token on the **Account** page with only the access and organizations
that the job needs, and set it as `STOGAS_TOKEN`. The CLI then uses it instead of the keychain, and
`signup`, `login` and `logout` refuse to run. See [Access tokens](/docs/reference/dashboard#access-tokens)
for what each token can do and when it stops working.

## Add credit

```console
stogas topup 25 BTC
stogas topup 25 USDT --network TRX
stogas topup 25 XMR --organization <organization-id>
```

The amount is the USD credit you want; the CLI prints the coin amount to send and the estimated
fees, which are added on top. Bitcoin and Monero go to the organization's
[deposit address](/docs/billing#pay-with-bitcoin-or-monero), and other coins through
[CCPayment](/docs/billing#pay-through-ccpayment). Use `--network` when a coin is available on
several networks; the error lists them. Without `--organization`, the credit goes to your personal
organization.

When the organization has no billing location yet, the CLI asks for its country, and in the
United States and Canada its state or province and postal code. The CLI then prints the address,
any memo, and a QR code on a terminal, and waits until the payment is credited. Press Ctrl+C to
stop waiting; the payment is still credited, and **Balance** shows it.

## Call the dashboard API

```console
stogas api GET /api/account
stogas api POST /api/<organization-id>/keys --input key.json
```

The CLI sends the request with your token and prints the response. On a terminal it formats JSON;
otherwise it writes the exact response, ready for `jq` or a file. `--input` reads a JSON body from
a file, or from standard input with `-`. A refused request prints the error, and the command exits
with status 1. The [Dashboard API](/docs/reference/dashboard) reference lists every operation.

## Other commands

| Command                    | Use                                                                              |
| -------------------------- | -------------------------------------------------------------------------------- |
| `stogas encryption-key`    | Create an organization key for [customer encryption](/docs/customer-encryption). |
| `stogas encrypt`           | Encrypt plugin settings or a provider credential with that key.                  |
| `stogas proof`             | Check a saved [receipt](/docs/receipts#check-a-receipt-later).                   |
| `stogas download-evidence` | Save the evidence that a receipt names, to check it without network access.      |
| `stogas verify-release`    | Check a [downloaded release](/docs/reproducible-builds#verify-an-sdk-download).  |

Run `stogas <command> --help` for every option.
