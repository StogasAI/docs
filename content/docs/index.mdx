We provide one API for supported AI models. Existing OpenAI-compatible clients work by changing the base URL.

## 1. Create an API key

Open the [Stogas dashboard](https://app.stogas.ai) and select the organization that will own the key.
If it is inactive, open **Balance** and add at least $1 in credited funds to activate it.
See [Billing](/docs/billing) for payment fees and when credit becomes available.

Create an API key. Under its **Credentials** tab, select **Stogas managed** for Chutes.
New keys start with this assignment. OpenAI, Anthropic and Azure require your own
[provider credential](/docs/byok), assigned to the key before use.

Copy the key and export it:

```console
export STOGAS_API_KEY="your-key"
```

See [API key types](/docs/api-keys) to choose between an organization service key and a
member-assigned key.

## 2. Send a request

These examples use the Chutes deployment `chutes-mistral-nemo-instruct-2407`.
The key must be enabled, have available funds and allowance, and permit this deployment
under its [effective policy](/docs/policies).

```console
curl https://api.stogas.ai/v1/chat/completions \
  -H "Authorization: Bearer $STOGAS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "chutes-mistral-nemo-instruct-2407",
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'
```

Or use the OpenAI Python client:

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-key",
    base_url="https://api.stogas.ai/v1",
)

response = client.chat.completions.create(
    model="chutes-mistral-nemo-instruct-2407",
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
)
print(response.choices[0].message.content)
```

## 3. Choose a model

Use the [model catalog](https://stogas.ai/catalog), or query it directly:

```console
curl https://api.stogas.ai/v1/models
```

## Protect the connection

Normal OpenAI-compatible requests need no Stogas-specific SDK. If you want your application to
check the gateway and encrypt the connection, continue with [Verify a gateway](/docs/verification).

## Request limits

Inference requests accept a decoded JSON body up to 128 MiB, at most 100,000 entries in
`messages` or array-valued `input`, and at most 1,000,000 JSON values with 128 levels of
nesting. Objects, arrays and scalar values count toward the value limit; property names
and text inside strings do not. Exceeding the body, message or value limit returns HTTP 413.
The selected provider's body, context and output limits also apply.

The catalog filters deployments using requested features and output/reasoning limits before
credential preparation and text processing. An incompatible explicitly selected model fails
instead of being replaced. Provider-specific parameter combinations still receive provider validation.
