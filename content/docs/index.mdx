Stogas provides a public OpenAI-compatible API gateway that proxies requests to upstream AI providers. You authenticate once with a Stogas API key — no need to manage individual provider keys.

## Base URL

```
https://api.stogas.ai
```

Endpoint paths include their API version.

## Endpoints

| Method | Path                   | Auth Required | Description                        |
| ------ | ---------------------- | :-----------: | ---------------------------------- |
| `GET`  | `/health`              |      No       | Gateway readiness check            |
| `POST` | `/v1/chat/completions` |      Yes      | OpenAI-compatible chat completions |
| `POST` | `/v1/responses`        |      Yes      | OpenAI-compatible Responses API    |

## Authentication

All model endpoints require a Stogas API key:

```http
Authorization: Bearer <stogas_api_key>
Content-Type: application/json
```

For SDK compatibility, the gateway also accepts the same key in `api-key`, `x-api-key`, and `x-goog-api-key`.
These are header aliases only; query parameters and cookies are not supported for API key authentication.

Get your key from the [Stogas Dashboard](https://app.stogas.ai).

## CORS

The gateway is intentionally browser-embeddable:

```http
Access-Control-Allow-Origin: *
```

No cookies are used for public API authentication.

## Debug Headers

<Callout type="info" title="Raw request mode">
	Set `X-Stogas-Return-Raw-Request: true` to receive the translated upstream provider request at
	`stogas.raw_request`.
</Callout>

<Callout type="info" title="Raw response mode">
	Set `X-Stogas-Return-Raw-Response: true` to receive the raw upstream provider JSON body.
</Callout>

Request additional metadata fields with:

```http
X-Stogas-Return-Extra-Fields: provider,model_requested,latency
```

Available field names: `provider`, `model_requested`, `model_deployment`, `latency`, `provider_response_headers`, `raw_request`, `raw_response`.

## Admission Failures

Before the gateway calls an upstream provider, it places a short-lived billing hold for the API key. Failed admission requests never create usage telemetry.

Known API keys record only these latest dashboard failure reasons: `insufficient_balance`, `key_disabled`, `key_expired`, `spend_limit_exceeded`, and `rate_limit_exceeded`. Unknown keys, request-ID conflicts, invalid internal hold amounts, and billing database outages are not attached to any key.

For streaming responses, metadata is emitted as a single SSE event before `[DONE]`:

```
event: stogas.meta
data: { ... }
```
