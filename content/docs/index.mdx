We provide one API for supported AI models. Existing OpenAI-compatible clients work by changing the base URL.

## 1. Create an API key

Open the [Stogas dashboard](https://app.stogas.ai) and select the organization that will own the key.
Your **personal organization** is for your own work. An **external organization** is a shared
workspace with members and roles. Use the organization menu to switch or create a shared organization.
If it is inactive, open **Balance** and add at least $1 in credited funds to activate it.
See [Billing](/docs/billing) for payment fees and when credit becomes available.

Create an API key. Under its **Credentials** tab, select **Stogas managed** for Chutes.
New keys start with this assignment. OpenAI, Anthropic and Azure require your own
[provider credential](/docs/byok), assigned to the key before use.

Copy the key and export it:

```console
export STOGAS_API_KEY="your-key"
```

See [API key types](/docs/api-keys) to choose between an organization service key and a
member-assigned key.

## 2. Send a request

These examples use the Chutes deployment `chutes-mistral-nemo-instruct-2407`.
The key must be enabled, have available funds and allowance, and permit this deployment
under its [effective policy](/docs/policies). The 64-token output cap keeps this first request
small; the reservation otherwise uses the deployment's maximum.

These examples call `api.stogas.ai`. Use an API key from the matching environment. If your
dashboard provides another API base URL, replace the URL in both examples. The address hosting
these docs does not select the API endpoint. Inference consumes billable usage.

```console
curl https://api.stogas.ai/v1/chat/completions \
  -H "Authorization: Bearer $STOGAS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "chutes-mistral-nemo-instruct-2407",
    "messages": [{"role": "user", "content": "Say hello in one sentence."}],
    "max_completion_tokens": 64
  }'
```

Or use the OpenAI Python client:

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-key",
    base_url="https://api.stogas.ai/v1",
    max_retries=0,
)

response = client.chat.completions.create(
    model="chutes-mistral-nemo-instruct-2407",
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
    max_completion_tokens=64,
)
print(response.choices[0].message.content)
```

A successful request returns HTTP 200 with the model's reply in `choices[0].message.content`.
The Python example prints that reply. Automatic retries are disabled because a disconnected
request may already have run.

| Error             | Next step                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `402`             | Check the organization's balance and applicable policy allowances.                                                     |
| `model_ambiguous` | Choose an exact deployment from the catalog.                                                                           |
| Provider error    | Inspect the request in **Analytics** before retrying. See [provider errors](/docs/reference/provider-behavior#errors). |

## 3. Choose a model

Use the [model catalog](https://stogas.ai/catalog), or query it directly:

```console
curl https://api.stogas.ai/v1/models
```

The directory organizes models into their authors' groups. Groups may nest at any depth and do
not inherit prices, capabilities, or data-handling guarantees. Use `group:` in catalog search.
**Include retired** loads archived records separately; active browsing does not download them.
Retired model and deployment URLs remain available, but retired deployments cannot receive requests.
