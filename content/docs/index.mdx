The public OpenAI-compatible gateway proxies requests to upstream AI providers. You authenticate once with a gateway API key instead of managing individual provider keys.

## Base URL

```
https://api.stogas.ai
```

Endpoint paths include their API version.

## Endpoints

| Method | Path                   | Auth Required | Description                        |
| ------ | ---------------------- | :-----------: | ---------------------------------- |
| `GET`  | `/health`              |      No       | Gateway readiness check            |
| `POST` | `/v1/chat/completions` |      Yes      | OpenAI-compatible chat completions |
| `POST` | `/v1/responses`        |      Yes      | OpenAI-compatible Responses API    |

## Authentication

All model endpoints require a gateway API key:

```http
Authorization: Bearer <api_key>
Content-Type: application/json
```

The catalog also defines `api-key`, `x-api-key`, and `x-goog-api-key` as authentication aliases.
The gateway canonicalizes these aliases to `Authorization: Bearer <api_key>` internally. Query parameters and cookies are not supported for API key authentication.

Get your key from the [dashboard](https://app.stogas.ai).

## CORS

The gateway is intentionally browser-embeddable:

```http
Access-Control-Allow-Origin: *
```

No cookies are used for public API authentication.

## Metadata Fields

Request catalog-defined metadata fields with:

```http
X-Stogas-Return-Extra-Fields: provider,model_requested,latency,raw_request,raw_response
```

Available field names: `provider`, `model_requested`, `model_deployment`, `latency`, `provider_response_headers`, `raw_request`, `raw_response`. Provider response headers are limited to diagnostic request identifiers and provider processing/version headers; account, rate-limit, cookie, CORS, and infrastructure headers are never returned.

## Admission Failures

Before the gateway calls an upstream provider, it places a short-lived billing hold for the API key. Failed admission requests never create usage telemetry.

Known API keys record only these latest dashboard failure reasons: `insufficient_balance`, `key_disabled`, `key_expired`, `spend_limit_exceeded`, and `rate_limit_exceeded`. Unknown keys, request-ID conflicts, invalid internal hold amounts, and billing database outages are not attached to any key.

For streaming responses, metadata is emitted as a single SSE event before `[DONE]`:

```
event: stogas.meta
data: { ... }
```
