title: Text extraction
description: Turn text and Office files into prompt text that every model reads and redaction scans.

---

Text extraction turns inline files into prompt text: text files such as CSV, JSON and source code,
and Office files such as Word, Excel and PowerPoint. The text works on any deployment, even one
that accepts no documents, and goes through [PII redaction](/docs/pii-redaction) and input checks
like the rest of the prompt.

```json title="Policy"
{
	"plugins": { "textExtraction": { "text": "auto", "office": "always" } }
}
```

Each key names a kind of file, and its value is the mode of those files:

| Key                              | Files                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------- |
| `text`                           | [UTF-8 text files](#what-counts-as-a-text-file)                                  |
| `office`                         | [Word, Excel, PowerPoint and OpenDocument files](#what-counts-as-an-office-file) |
| A media type, such as `text/csv` | [Files of that one type](#set-one-media-type)                                    |

| Mode     | A deployment that reads the file | Any other deployment       |
| -------- | -------------------------------- | -------------------------- |
| `off`    | The file stays a file            | The deployment is left out |
| `auto`   | The file stays a file            | The file becomes text      |
| `always` | The file becomes text            | The file becomes text      |

[PII redaction](/docs/pii-redaction) and [ASCII-only input](/docs/pii-redaction#ascii-only-input)
read only text. With either, `auto` turns every file that it covers into text, and `off` refuses
one.

A file that stays a file goes to the provider [as a type that it reads](/docs/input-files#text-files).
`always` gives every candidate the same prompt, whichever provider serves the request.

## Set one media type

```json title="Policy"
{
	"plugins": {
		"textExtraction": {
			"office": "auto",
			"application/vnd.openxmlformats-officedocument.spreadsheetml.sheet": "always"
		}
	}
}
```

This policy turns every Excel workbook into text, and other Office files only where the deployment
does not read them. In one policy, the mode of a media type applies to its files in place of the
mode of their family.

- A key is a lowercase media type without parameters that a family holds: a
  [text type](#what-counts-as-a-text-file) or an [Office type](#what-counts-as-an-office-file). A
  class such as `text/*`, a filename extension and any other type fail when you save the policy.
- The gateway reads the type from the data URL or `file_type`. A text file with no type is
  `text/plain`, and an Office file with no type has the type of its filename extension.
- Text formats have no signature, so a client can send a CSV file as `text/plain`. Set `text` where
  the mode must not depend on the type that a client declares.

## A file that no policy sets is off

The gateway changes a file only when a policy says so. A new organization's policy starts with this
[default rule](/docs/policies/rules#defaults), which you can edit or remove:

```json title="Organization policy"
{
	"rules": {
		"default_extraction": {
			"mode": "default",
			"plugins": { "textExtraction": { "text": "auto", "office": "auto" } }
		}
	}
}
```

A required mode for a family, or for one of its media types, replaces the default modes of that
family. To change one media type and keep the rest of a default, repeat the family:

```json title="Key policy"
{
	"plugins": { "textExtraction": { "text": "auto", "text/csv": "always" } }
}
```

## How policies combine

When several policies set a mode for a file, the strongest applies: `always`, then `auto`, then
`off`. A policy that sets a family and not the file's media type gives the file its family mode.

| Organization policy | Key policy             | CSV files | Other text files |
| ------------------- | ---------------------- | --------- | ---------------- |
| `"text": "auto"`    | `"text/csv": "always"` | `always`  | `auto`           |
| `"text": "always"`  | `"text/csv": "off"`    | `always`  | `always`         |
| `"text/csv": "off"` | `"text": "auto"`       | `auto`    | `auto`           |

Each family combines on its own, so `"office": "always"` in one policy leaves the `text` mode of
another policy in place.

`off` never weakens another policy's mode. Use it as a
[neutral value](/docs/policies/rules#replace-a-default-without-adding-a-restriction) to replace a
default.

## What the provider gets

The gateway replaces each file with a text block. Its first line names the file and its media type:

```json tab="Request"
{
	"type": "file",
	"file": {
		"filename": "orders.csv",
		"file_data": "data:text/csv;base64,aWQsYW1vdW50CjEsMjAKMiwzNQ=="
	}
}
```

```json tab="Sent to the provider"
{
	"type": "text",
	"text": "orders.csv (text/csv)\nid,amount\n1,20\n2,35"
}
```

Responses names its blocks differently, so an `input_file` becomes an `input_text`. A
`cache_control` or `prompt_cache_breakpoint` on the file moves to the text, so the provider caches
the prompt up to the same place:

```json tab="Request"
{
	"type": "input_file",
	"filename": "schema.json",
	"file_data": "data:application/json;base64,eyJ0eXBlIjoib2JqZWN0In0=",
	"cache_control": { "type": "ephemeral" }
}
```

```json tab="Sent to the provider"
{
	"type": "input_text",
	"text": "schema.json (application/json)\n{\"type\":\"object\"}",
	"cache_control": { "type": "ephemeral" }
}
```

A file without a filename starts with its type alone, such as `(application/yaml)`, and a file
without a type starts with its filename alone. A file block with any other field fails, so nothing
in the request is lost.

## Text files

| File            | Media type               |
| --------------- | ------------------------ |
| `notes.md`      | `text/markdown`          |
| `orders.csv`    | `text/csv`               |
| `page.html`     | `text/html`              |
| `main.py`       | `text/x-python`          |
| `app.js`        | `application/javascript` |
| `data.json`     | `application/json`       |
| `events.ndjson` | `application/x-ndjson`   |
| `config.yaml`   | `application/yaml`       |
| `Cargo.toml`    | `application/toml`       |
| `query.sql`     | `application/sql`        |
| `feed.xml`      | `application/rss+xml`    |
| `logo.svg`      | `image/svg+xml`          |

Each becomes its header line, such as `main.py (text/x-python)`, then its content unchanged. The
gateway never rewrites a text file, so a table stays the CSV, TSV or Markdown that you sent.

### What counts as a text file

- A file whose data URL or `file_type` names `text/*`, a type that ends in `+json` or `+xml`, or
  one of these application types:

  ```txt
  application/csv  application/ecmascript  application/graphql  application/javascript
  application/json  application/json5  application/jsonl  application/sql  application/toml
  application/typescript  application/x-awk  application/x-bash  application/x-diff
  application/x-graphql  application/x-httpd-php  application/x-httpd-php-source
  application/x-javascript  application/x-json5  application/x-latex  application/x-ndjson
  application/x-patch  application/x-perl  application/x-php  application/x-powershell
  application/x-ruby  application/x-rust  application/x-scala  application/x-sh
  application/x-shellscript  application/x-sql  application/x-subrip  application/x-terraform
  application/x-tex  application/x-toml  application/x-yaml  application/xml  application/yaml
  ```

- A file with no type, or with `application/octet-stream`, whose content is text. Browsers give
  most source files, such as `.rs`, `.go` and `.zig`, no type.

The filename never decides whether a file is text.

Extraction needs valid UTF-8 without NUL bytes. A file that names a text type and holds other
bytes fails the request with 400, and a file with no type stays a file. Only document blocks are
extracted, so an SVG sent as an image stays an image.

## Office files

| Format                            | Extensions               | Becomes                                               |
| --------------------------------- | ------------------------ | ----------------------------------------------------- |
| Word and OpenDocument text        | `.docx`, `.docm`, `.odt` | Markdown with headings, lists, tables and footnotes   |
| Excel and OpenDocument sheets     | `.xlsx`, `.xlsm`, `.ods` | One CSV for each sheet, under a heading with its name |
| PowerPoint and OpenDocument decks | `.pptx`, `.pptm`, `.odp` | The text, tables and speaker notes of each slide      |

```txt tab="Word"
report.docx (application/vnd.openxmlformats-officedocument.wordprocessingml.document)
# Quarterly report

Revenue grew 12% in the third quarter.[^1]

- Europe
  - Zürich

| Region | Revenue |
| --- | --- |
| Europe | 1,200 |

[^1]: Unaudited.
```

```txt tab="Excel"
orders.xlsx (application/vnd.openxmlformats-officedocument.spreadsheetml.sheet)
## Orders
id,customer,amount,ordered
1,"Acme, Inc.",20.5,2026-03-01
total,,20.5
```

```txt tab="PowerPoint"
plan.pptx (application/vnd.openxmlformats-officedocument.presentationml.presentation)
## Slide 1
Launch plan
Ship in May
Notes:
Mention the beta users.
```

- A Word file gives its text with every tracked change accepted. Text boxes, footnotes and
  endnotes are part of it. Headers, footers and comments are not.
- A cell gives the value that the file stores: the last result of a formula, and a date or time in
  ISO 8601 where the cell's format shows one. Hidden sheets, rows and slides are part of the text.
- Slide numbers, dates and footers are left out.
- Images, charts and embedded files have no text and are left out. To let the model see them, send
  the file to a deployment that [reads the format](/docs/input-files#supported-formats).

### What counts as an Office file

- A zip archive whose data URL or `file_type` names one of these types.
- A zip archive with no type, `application/octet-stream` or `application/zip`, whose filename has
  one of these extensions.

| Extension | Media type                                                                  |
| --------- | --------------------------------------------------------------------------- |
| `.docx`   | `application/vnd.openxmlformats-officedocument.wordprocessingml.document`   |
| `.docm`   | `application/vnd.ms-word.document.macroenabled.12`                          |
| `.odt`    | `application/vnd.oasis.opendocument.text`                                   |
| `.xlsx`   | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`         |
| `.xlsm`   | `application/vnd.ms-excel.sheet.macroenabled.12`                            |
| `.ods`    | `application/vnd.oasis.opendocument.spreadsheet`                            |
| `.pptx`   | `application/vnd.openxmlformats-officedocument.presentationml.presentation` |
| `.pptm`   | `application/vnd.ms-powerpoint.presentation.macroenabled.12`                |
| `.odp`    | `application/vnd.oasis.opendocument.presentation`                           |

The content must match the declared format. A spreadsheet that is named `report.docx` fails the
request with 400.

### Limits

| Limit                             | Value  |
| --------------------------------- | ------ |
| XML inside one file, uncompressed | 32 MiB |
| Text from one file                | 8 MiB  |

A file beyond a limit, a file that is not a readable archive and a file whose XML is not UTF-8 fail
the request with 400 where extraction applies.

## What stays a file

| Input                                    | Why                                                                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| PDFs and other binary formats            | The provider reads them. [Find a route](/docs/input-files#supported-formats) that lists the format. |
| `.doc`, `.xls` and `.ppt` files          | The Office 97 to 2003 formats are binary.                                                           |
| Password-protected Office files          | Their content is encrypted.                                                                         |
| RTF, Protocol Buffers and email messages | They hold binary data or encoded parts, not plain text.                                             |
| Images and audio                         | Models read them as they are.                                                                       |
| URLs and file IDs                        | The gateway never downloads a file.                                                                 |

To refuse some file types outright, [allow or deny them](/docs/input-files#allow-or-deny-file-types).

## What the request record shows

```jsonc
"plugins": {
	"text_extraction": {
		"files_extracted": 2, // Files sent as text.
		"duration_us": 1840 // Time spent reading them, in microseconds.
	}
}
```

The [request record](/docs/request-records) has this entry only when a file became text.
