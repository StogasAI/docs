---
title: PII redaction
description: Replace personal data, secrets, hidden characters and your own terms in prompts before a provider receives them, and in responses.
icon: EyeOff
---

Redaction replaces personal data, credentials, hidden characters and terms that you choose with
placeholders such as `<EMAIL_ADDRESS>`, before the gateway sends a request to the provider. It runs
inside the confidential gateway, so the original text never leaves it. Redaction is off until a
policy turns it on. A policy can also [put the values back in the response, refuse a match, count
matches without changing them, or redact the response](#parts-and-actions).

## Turn on redaction

Add `redaction` to the policy of an API key or another [scope](/docs/policies/scopes), then
[save the policy](/docs/policies/editing):

```jsonc title="policy.json"
{
	"plugins": {
		"redaction": {
			"presets": ["email_address", "bank_identifiers"], // Presets that you leave out stay off.
			"literals": [{ "values": ["Project Aurora"], "ignoreCase": true }], // Your own terms.
			"customPattern": "\\bEMP-[0-9]{6}\\b" // Employee IDs such as EMP-123456.
		}
	}
}
```

With this policy, a prompt reaches the provider with placeholders:

```text title="Your prompt"
Email ana.silva+orders@contoso.com about EMP-123456 and project aurora.
```

```text title="What the provider receives"
Email <EMAIL_ADDRESS> about <CUSTOM_PII> and <CUSTOM_PII>.
```

Every setting is optional. An empty `redaction` object adds no rules and replaces
[default redaction](/docs/policies/rules#defaults). To keep the terms private,
[encrypt the redaction](/docs/customer-encryption#encrypt-plugin-settings).

## Presets

Each preset in `presets` turns on a group of detectors:

| Preset                   | Replaces                                                          | Placeholders                                                                            |
| ------------------------ | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `email_address`          | Email addresses                                                   | `<EMAIL_ADDRESS>`                                                                       |
| `phone_number`           | Formatted phone numbers, including international numbers          | `<PHONE_NUMBER>`                                                                        |
| `social_security_number` | U.S. Social Security numbers                                      | `<US_SSN>`                                                                              |
| `credit_card_number`     | Payment card numbers                                              | `<PAYMENT_CARD>`                                                                        |
| `ip_address`             | IPv4 and IPv6 addresses                                           | `<IP_ADDRESS>`                                                                          |
| `api_keys_and_secrets`   | Passwords, API keys, tokens, private keys and credentials in URLs | `<CREDENTIAL>`, `<VENDOR_TOKEN>`, `<PRIVATE_KEY>`, `<JSON_WEB_TOKEN>`, `<DATABASE_URL>` |
| `bank_identifiers`       | IBANs and U.S. ABA routing numbers                                | `<IBAN>`, `<US_ROUTING_NUMBER>`                                                         |
| `national_identifiers`   | National, tax and business IDs from many countries                | One for each type, such as `<UK_NATIONAL_INSURANCE_NUMBER>`                             |
| `health_identifiers`     | Health insurance and provider IDs from several countries          | One for each type, such as `<US_NPI>`                                                   |
| `hidden_characters`      | Characters that a reader cannot see and a model reads             | `<HIDDEN_CHARACTERS>`                                                                   |

Detectors check the format, checksum and nearby labels, so ordinary numbers do not match. Some
values match only with a label nearby, such as `ITIN`, `NHS` or `routing number`. Known sample values, such as the card number
`4242 4242 4242 4242` and the SSN `123-45-6789`, never match. Numbers written with other digits,
such as full-width or Arabic-Indic digits, also match.

<Accordions type="multiple">
<Accordion title="Email addresses">

Covers plus-addressing, subdomains and Unicode letters, such as `élise@bücher.de`. Addresses at
reserved domains, such as `example.com` and `.test`, stay unchanged. Quoted local parts, IP address
literals and obfuscated addresses, such as `name at domain dot com`, are not detected.

</Accordion>
<Accordion title="Phone numbers">

Covers formatted North American numbers, such as `(415) 555-2671` and `+1 415-555-2671`, and
international formats such as `+44 20 7946 0958`. A marked extension of up to ten digits, such as
`ext. 204`, `x204` or `;ext=204`, is replaced with the number. Unformatted strings of digits are
not detected.

</Accordion>
<Accordion title="Social Security numbers and payment cards">

SSNs match in the form `NNN-NN-NNNN`. Other forms need a nearby `SSN` or `social security` label.
Numbers that the Social Security Administration never issues, such as area `000`, `666` or
`900`–`999`, do not match.

Payment cards need a known network prefix and length, a valid Luhn checksum, and the usual grouping
of digits or a nearby card label. `national_identifiers` does not include SSNs, and
`bank_identifiers` does not include payment cards.

</Accordion>
<Accordion title="Bank identifiers">

IBANs, with or without spaces, for every country length, with checksum validation. Nine-digit U.S.
ABA routing numbers, with a nearby routing label and checksum validation. Account numbers, SWIFT/BIC
codes and cryptocurrency wallet addresses are not detected.

</Accordion>

<Accordion title="API keys and secrets">

- Database URLs with credentials, for PostgreSQL, CockroachDB, MySQL, MariaDB, MongoDB, SQL Server,

</Accordion>
<Accordion title="Hidden characters">

Each run of the [hidden characters](/docs/classification#hidden-characters) that classification
counts becomes one placeholder, such as instructions written in Unicode tag characters. Text from
web pages and files reaches a model in tool results, so this redaction refuses a request whose tool
results hold any:

```json title="policy.json"
{
	"plugins": {
		"redaction": {
			"presets": ["hidden_characters"],
			"parts": ["toolResults"],
			"action": "refuse"
		}
	}
}
```

</Accordion>
</Accordions>

## Terms and phrases

Use `literals` for names, code words, domains and other exact text. Each group applies its options
to every string in `values`:

```jsonc title="policy.json"
{
	"plugins": {
		"redaction": {
			"literals": [
				// Also matches "project aurora" and one typo, such as "Project Auorra".
				{ "values": ["Project Aurora", "Project Borealis"], "ignoreCase": true, "fuzzy": true },
				// Matches inside longer text, such as https://wiki.internal.contoso.com/page.
				{ "values": ["internal.contoso.com"], "wholeWord": false }
			]
		}
	}
}
```

<PolicyFields section="literalRule" />

- Terms are plain text: `.` and `*` have no special meaning. Every match becomes `<CUSTOM_PII>`.
- With `wholeWord` on, the characters next to a match cannot be letters, numbers, combining marks or
  underscores.
- `ignoreCase` treats ASCII `A`–`Z` and `a`–`z` as equal. Other letters keep their case.
- `fuzzy` also matches one inserted, deleted or changed character, or two swapped neighbors. A fuzzy
  term needs 8–64 printable ASCII characters, a letter, digit or underscore at each end, and
  `wholeWord` on.
- Text is not normalized. Composed and decomposed Unicode, look-alike characters, percent-encoding
  and abbreviations count as different text.

Each term can be up to 256 bytes. One policy, counting its rules, can have up to 1,000 terms and
65,536 bytes of term text.

## Custom pattern

For identifiers with a fixed structure, add one regular expression. Use `|` for more than one
format:

```jsonc title="policy.json"
{
	"plugins": {
		"redaction": {
			// Matches EMP-123456 and ACCT-FR-12345678.
			"customPattern": "\\b(?:EMP-[0-9]{6}|ACCT-[A-Z]{2}-[0-9]{8})\\b"
		}
	}
}
```

<Callout type="warn">
	In JSON, write `\\b` for the regex `\b`. A single `\b` in a JSON string is a backspace character.
</Callout>

- Patterns use [Go RE2 syntax](https://pkg.go.dev/regexp/syntax). Lookarounds, backreferences and
  `\C` are not supported.
- Every match becomes `<CUSTOM_PII>`.
- A pattern must match at least one character. Patterns that can match empty text, such as `.*`,
  and patterns that match a placeholder are rejected.
- `\b` uses ASCII word characters, and `(?i)` uses Unicode case folding.
- Start with fixed text and bound each repetition, such as `EMP-[0-9]{1,12}`, to keep scans fast.

| Limit                                       | Maximum            |
| ------------------------------------------- | ------------------ |
| Patterns in a policy or in one of its rules | 1                  |
| Patterns in one policy, counting its rules  | 16                 |
| Size of one pattern                         | 512 bytes          |
| Compiled size of one policy's patterns      | 4,096 instructions |
| Count in one repetition, such as `{1000}`   | 1,000              |

## Parts and actions

`parts` names the text that a redaction reads, and `action` says what a match does. A policy and
each of its [rules](/docs/policies/rules) hold one redaction, so use rules to treat text
differently:

```jsonc title="policy.json"
{
	"plugins": {
		// Replace card numbers in the whole request. Both settings have this default.
		"redaction": { "presets": ["credit_card_number"] }
	},
	"rules": {
		"contacts": {
			// The provider gets <EMAIL_ADDRESS_1>, and your application gets the address back.
			"plugins": { "redaction": { "presets": ["email_address"], "action": "restore" } }
		},
		"tool-secrets": {
			// Refuse a request whose tool results hold a credential.
			"plugins": {
				"redaction": {
					"presets": ["api_keys_and_secrets"],
					"parts": ["toolResults"],
					"action": "refuse"
				}
			}
		},
		"replies": {
			// Replace phone numbers that the model writes.
			"plugins": { "redaction": { "presets": ["phone_number"], "parts": ["response"] } }
		}
	}
}
```

| Part          | Text                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| `request`     | Every request part below. This is the default.                                       |
| `system`      | System and developer messages, and `instructions`                                    |
| `user`        | User messages, and an `input` that is one string                                     |
| `assistant`   | Assistant messages, tool calls and reasoning from earlier turns                      |
| `toolResults` | Tool results, and the result inside a call that the provider ran                     |
| `tools`       | Tool definitions, structured output schemas and stop sequences                       |
| `response`    | The text, refusals, tool call arguments and unsigned reasoning that the model writes |

| Action    | A match                                                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------------- |
| `replace` | Becomes a placeholder. This is the default.                                                                            |
| `restore` | Becomes a numbered placeholder, such as `<EMAIL_ADDRESS_1>`, and the response gets the value back. Request parts only. |
| `refuse`  | Fails the request with [`redaction_refused`](#errors).                                                                 |
| `record`  | Stays as it is, and the [request record](#check-results) counts it.                                                    |

- Where redactions read the same text, the strictest action applies to a match: `refuse`, then
  `replace`, then `restore`, then `record`.
- A message or an input item with a role or type that the gateway does not know counts as every
  request part.
- `parts` and `action` need a preset, a term or a pattern in the same redaction.

### Restore values in the response

With `restore`, each value keeps one number through the request, so the model can tell two
addresses apart:

```text title="Your prompt"
Forward the note from ana@contoso.com to li@contoso.com, and copy ana@contoso.com.
```

```text title="What the provider receives"
Forward the note from <EMAIL_ADDRESS_1> to <EMAIL_ADDRESS_2>, and copy <EMAIL_ADDRESS_1>.
```

```text title="What the model writes"
Done. <EMAIL_ADDRESS_2> has the note.
```

```text title="What you receive"
Done. li@contoso.com has the note.
```

- The gateway puts the values back in the response text and in tool call arguments, where it
  writes them as JSON strings. It keeps the values in memory until the response ends, and stores
  none.
- Reasoning keeps its placeholders, because providers sign reasoning and reject a changed copy in
  the next turn.
- A placeholder that the model changes, such as `<EMAIL ADDRESS 1>`, stays as it is.
- A tool that the provider runs, such as web search, gets the placeholder.
- Citations keep the character positions that the provider wrote, so a position after a value
  that changed length can be off.
- The request record and the [export](/docs/export) keep the request with its placeholders.
- With `stream: true`, text arrives as the model writes it. Only a text that may be the start of a
  placeholder waits for the events that complete it.

### Count matches before you enforce

`record` shows how often a redaction would match, before you let it change or refuse traffic:

```jsonc title="policy.json"
{
	"plugins": {
		"redaction": {
			"presets": ["email_address", "phone_number"],
			"parts": ["request", "response"],
			"action": "record"
		}
	}
}
```

- The request, the response and the stream stay as they are. Attachments and log probabilities
  stay allowed.
- A match that a stricter redaction replaces or restores counts for that redaction only.
- The [redaction limits](#errors) still apply.

### A redaction of the response holds the stream

A redaction that replaces or refuses in `response` changes the response after the model finishes,
because a match can span two stream events. With `stream: true`:

- Events arrive when the provider's stream ends. Until then the gateway sends
  [keepalive comments](/docs/streaming).
- A text that changed arrives in one delta. Its other deltas are empty.
- A response that `refuse` matches is discarded. The request fails with `redaction_refused`, and
  the provider's usage is charged.

Signed or encrypted reasoning, images, audio, citations and log probabilities stay as the provider
wrote them. A request that asks for log probabilities fails with `400` while a redaction replaces
or refuses in `response`.

## What is scanned

Redaction runs after the gateway selects a deployment, and before it estimates input tokens and
calls the provider.

| Scanned                                                             | Not scanned                                      |
| ------------------------------------------------------------------- | ------------------------------------------------ |
| Message and `input` text, and instructions                          | Model, routing and policy fields                 |
| Tool definitions and tool call arguments                            | Headers, `metadata`, sampling and cache settings |
| Structured output schemas and stop sequences                        | Signed or encrypted reasoning from earlier turns |
| Files that [text extraction](/docs/text-extraction) turns into text | Encrypted web search results from earlier turns  |

Redaction cannot read images, audio, URLs, file IDs or other files, so it refuses them, and
[routing](/docs/input-files#when-no-candidate-reads-a-file) leaves out each candidate whose policy
redacts. Turn on text extraction to send text files, Office files and PDFs.

The settings of a [remote MCP server](/docs/model-tools#remote-mcp-servers), such as its address,
credentials and tool filters, are not scanned, because a changed token or address would fail.

- A `replace` cannot be undone. The gateway keeps no record of the original values.
- Placeholders can use more tokens than the text they replace. [Input estimates](/docs/usage#input-estimates)
  count the redacted text.
- Each detector reads the original text, and overlapping matches become one placeholder. A
  placeholder that the client sends does not protect the text around it.

## Combine scopes

Redaction from every scope that applies to a request adds together. For example, organization email
detection, a grant's banking detection and a key's custom pattern all run on the same request. A
child scope cannot turn off a preset, term or pattern that another scope requires.

Every pattern and term list reads the whole text, and one request has one
[scan budget](#errors). Each one that a scope adds lowers the largest text that a request can send.
To keep terms and patterns private, [encrypt the plugin
settings](/docs/customer-encryption#encrypt-plugin-settings).

## ASCII-only input

To reject a prompt that contains non-ASCII text, instead of redacting it:

```json title="policy.json"
{ "input": { "asciiOnly": true } }
```

<PolicyFields section="input" />

The check reads the [scanned fields](#what-is-scanned) before redaction, and refuses the
attachments that redaction refuses. JSON escapes such as `\u00e9` count as non-ASCII. Any scope
can require the check, and a child scope cannot turn it off.
A request policy can set it when `delegation.requests` permits `input.asciiOnly`.

## Errors

| Status | Code                        | Cause                                                                |
| ------ | --------------------------- | -------------------------------------------------------------------- |
| `400`  | `attachment_unsupported`    | Redaction or ASCII-only input is on, and an attachment is not text   |
| `400`  | `input_ascii_required`      | ASCII-only input is on, and the prompt has other characters          |
| `400`  | `redaction_refused`         | A redaction with `refuse` matched. The message names the placeholder |
| `413`  | `request_too_large`         | The request exceeded a redaction limit                               |
| `503`  | `gateway_capacity_exceeded` | The gateway cannot load the redaction policy now                     |

The redaction limits for one request are 65,536 matches in one text value, 100,000 replacements,
128 levels of JSON nesting, and one shared scan budget. Complex patterns and long text use more of
the budget, so a valid pattern can still exceed it. To fix a `413`, narrow the pattern or send less
text. Retry a `503` with backoff.

These errors happen before the provider receives the request, and they are not charged. The one
exception is a [response that a redaction refuses](#a-redaction-of-the-response-holds-the-stream). The gateway never
sends a request without its required redaction.

## Check results

The [request record](/docs/request-records) shows what redaction did:

```jsonc
"plugins": {
	"redaction": {
		"items_redacted": 3, // Values replaced in the request.
		"response_items_redacted": 1, // Values replaced in the response.
		"items_restored": 2, // Values put back in the response.
		"items_recorded": 4, // Matches that `record` counted in the request.
		"response_items_recorded": 1, // Matches that `record` counted in the response.
		"duration_us": 412 // Time spent scanning and replacing in the request, in microseconds.
	}
}
```

The record has no original values, positions or counts for each preset. To find requests in
[Analytics](/docs/analytics#filters), filter on `redaction:`. A request with `not_recorded` has no
redaction data in its record, but redaction may still have run.

## What redaction does not detect

- Names, street addresses, places, dates, UUIDs and numbers without a format or label.
- IDs that no preset lists.

Before you rely on a rule, test it with typical prompts, including values that must stay unchanged.
Redaction does not detect prompt injection or harmful content.
