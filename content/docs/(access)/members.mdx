---
title: Members and roles
description: Manage organization membership, assign permissions and connect roles to grants.
---

Open **Members** in an external organization to manage its members, roles and invitations. Roles
grant organization permissions and can be assigned View, Use, Manage, or Admin on particular folders, grants and
service keys or provider credentials. A [grant](/docs/grants) separately controls which member keys a person may create.
Personal organizations have no collaborative roles, grants or invitations.
See [organization types](/docs#1-create-an-api-key) if you are choosing where to work.

## Give a teammate API access

1. Select the shared organization. Reuse an existing grant with suitable limits, or create one
   from **Grants**.
2. Reuse a suitable role, or create one in **Members → Roles** with **Use** on that grant or its
   folder. It needs no organization-wide API key permissions.
3. Invite the teammate from **Invites**, then assign the role from **Members**. Review the default
   role assigned on joining and any other roles: broader access remains effective alongside this role.
4. The teammate opens **API keys**, creates their own member key under the grant, and uses that key.

Inviting and assigning roles requires **Members → Manage**. Introducing grant rights also
requires matching resource **Admin**; creating or editing the role requires **Roles → Manage**.
Use an existing suitable role when you do not need different access.

## Invite a member

Create an invitation from the **Invites** tab. Choose its expiry and permitted uses,
then share the invitation link. Delete an unused invitation to stop further joins; this does
not remove members who already joined. Joining assigns the organization's current default role.

## Assign roles

Create a role from the **Roles** tab. Choose organization permissions and add resources with
View, Use, Manage, or Admin. Search resources by name; only selected resources appear in the role.
Assign roles from the member list, individually or to a selection. Keep administrative permissions limited to the people
who need them. The role list shows the permissions and member count directly.

Analytics permissions cover request logs and usage; Activity covers organization audit events.

A role can have no organization-wide permissions and still grant access to assigned resources.
Adding a member gives them all of that role's resource rights, including management; removing the
role removes that source of access. Use on a grant or its folder lets members create their own keys.
Before removing a role, check whether it supplies the member's last grant Use: removing that
last source deletes their keys under the grant, and assigning the role again does not restore them.

Member managers can grant organization permissions they hold. New API-key or credential rights also
require Admin at the matching scope, including organization-wide grants. Existing recipient access
may be preserved.
Role-management permission allows creating and editing roles with permissions the manager does not hold. The final role manager cannot leave or be
removed while another member remains.

## Permission reference

These are the organization-wide labels in the role editor. Resource permissions apply only to
the selected folder, grant, service key, or credential; folder rights also cover its children.
Access from all assigned roles adds together. Their [policy restrictions](/docs/policies/scopes)
apply separately and can narrow inference even when access is granted.

| Area         | Permission | Allows                                                                                                     |
| ------------ | ---------- | ---------------------------------------------------------------------------------------------------------- |
| Activity     | Read       | Read organization audit events.                                                                            |
| API keys     | Read all   | Read all key, grant, and folder settings and usage.                                                        |
| API keys     | Use all    | Retrieve service-key secrets and create own keys from any grant.                                           |
| API keys     | Manage all | Create and manage keys, grants, folders, and their policies; edit organization, member, and role policies. |
| API keys     | Admin all  | Use and manage all API resources, and assign access within that scope.                                     |
| Analytics    | Read own   | Read own request logs and usage.                                                                           |
| Analytics    | Read all   | Read all organization request logs and usage.                                                              |
| Billing      | Read       | Read balance, payment history, and receipts.                                                               |
| Billing      | Manage     | Save billing details and create payment instructions.                                                      |
| BYOK         | Read all   | Read all provider credential metadata and policies.                                                        |
| BYOK         | Use all    | Assign any provider credential to keys you manage.                                                         |
| BYOK         | Manage all | Create, edit, replace, disable, or delete provider credentials.                                            |
| BYOK         | Admin all  | Use and manage all provider credentials, and assign access within that scope.                              |
| Members      | Read       | Read members, roles, and invitations.                                                                      |
| Members      | Manage     | Invite or remove members and assign existing roles, subject to assignment authority.                       |
| Organization | Manage     | Change organization settings.                                                                              |
| Roles        | Manage     | Create, edit, or delete roles, including roles with permissions you do not hold.                           |

Resource **Use** and **Manage** each include **View**, and can be combined as **Use and manage**.
**Admin** includes both and permits access assignment within that scope; assigning roles to members
also needs **Members → Manage**. Editing a role needs **Roles → Manage**, which is broader authority.
The editor includes required read permissions when you select a management permission.

Member-key owners can manage and use their own keys. Other managers can change their settings but
cannot retrieve their secrets or use them for inference. Credentials have no folder inheritance:
adding one to a key requires credential **Use** and key **Manage**; removing or reordering an existing
assignment requires only key **Manage**. Parent policy delegation can further restrict saved-policy
edits; see [who can edit each policy](/docs/policies/editing#open-the-editor).

## Scope a role to resources

In the role editor, add a folder, grant, service key, or provider credential and choose its permissions.
Folder rights cover contained grants and keys; grant rights cover member-key settings. Member-key
secrets and inference use remain owner-only. Credentials have no folder inheritance.

A role can combine organization permissions and different permissions on selected resources.
For grant access, select **Use** on the grant or its folder. Members receive that access through
their assigned roles. Shared access has no individual member exceptions.

## Remove access

Removing a member's last route to a grant deletes their member keys under that grant. Another
role, folder, or organization permission that grants Use preserves those keys. Restoring the role does not restore
deleted keys. Check the access being removed before confirming a role or membership removal.

For a reversible pause, disable the grant or an individual API key instead. Removing service-key
access preserves the key. Rotate its secret to revoke copies they may hold.

Voluntary departure preserves outstanding invitations. Administrative removal revokes invitations
created by that member. The last member's departure deletes the organization and its active resources;
financial history is retained.
