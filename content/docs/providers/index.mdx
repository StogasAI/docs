The [model catalog](https://stogas.ai/catalog) shows each deployment's price, context window,
input types, reasoning levels and data handling. [Routing policies](/docs/policies/routing) can
filter on these facts, for example to allow only zero data retention deployments.

## How the gateway reaches a provider

The gateway decrypts your request inside its confidential VM, applies your policies, and sends the
request to the selected provider. The provider sees the prompt, and we cannot prove how the provider
handles it. Each provider page lists that provider's published data terms.

- **OpenAI and Anthropic:** the gateway requires TLS 1.3 with the X25519MLKEM768 post-quantum key
  exchange.
- **Azure:** the gateway requires TLS 1.3. Azure endpoints do not accept a post-quantum-only
  connection, so the key exchange can fall back to classical X25519.
- **Chutes:** the gateway checks the hardware evidence of the TEE that runs the model and encrypts
  the prompt to a key bound to that evidence. See [Chutes](/docs/providers/chutes#end-to-end-encryption).

With [BYOK](/docs/byok), the request runs on your provider account under your agreement with that
provider. Chutes without BYOK runs on our account.

## Request fields

The gateway checks each request against the selected deployment before it calls the provider. A
field that the provider cannot accept, or that the gateway cannot price, returns `400` with no
charge. Unknown top-level fields are ignored and never forwarded. The
[compatibility notes](/docs/reference/provider-behavior) list fields that the gateway never accepts.
