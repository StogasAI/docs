Every catalog deployment belongs to one provider. The feature pages describe what all providers
share, and each provider's page lists its own setup, limits and data handling. The provider sees
your prompt and handles it under its own terms, as the [security model](/docs/security-model)
explains.

Every provider serves Chat Completions. The [catalog](https://stogas.ai/catalog) shows each
deployment's price, context window, input types, reasoning levels and data handling, and
[routing policies](/docs/policies/routing) can filter on them, for example to allow only zero data
retention deployments.

## Request fields

The gateway checks each request against the selected deployment before it calls the provider. A
field that the provider cannot accept, or that the gateway cannot price, returns `400` with no
charge, and so does an unknown top-level field. The
[compatibility notes](/docs/reference/provider-behavior) list fields that the gateway never accepts.

## Responses through Chat Completions

Azure and Chutes deployments that take only Chat Completions also take Responses requests. The
gateway translates the request to Chat Completions, and returns the reply, or each streamed event,
as Responses. The request record's `request_type` shows the API that you called, and each attempt's
[catalog chain](/docs/request-records#catalog-history) names the route that the gateway called. A
deployment that takes Responses itself always gets Responses, unless `model` names its Chat
Completions route.

A translated request returns `400` for what Chat Completions cannot carry:

- `include`, `text.verbosity` and `stream_options.include_obfuscation`
- hosted tools, such as `web_search`, and tool choices that name them
- a `reasoning.summary` other than `auto` or `none`
- input items other than messages, function calls, their outputs and reasoning
- file URLs and image file IDs
- earlier reasoning items on Azure. Chutes takes back their reasoning text, without
  `encrypted_content` or a summary.

Routing leaves out a translated deployment that cannot take the request, so another deployment can
serve it.

[^anthropic]: Only on deployments that Anthropic runs, whose IDs end in `-anthropic-hosted`.

[^translated]: Partly [through Chat Completions](#responses-through-chat-completions).
