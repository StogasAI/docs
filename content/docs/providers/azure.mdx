Azure deployments run GPT, Claude and open models from your Microsoft Foundry deployments. The
gateway calls them with a Microsoft Entra application that you create. Azure bills you for
inference, and we charge the [BYOK fee](/docs/byok#billing).

| Deployment ID suffix | Azure deployment type           | Where inference runs                   |
| -------------------- | ------------------------------- | -------------------------------------- |
| None                 | Global Standard                 | Any Azure region                       |
| `-us`                | US Data Zone Standard           | United States                          |
| `-eu`                | EU Data Zone Standard           | Europe, under Azure's EU Data Boundary |
| `-apac`              | Asia Pacific Data Zone Standard | Asia Pacific                           |
| `-instant`           | Instant access                  | A Foundry project in West US 3         |
| `-anthropic-hosted`  | Claude hosted by Anthropic      | Anthropic                              |

For example, `azure-gpt-5.5-2026-04-23-us` runs GPT-5.5 only in the United States. Instant access
needs a Foundry project in West US 3 that the credential can reach.

## Connect your account

Create an Entra application with a client secret, and give it the **Foundry User** role on your
model accounts, or on a resource group or subscription that holds them:

```bash
az ad sp create-for-rbac --name stogas-gateway \
  --role 53ca6127-db72-4b80-b1b0-d745d6d5456d \
  --scopes /subscriptions/<subscription-id>/resourceGroups/<group>
```

Enter `tenant`, `appId` and `password` from the output in [BYOK](/docs/byok) as the tenant ID,
client ID and client secret. Each account that you connect becomes its own credential. To connect
more accounts with the same application later, choose **Add accounts** in a credential's menu.

## Customer encryption

With [customer encryption](/docs/byok#customer-encryption), we store only the encrypted
application, and only a gateway can open it with your key.

1. Save the application, then encrypt it. The CLI also takes `tenantId`, `clientId` and
   `clientSecret` in a JSON object.

   ```bash
   az ad sp create-for-rbac --name stogas-gateway \
     --role 53ca6127-db72-4b80-b1b0-d745d6d5456d \
     --scopes /subscriptions/<subscription-id>/resourceGroups/<group> > app.json
   stogas encrypt --key-file org.key --organization <organization-id> \
     --purpose byok/azure --input app.json --output application.json
   ```

   Then delete `app.json`, which holds the secret.

2. In [BYOK](/docs/byok), add an Azure credential, select **Customer encrypted**, and paste
   `application.json`. Enter the resource ID of each account to connect, which
   `az cognitiveservices account list --query "[].id" --output tsv` lists. Each account becomes
   its own credential, and **Add accounts** in a credential's menu connects more with the same
   application.
3. Run the command that the dashboard shows where you keep the key, such as:

   ```console
   stogas byok check CREDENTIAL_ID ... --organization YOUR_ORGANIZATION_ID --key-file org.key
   ```

   A gateway signs in with the application, finds each account's deployments and saves them as
   targets, as for a stored credential. The CLI prints the targets that it found.

Until its first check, a credential has no targets, so no request uses it. After that, gateways
look for new deployments once a day while requests use the credential, and each check looks at
once. A replaced application keeps its targets until the next check.

## Targets

You choose which of your Azure deployments serves each catalog deployment. A target is one exact
model version, and the gateway never sends a request to a deployment that you did not choose. If a
target stops serving, the gateway tries the next candidate that your
[routing](/docs/policies/routing#retries-and-fallbacks) allows.

Azure upgrades deployments to new model versions unless their `versionUpgradeOption` is
`NoAutoUpgrade`. After an upgrade, the target stops serving, and requests to it fail with
`byok_target_changed` until you choose the new version.

## Claude on Azure

Claude accepts the same request fields as on [Anthropic](/docs/providers/anthropic), except
`task_budget`.
