Azure deployments run GPT, Claude and open models in your own Azure account through Microsoft
Foundry. The gateway calls your Foundry deployments with a Microsoft Entra application that you
create. Azure bills you for inference, and we charge the [BYOK fee](/docs/byok#billing).

## Connect your account

<Steps>
<Step>

### Create an application with the Foundry User role

Create one Microsoft Entra application with a client secret, and give it the **Foundry User** role
on your model accounts, or on a resource group or subscription that contains them. One application
can serve all of your accounts. With the Azure CLI:

```bash
az ad sp create-for-rbac --name stogas-gateway \
  --role 53ca6127-db72-4b80-b1b0-d745d6d5456d \
  --scopes /subscriptions/<subscription-id>/resourceGroups/<group>/providers/Microsoft.CognitiveServices/accounts/<account>
```

The output shows the tenant ID as `tenant`, the client ID as `appId` and the client secret as
`password`. Azure shows the secret only once.

In the Azure portal, register the application under **Microsoft Entra ID → App registrations** and
add a client secret under **Certificates & secrets**. Then open each account's **Access control
(IAM)** and add a **Foundry User** role assignment for the application.

- Foundry User lets us read the account and its deployments, and lets the gateway run model
  requests. **Owner**, **Contributor** and **Reader** do not allow model requests.
- `53ca6127-db72-4b80-b1b0-d745d6d5456d` is the ID of Foundry User, which Azure used to call Azure
  AI User. The ID stays the same under both names.
- A new role can take several minutes to apply.

</Step>
<Step>

### Connect accounts

Open **BYOK → Add → Azure**, enter the tenant ID, client ID, client secret and the IDs of the
subscriptions that hold your accounts, and select **Find accounts**. Choose the accounts and select
**Connect**. Each account becomes its own credential, named after the account.

The list marks an account that needs a change before you can connect it. For **Needs a custom
subdomain**, select **Generate Custom Domain Name** on the account's **Overview** page, because only
an endpoint on a subdomain accepts Entra sign-in. Apps that use the regional endpoint keep working,
but you cannot change the subdomain later.

Accounts created in the Azure portal, Cloud Shell or Azure CLI already have a subdomain, and an
Azure OpenAI account without one has its own `openai.azure.com` endpoint. A Foundry account created
from a template can lack one. To add it with the Azure CLI:

```bash
az cognitiveservices account update --name <account> --resource-group <group> \
  --custom-domain <subdomain>
```

</Step>
<Step>

### Assign it to a key

Open an API key and select the credential under **Credentials**.

</Step>
</Steps>

## Credential checks

We read your deployments and projects through Azure Resource Manager. These reads are free, so they
cannot prove quota; Azure checks quota when a request runs.

- We check each credential once a day, and an hour after a failed check.
- After you add, remove or change deployments or projects, select **Check credential** in the BYOK
  list, or **Refresh targets** in **Azure targets**, to update the targets at once.
- If the application has no role that allows model requests, the check fails but the credential
  keeps its targets, because a new role can take several minutes to show.
- To change the application or its secret, edit the credential. It keeps its account.

## Choose Azure targets

Each catalog deployment matches an exact model, version, hosting and deployment type in your
account. Open **Azure targets** on the credential to choose which of your Azure deployments serves
each match.

- A single match is selected for you. When there are several, you choose.
- Refreshing keeps your choices. New matches stay unselected.
- If a check fails, requests use the targets from the last successful check, and the BYOK list
  shows the failure.
- If a selected deployment disappears or its model retires, requests for it fail until you choose
  another. The gateway never guesses a deployment name or falls back to another provider.
- The BYOK list flags a credential that has no selected target or has selected targets that are
  unavailable. It also counts models that have targets but none selected, such as new deployments
  that a check found.

## Deployment types

The deployment ID shows the Azure deployment type:

| Deployment ID suffix | Azure deployment type           | Where inference runs                   |
| -------------------- | ------------------------------- | -------------------------------------- |
| None                 | Global Standard                 | Any Azure region                       |
| `-us`                | US Data Zone Standard           | United States                          |
| `-eu`                | EU Data Zone Standard           | Europe, under Azure's EU Data Boundary |
| `-apac`              | Asia Pacific Data Zone Standard | Asia Pacific                           |
| `-instant`           | Instant access                  | A Foundry project in West US 3         |

For example, `azure-gpt-5.5-2026-04-23-us` runs GPT-5.5 only in the United States. To keep every
request of a key in the United States, on any provider, add this
[routing filter](/docs/policies/routing):

```json title="Policy"
{
	"routing": { "filter": "deployment.dataHandling.processingLocation == 'US'" }
}
```

Instant access uses models that Microsoft runs for a Foundry project, without a deployment of your
own. The gateway finds them through a West US 3 project that the credential can reach. If one of
your deployments uses the same model name, the gateway skips the Instant target, because Azure would
send the request to your deployment instead.

`deployment.upstream.hosting` shows who runs the model. Claude runs on Azure, or on Anthropic for
IDs that end in `-anthropic-hosted`. Partners host some open models for Azure, and their processing
location is unknown.

## Tiers and Pro

| Mode | Models          | How Azure runs it                                                            |
| ---- | --------------- | ---------------------------------------------------------------------------- |
| Flex | Some GPT models | A request mode of your GPT deployment                                        |
| Fast | Some GPT models | Priority processing, a request mode of your GPT deployment                   |
| Fast | Claude Opus 5.5 | A separate model, `claude-opus-5-5-fast`, that you deploy                    |
| Pro  | Some GPT models | A request mode of your GPT deployment, on Responses only, at no extra charge |

Select Flex or Fast with `service_tier` or a `-flex` or `-fast` deployment ID, and Pro with
[`reasoning.mode`](/docs/reasoning#select-pro-mode) or a `-pro` deployment ID. A GPT deployment serves all of its request modes, so it needs no other target. For
Claude Opus 5.5 Fast, deploy `claude-opus-5-5-fast` in your account and choose it in **Azure
targets**. Azure runs every request to that deployment at Fast, and it does not share prompt caches
with standard Claude Opus 5.5. The catalog lists the tiers that each model has. See
[Service tiers](/docs/service-tiers).

## Endpoints

| Models      | Chat Completions | Responses |
| ----------- | ---------------- | --------- |
| GPT         | Yes              | Yes       |
| Claude      | Yes              | Yes       |
| Open models | Yes              | No        |

- On Chat Completions, Azure rejects GPT requests that combine reasoning with function tools. Use
  Responses for that combination.
- GPT models accept `max` effort only on Responses. On Chat Completions, the gateway sends `xhigh`
  instead.
- The gateway sends `temperature`, `top_p` and `logprobs` unchanged, and Azure returns `400` when a
  GPT model does not accept them.

## Prompt caching

GPT deployments use the same cache controls as [OpenAI](/docs/providers/openai#prompt-caching).
Azure reports cache reads and writes, and they are billed at the catalog rates.

Claude deployments use `cache_control`, as on [Anthropic](/docs/providers/anthropic#prompt-caching).

## Claude on Azure

Claude on Azure works as on [Anthropic](/docs/providers/anthropic), with these differences:

- Only Claude Opus 5.5 has Fast, as a separate model. See [Tiers and Pro](#tiers-and-pro).
- `task_budget` is rejected, because the gateway does not send it to Azure.
- System messages after the first turn are rejected.
- Claude Fable and Claude Mythos accept effort up to `xhigh`, which Microsoft says gives the same
  result as `max`. The gateway sends `xhigh` when a request asks for `max`.
- Claude Mythos 5.1 and Claude Mythos 5 need access from Anthropic, as on
  [Anthropic](/docs/providers/anthropic#models-that-need-approval). Until Anthropic grants it, Azure
  does not offer them for deployment.

## Tools and files

- GPT models accept `function` tools, and `custom` tools on Responses. They have no hosted tools.
- GPT models read PDFs on Responses. Chat Completions accepts no documents.
- DeepSeek models can return several tool calls in one turn, even when
  `parallel_tool_calls` is `false`.
- Claude reads PDFs and plain text, as on [Anthropic](/docs/providers/anthropic#files).

See [Images and files](/docs/input-files).

## Data handling

The gateway always sends `store: false`, and Microsoft does not train on your data. Your agreement
with Microsoft governs your account.

| Deployments                             | What Azure keeps                                                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ordinary deployments                    | No inference content, but abuse monitoring can keep flagged samples for human review. The catalog therefore does not list Azure as zero data retention. |
| Instant access, Flex and Azure previews | Microsoft's preview terms do not limit where or how long it stores data. The catalog lists storage as `world` and retention as unknown.                 |
| Claude hosted on Azure                  | Prompts and responses stay in Azure. Anthropic receives only usage data and content that its safety systems flag.                                       |
| Claude hosted by Anthropic              | IDs end in `-anthropic-hosted`. [Anthropic's data handling](/docs/providers/anthropic#data-handling) applies.                                           |

A filter such as `deployment.dataHandling.retentionDays == 0` skips previews.

Customer encryption is not available for Azure credentials. Your deployment names, resource IDs,
endpoints and locations never appear in the public catalog.
