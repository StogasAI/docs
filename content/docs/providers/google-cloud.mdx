Google Cloud deployments run Claude in your Google Cloud project. Google bills you for inference,
and we charge the [BYOK fee](/docs/byok#billing). Agent Platform on this page is Gemini Enterprise
Agent Platform, the service that Google called Vertex AI until April 2026.

| Deployment ID suffix   | Offering                                                        | Who runs Claude, and where      |
| ---------------------- | --------------------------------------------------------------- | ------------------------------- |
| None                   | Agent Platform, global endpoint                                 | Google, in any region           |
| `-us`                  | Agent Platform, US multi-region                                 | Google, in the United States    |
| `-eu`                  | Agent Platform, EU multi-region                                 | Google, in the European Union   |
| `-anthropic-hosted`    | Claude Models on Google Cloud (Anthropic managed)               | Anthropic, in any country       |
| `-anthropic-hosted-us` | Claude Models on Google Cloud (Anthropic managed), US inference | Anthropic, in the United States |

[Claude Models on Google Cloud (Anthropic managed)](https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/anthropic-managed)
serves the same models as Anthropic's own API,
except Claude Mythos before 5.2. Fast is available there for Claude Fable 5.2, Claude Mythos 5.2 and
Claude Opus 5.5, and models before Claude 4.6 have no US-only inference there.

## Create a credential

A [workload identity pool](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-other-providers)
holds no secret. Google Cloud trusts your organization's
[issuer](/docs/byok#federation), and the gateway exchanges its tokens for access that lasts one
hour.

1. Create a pool and a provider for your organization's issuer. [BYOK](/docs/byok) shows the
   issuer URL and the subject when you add a Google Cloud credential.

   ```bash
   gcloud iam workload-identity-pools create stogas \
     --project=PROJECT_ID --location=global
   gcloud iam workload-identity-pools providers create-oidc stogas \
     --project=PROJECT_ID --location=global --workload-identity-pool=stogas \
     --issuer-uri=https://app.stogas.ai/api/federation/<organization-id> \
     --attribute-mapping=google.subject=assertion.sub
   ```

   Leave the allowed audiences empty. The gateway sends the provider's default audience.

2. Give your organization the roles it needs:

   ```bash
   gcloud projects add-iam-policy-binding PROJECT_ID \
     --member="principal://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/stogas/subject/organization:<organization-id>" \
     --role=roles/aiplatform.user
   ```

   `roles/aiplatform.user` serves Agent Platform. For Claude Models on Google Cloud, grant
   `roles/claude.user` too.

3. Add the project ID and the provider's path in [BYOK](/docs/byok), with your workspace ID for
   Claude Models on Google Cloud:

   ```text
   projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/stogas/providers/stogas
   ```

To reach Google Cloud as a service account instead, grant your organization
`roles/iam.workloadIdentityUser` on the service account and add its email with the credential.

### Use a key file instead

1. Create a service account with the roles it needs, and a key for it:

   ```bash
   gcloud iam service-accounts create stogas-gateway --project=PROJECT_ID
   gcloud projects add-iam-policy-binding PROJECT_ID \
     --member=serviceAccount:stogas-gateway@PROJECT_ID.iam.gserviceaccount.com \
     --role=roles/aiplatform.user
   gcloud iam service-accounts keys create key.json \
     --iam-account=stogas-gateway@PROJECT_ID.iam.gserviceaccount.com
   ```

2. Add `key.json` in [BYOK](/docs/byok), with your workspace ID for Claude Models on Google Cloud,
   then delete `key.json`.

If `keys create` fails with a policy error, your organization blocks service account keys. Google
blocks them by default in organizations created since May 3, 2024. An organization policy
administrator can allow them in one project: override the parent's policy for the constraint that
blocks them, `iam.disableServiceAccountKeyCreation` or
`iam.managed.disableServiceAccountKeyCreation`, and turn enforcement off.

## Customer encryption

With [customer encryption](/docs/byok#customer-encryption), the CLI encrypts a credential
document, which for a workload identity pool holds `schema`, `projectId` and
`workloadIdentityProvider`, with `serviceAccountEmail` and `workspaceId` when you use them. It also
encrypts a key file as Google Cloud downloaded it:

```bash
stogas encrypt --key-file providers.key --organization <organization-id> \
  --credential google-cloud --input key.json
```

For Claude Models on Google Cloud, encrypt a credential document with your workspace ID instead:

```bash
jq --arg workspace wrkspc_... '{
  schema: "stogas.google-cloud-byok.v1",
  projectId: .project_id,
  clientEmail: .client_email,
  privateKeyId: .private_key_id,
  privateKey: (.private_key | gsub("-----[A-Z ]+-----|\\s"; "")),
  workspaceId: $workspace
}' key.json > google.json
stogas encrypt --key-file providers.key --organization <organization-id> \
  --credential google-cloud --input google.json
```

Then delete `key.json` and `google.json`, and add what the CLI printed in [BYOK](/docs/byok).

## Turn on Claude Fable on Agent Platform

1. Accept the Advanced AI Safety Addendum for your project in Model Garden.
2. Turn on sharing with Anthropic for each Claude Fable model in each location that you use:

   ```bash
   for model in claude-fable-5 claude-fable-5-1 claude-fable-5-2; do
     for location in global us eu; do
       host=aiplatform.googleapis.com
       [ "$location" = global ] || host="aiplatform.$location.rep.googleapis.com"
       curl -X POST "https://$host/v1beta1/projects/PROJECT_ID/locations/$location/publishers/anthropic/models/$model:setPublisherModelConfig" \
         -H "Authorization: Bearer $(gcloud auth print-access-token)" \
         -H "Content-Type: application/json" \
         -d '{"publisherModelConfig": {"dataSharingEnabledProvider": "ANTHROPIC"}}'
     done
   done
   ```

Google keeps the prompts and responses of Claude Fable for up to 30 days, and shares them with
Anthropic to
[monitor abuse](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/abuse-monitoring).
[`deployment.dataHandling.sharedWith`](/docs/policies/routing-fields#companies) of these deployments
is `['anthropic']`.

## Differences from Anthropic

Claude Models on Google Cloud works as on [Anthropic](/docs/providers/anthropic). On Agent
Platform, send files inline, because file URLs and file IDs are rejected. `web_search` and
`web_fetch` are not available.

On Agent Platform, a `json_schema` response format and strict tools work only once your
organization's `constraints/vertexai.allowedPartnerModelFeatures` policy allows structured outputs
for the model, which Google blocks by default. Allow one value for each model:

```yaml title="policy.yaml"
name: projects/PROJECT_NUMBER/policies/vertexai.allowedPartnerModelFeatures
spec:
  rules:
    - values:
        allowedValues:
          - publishers/anthropic/models/claude-sonnet-5-5:structured_outputs
```

```bash
gcloud org-policies set-policy policy.yaml
```
