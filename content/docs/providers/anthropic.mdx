Anthropic deployments run Claude models on the Anthropic Messages API with your own Anthropic API
key. Add the key in [BYOK](/docs/byok). The gateway converts Chat Completions and Responses requests
to Messages, so you can keep your OpenAI client.

## US and Fast deployments

Each option is a separate deployment with its own price, and its ID adds a suffix to the standard
deployment ID:

| Option | Effect                              | Example ID                        |
| ------ | ----------------------------------- | --------------------------------- |
| US     | Inference runs in the United States | `anthropic-claude-opus-5-us`      |
| Fast   | Faster output                       | `anthropic-claude-opus-5-fast`    |
| Both   |                                     | `anthropic-claude-opus-5-fast-us` |

Choose them by deployment ID, a [service tier](/docs/service-tiers) or a
[routing filter](/docs/policies/routing). Requests that send Anthropic's `speed` or `inference_geo`
field return `400`.

If your Anthropic workspace allows only US inference, turn on **Workspace allows only US inference**
for the credential, which saves this rule in its policy:

```json
{
	"rules": {
		"us-only-workspace": {
			"routing": {
				"filter": "!has(deployment.upstream.inferenceGeo) || deployment.upstream.inferenceGeo == 'us'"
			}
		}
	}
}
```

## Prompt caching

Anthropic caches only what you mark. Add a top-level `cache_control` to cache the longest reusable
prefix:

```json
{
	"model": "claude-sonnet-5",
	"cache_control": { "type": "ephemeral", "ttl": "1h" },
	"messages": [{ "role": "user", "content": "<long shared context>" }]
}
```

- To choose the cache boundaries yourself, put the same object on text, image or file blocks, or on
  tools outside a namespace.
- `ttl` is `5m`, the default, or `1h`.
- To fill the cache without generating output, send an output limit of `0`.

## Anthropic request fields

These fields work only on Anthropic deployments:

| Field                | Use                                                              |
| -------------------- | ---------------------------------------------------------------- |
| `top_k`              | Sample from the top K tokens.                                    |
| `stop_sequences`     | Another name for `stop`. Do not send both.                       |
| `task_budget`        | Tell the model how many tokens an agent task can use.            |
| `context_management` | Clear old thinking or tool results, or compact the conversation. |

```json title="Task budget and context editing"
{
	"model": "claude-opus-5",
	"task_budget": { "type": "tokens", "total": 200000 },
	"context_management": {
		"edits": [
			{ "type": "clear_thinking_20251015", "keep": { "type": "thinking_turns", "value": 2 } },
			{ "type": "clear_tool_uses_20250919" }
		]
	},
	"messages": [{ "role": "user", "content": "Audit the repository." }]
}
```

- `task_budget` guides the model and does not lower the
  [hold](/docs/usage#how-a-request-is-charged).
- `context_management.edits` accepts `clear_thinking_20251015`, `clear_tool_uses_20250919` and
  `compact_20260112`, each once. A compaction raises the hold to cover one more input pass and the
  summary.

## Reasoning

On Responses, Claude returns each thinking block as its own reasoning item, whose
`encrypted_content` holds the whole block when you [ask for it](/docs/reasoning#send-reasoning-back).

- On Chat Completions, `reasoning_details` holds the reasoning that starts each reply, which Claude
  continues from, and `reasoning` holds all of it. Later reasoning, such as a note before a tool
  call, is for display.
- Claude checks that its reasoning comes back after the same system prompt, tools and earlier
  messages. If one of them changed, Claude Fable 5.2, Mythos 5.2 and Mythos 5.1 return a 400 error,
  and other models can bill the reasoning. Send the request again without its reasoning to
  continue.
- To change instructions during a conversation, add a `system` or `developer` message right after
  the newest user message or tool results. It must be the last message or come right before
  Claude's reply. Claude Opus 4.8 and later, Sonnet 5.5 and later, Haiku 5.5 and later, Fable and
  Mythos accept it on every provider. Other models, and other positions, get a 400 error.

### Progress updates

Claude Fable, Mythos, Opus 5.5 and Sonnet 5.5 can write a short update before a tool call during
long work. Ask for the updates without the reasoning:

```json tab="Chat Completions"
{
	"model": "claude-fable-5-2",
	"messages": [{ "role": "user", "content": "Fix the failing test." }],
	"reasoning": { "effort": "medium", "display": "updates" }
}
```

```json tab="Responses"
{
	"model": "claude-fable-5-2",
	"input": "Fix the failing test.",
	"reasoning": { "effort": "medium", "summary": "updates" }
}
```

| Chat Completions `reasoning.display` | Responses `reasoning.summary` | The reply shows                              |
| ------------------------------------ | ----------------------------- | -------------------------------------------- |
| `summarized`                         | `auto`                        | A summary of the reasoning, and the updates. |
| `omitted`                            | `none`                        | No reasoning text.                           |
| `updates`                            | `updates`                     | The updates only.                            |

- Without the field, Claude uses its default, which is `omitted` on Claude 5 models.
- On Chat Completions, the updates arrive in `reasoning`, with a blank line between two. On
  Responses, each update is a reasoning item with the update as its summary.
- The effort is optional. Without it, Claude reasons as much as it does by default.
- A model that writes no updates gets `omitted` in place of `updates`.
- Send every reasoning entry back unchanged, also when its text is empty.

## Tools

- A request can use one hosted tool type.
- `web_search` runs as `web_search_20250305` and `web_fetch` as `web_fetch_20250910`. You can also
  name either version. A request that names another version gets a 400 error.
- `web_search` searches only the live web, so `external_web_access` must be `true` or left out.
  Codex sends `false` unless you set `web_search = "live"`.
- A `required` or named `tool_choice` makes Claude call the tool without reasoning first, and
  returns a 400 error together with a reasoning token budget. Claude Fable 5.2, Mythos 5.2, Fable
  5.1, Mythos 5.1, Opus 5.5 and Sonnet 5.5 take only `auto` and `none`.
- `custom` tools are not available.
- Claude gets each tool of a [namespace](/docs/model-tools#group-tools-in-namespaces) as a
  function, so a call in `input` must name a tool that `tools` declares in its namespace.

### Bash and text editor

```jsonc title="Responses"
{
	"model": "claude-sonnet-5",
	"input": "Fix the failing test.",
	"tools": [
		{ "type": "bash_20250124", "name": "bash" },
		{ "type": "text_editor_20250728", "name": "str_replace_based_edit_tool" }
	]
}
```

Claude calls both as functions. The call is a `function_call` item named `bash` or
`str_replace_based_edit_tool` with Anthropic's arguments, such as `{"command": "go test ./..."}`.
Run it in your application and send the result as a `function_call_output` item.

- Both tools work on Responses, with these versions and names only. The text editor also takes
  `max_characters`, and both take `cache_control`.
- No other tool can have their names, and `tool_choice` names them as functions.
- Both tools cost only tokens. Anthropic adds its own instructions to the input of each request:
  325 tokens for bash and 974 for the text editor on Claude Opus 4.7 and later models.
- Computer use and the memory tool are not available.
- See Anthropic's [bash](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool)
  and
  [text editor](https://platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool)
  guides for the arguments and results.

## Files

Send text files, including Markdown and CSV, as `text/plain`, for example
`data:text/plain;base64,...`. Anthropic downloads file URLs itself.

## Refusals

When Claude refuses before it writes any output, the request returns `200` with the finish reason
`content_filter`.
