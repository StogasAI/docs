AWS deployments run Claude in your AWS account. AWS bills you for inference, and we charge the
[BYOK fee](/docs/byok#billing).

| Deployment ID suffix | Offering                       | Who runs Claude, and where |
| -------------------- | ------------------------------ | -------------------------- |
| None                 | Amazon Bedrock, global profile | AWS, in any Region         |
| `-us`                | Amazon Bedrock, US profile     | AWS, in US Regions         |
| `-anthropic-hosted`  | Claude Platform on AWS         | Anthropic                  |

For example, `aws-claude-fable-5-1-us` runs Claude Fable 5.1 on Bedrock only in US Regions.

## Create a credential

Give an IAM user the policy in [Grant access](#grant-access), and add one of its keys in
[BYOK](/docs/byok) with a commercial Region, such as `us-east-1`. A Claude Platform on AWS workspace
must be in that Region.

| Key                                              | Serves                                               |
| ------------------------------------------------ | ---------------------------------------------------- |
| IAM access key                                   | Bedrock, and Claude Platform on AWS with a workspace |
| Bedrock API key                                  | Bedrock                                              |
| Claude Platform on AWS API key, with a workspace | Claude Platform on AWS                               |

`-us` deployments use the credential only if its Region is `us-east-1`, `us-east-2`, `us-west-1`
or `us-west-2`.

## Grant access

The IAM user that owns the key needs this policy:

```json title="IAM policy"
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Effect": "Allow",
			"Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
			"Resource": [
				"arn:aws:bedrock:*:*:inference-profile/*.anthropic.claude-*",
				"arn:aws:bedrock:*::foundation-model/anthropic.claude-*"
			]
		},
		{
			"Effect": "Allow",
			"Action": ["aws-external-anthropic:CreateInference", "aws-external-anthropic:ListModels"],
			"Resource": "arn:aws:aws-external-anthropic:*:*:workspace/*"
		}
	]
}
```

A Bedrock API key also needs `bedrock:CallWithBearerToken` and `bedrock:ListFoundationModels`,
and a Claude Platform on AWS API key needs `aws-external-anthropic:CallWithBearerToken`.

## Customer encryption

With [customer encryption](/docs/byok#customer-encryption), the CLI encrypts a credential
document that holds the same fields:

```json tab="Access key"
{
	"schema": "stogas.aws-byok.v1",
	"region": "us-east-1",
	"accessKeyId": "AKIA...",
	"secretAccessKey": "...",
	"workspaceId": "wrkspc_..."
}
```

```json tab="API key"
{
	"schema": "stogas.aws-byok.v1",
	"region": "us-east-1",
	"apiKey": "..."
}
```

Leave out `workspaceId` unless the credential serves Claude Platform on AWS. Save the document as
`aws.json`, then encrypt it:

```bash
stogas encrypt --key providers --organization <organization-id> \
  --purpose byok/aws --input aws.json --output credential.json
```

Delete `aws.json`, and add `credential.json` in [BYOK](/docs/byok).

## Differences from Anthropic

Claude Platform on AWS works as on [Anthropic](/docs/providers/anthropic). On Bedrock, send files
inline, because file URLs and file IDs are rejected. `web_search`, `web_fetch` and `task_budget`
are not available.
