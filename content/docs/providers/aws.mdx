AWS deployments run Claude in your AWS account. AWS bills you for inference, and we charge the
[BYOK fee](/docs/byok#billing).

| Deployment ID suffix   | Offering                             | Who runs Claude, and where      |
| ---------------------- | ------------------------------------ | ------------------------------- |
| None                   | Amazon Bedrock, global profile       | AWS, in any Region              |
| `-us`                  | Amazon Bedrock, US profile           | AWS, in US Regions              |
| `-eu`                  | Amazon Bedrock, EU profile           | AWS, in EU Regions              |
| `-jp`                  | Amazon Bedrock, Japan profile        | AWS, in Tokyo and Osaka         |
| `-au`                  | Amazon Bedrock, Australia profile    | AWS, in Sydney and Melbourne    |
| `-in`                  | Amazon Bedrock, India profile        | AWS, in Mumbai and Hyderabad    |
| `-ca`                  | Amazon Bedrock, Canada profile       | AWS, in Montreal and Calgary    |
| `-anthropic-hosted`    | Claude Platform on AWS               | Anthropic, in any country       |
| `-anthropic-hosted-us` | Claude Platform on AWS, US inference | Anthropic, in the United States |

For example, `aws-claude-fable-5-1-us` runs Claude Fable 5.1 on Bedrock only in US Regions.
[Claude Platform on AWS](https://platform.claude.com/docs/en/build-with-claude/claude-platform-on-aws)
serves the same models as Anthropic's own API, except Claude Mythos, and has
no Fast tier. Models before Claude 4.6 have no US-only inference there.

The catalog also lists Bedrock's profile of the AWS GovCloud (US) Regions, with the suffix
`-us-gov` and its own prices. We don't serve it, so a request for one of these deployments gets
`model_unavailable`.

## Create a credential

A role holds no secret. AWS
[trusts](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_create_oidc.html) your
organization's [issuer](/docs/byok#federation), and the
gateway assumes the role for one hour at a time.

1. Add your organization's issuer to IAM. [BYOK](/docs/byok) shows the issuer URL and the subject
   when you add an AWS credential.

   ```bash
   aws iam create-open-id-connect-provider \
     --url https://app.stogas.ai/api/federation/<organization-id> \
     --client-id-list sts.amazonaws.com
   ```

2. Save this trust policy as `trust.json`:

   ```json title="trust.json"
   {
   	"Version": "2012-10-17",
   	"Statement": [
   		{
   			"Effect": "Allow",
   			"Principal": {
   				"Federated": "arn:aws:iam::<account-id>:oidc-provider/app.stogas.ai/api/federation/<organization-id>"
   			},
   			"Action": "sts:AssumeRoleWithWebIdentity",
   			"Condition": {
   				"StringEquals": {
   					"app.stogas.ai/api/federation/<organization-id>:aud": "sts.amazonaws.com",
   					"app.stogas.ai/api/federation/<organization-id>:sub": "organization:<organization-id>"
   				}
   			}
   		}
   	]
   }
   ```

3. Save the policy from [Grant access](#grant-access) as `policy.json`, and create the role:

   ```bash
   aws iam create-role --role-name stogas-gateway \
     --assume-role-policy-document file://trust.json
   aws iam put-role-policy --role-name stogas-gateway \
     --policy-name stogas-claude --policy-document file://policy.json
   ```

4. Add the role's ARN in [BYOK](/docs/byok) with a commercial Region, such as `us-east-1`. A
   Claude Platform on AWS workspace must be in that Region.

### Use a key instead

1. Save the policy from [Grant access](#grant-access) as `policy.json`, and give it to a new IAM
   user:

   ```bash
   aws iam create-user --user-name stogas-gateway
   aws iam put-user-policy --user-name stogas-gateway \
     --policy-name stogas-claude --policy-document file://policy.json
   ```

2. Create the user's key:

   ```bash tab="Access key"
   aws iam create-access-key --user-name stogas-gateway
   ```

   ```bash tab="Bedrock API key"
   aws iam create-service-specific-credential --user-name stogas-gateway \
     --service-name bedrock.amazonaws.com --credential-age-days 365
   ```

3. Add the key in [BYOK](/docs/byok) with a commercial Region, such as `us-east-1`. A Claude
   Platform on AWS workspace must be in that Region.

| Credential                                       | Serves                                               |
| ------------------------------------------------ | ---------------------------------------------------- |
| IAM role                                         | Bedrock, and Claude Platform on AWS with a workspace |
| IAM access key                                   | Bedrock, and Claude Platform on AWS with a workspace |
| Bedrock API key                                  | Bedrock                                              |
| Claude Platform on AWS API key, with a workspace | Claude Platform on AWS                               |

A profile other than global uses the credential only from a Region that keeps it in its place:

| Profile | Credential Region                                        |
| ------- | -------------------------------------------------------- |
| `-us`   | `us-east-1`, `us-east-2`, `us-west-1` or `us-west-2`     |
| `-eu`   | `eu-central-1`, `eu-north-1`, `eu-west-1` or `eu-west-3` |
| `-jp`   | `ap-northeast-1` or `ap-northeast-3`                     |
| `-au`   | `ap-southeast-2`                                         |
| `-in`   | `ap-south-1`                                             |
| `-ca`   | `ca-central-1`                                           |

Other Regions can add their own Region: from `ca-central-1` the US profile also runs in Canada,
and from `eu-west-2` the EU profile also runs in London.

## Grant access

The role, or the IAM user that owns the key, needs this policy:

```json title="IAM policy"
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Effect": "Allow",
			"Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
			"Resource": [
				"arn:aws:bedrock:*:*:inference-profile/*.anthropic.claude-*",
				"arn:aws:bedrock:*::foundation-model/anthropic.claude-*"
			]
		},
		{
			"Effect": "Allow",
			"Action": ["aws-external-anthropic:CreateInference", "aws-external-anthropic:ListModels"],
			"Resource": "arn:aws:aws-external-anthropic:*:*:workspace/*"
		}
	]
}
```

A Bedrock API key also needs `bedrock:CallWithBearerToken` and `bedrock:ListFoundationModels`,
and a Claude Platform on AWS API key needs `aws-external-anthropic:CallWithBearerToken`.

## Turn on Claude Fable and Claude Mythos

```bash
curl -X PUT https://bedrock.us-east-1.amazonaws.com/data-retention \
  -H "Authorization: Bearer $AWS_BEARER_TOKEN_BEDROCK" \
  -H "Content-Type: application/json" \
  -d '{ "mode": "aws_review" }'
```

Bedrock rejects Claude Fable and Claude Mythos requests until your account's
[data retention mode](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html) is
`aws_review` in the Region of your credential. Run the command once for that Region, with a Bedrock
API key that has `bedrock:PutAccountDataRetention`. AWS then keeps the prompts and responses of
these models for up to 30 days in the Regions that run them, and can review them. AWS doesn't share
them with Anthropic. Claude Mythos also needs Anthropic's approval for your account.

## Customer encryption

With [customer encryption](/docs/byok#customer-encryption), the CLI encrypts a credential
document that holds the same fields:

```json tab="Role"
{
	"schema": "stogas.aws-byok.v1",
	"region": "us-east-1",
	"roleArn": "arn:aws:iam::123456789012:role/stogas-gateway"
}
```

```json tab="Access key"
{
	"schema": "stogas.aws-byok.v1",
	"region": "us-east-1",
	"accessKeyId": "AKIA...",
	"secretAccessKey": "...",
	"workspaceId": "wrkspc_..."
}
```

```json tab="API key"
{
	"schema": "stogas.aws-byok.v1",
	"region": "us-east-1",
	"apiKey": "..."
}
```

Leave out `workspaceId` unless the credential serves Claude Platform on AWS. Save the document as
`aws.json`, then encrypt it:

```bash
stogas encrypt --key providers --organization <organization-id> \
  --purpose byok/aws --input aws.json
```

Delete `aws.json`, and add what the CLI printed in [BYOK](/docs/byok).

## Differences from Anthropic

Claude Platform on AWS works as on [Anthropic](/docs/providers/anthropic). On Bedrock, send files
inline, because file URLs and file IDs are rejected. `web_search`, `web_fetch` and `task_budget`
are not available.
