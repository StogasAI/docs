OpenAI deployments run GPT models on the OpenAI API with your own OpenAI API key. Add the key in
[BYOK](/docs/byok). Chat Completions and Responses requests go to OpenAI's matching endpoints.
Deployments that take only Responses, such as Pro, get Chat Completions requests [through
Responses](/docs/providers#chat-completions-through-responses). So do the others for a request with
earlier reasoning, or with tools while the model reasons.

Keys from projects with [data residency](https://developers.openai.com/api/docs/guides/your-data)
don't work, because the gateway sends requests to `api.openai.com`.

A restricted key needs the permissions of the endpoints that your requests use. It doesn't need
permission to list models.

## Tiers and Pro

Each option is a separate deployment with its own price, and its ID adds a suffix to the standard
deployment ID:

| Option    | Effect                           | Select it with                                    |
| --------- | -------------------------------- | ------------------------------------------------- |
| Flex      | Lower price, slower responses    | `service_tier: "flex"` or a `-flex` ID            |
| Fast      | Higher price, faster responses   | `service_tier: "fast"` or a `-fast` ID            |
| Ultrafast | Highest price, fastest responses | `service_tier: "ultrafast"` or an `-ultrafast` ID |
| Pro       | More compute per request         | `"reasoning": { "mode": "pro" }` or a `-pro` ID   |

Pro combines with [Flex](https://developers.openai.com/api/docs/guides/flex-processing) or
[Fast](https://developers.openai.com/api/docs/guides/priority-processing), for example `openai-gpt-5.6-sol-pro-fast`.

## Prompt caching

OpenAI caches long prompts automatically. Deployments with `explicitPromptCaching` in the catalog
also let you mark where the cache ends:

```jsonc title="Chat Completions"
{
	"model": "gpt-5.6-sol",
	"prompt_cache_key": "contract-review-v3",
	"prompt_cache_options": { "mode": "explicit", "ttl": "30m" },
	"messages": [
		{
			"role": "user",
			"content": [
				{
					"type": "text",
					"text": "<the long reference document>",
					"prompt_cache_breakpoint": { "mode": "explicit" }
				},
				{ "type": "text", "text": "Which clauses limit liability?" }
			]
		}
	]
}
```

The gateway sends `prompt_cache_key`, `prompt_cache_options`, `prompt_cache_breakpoint` and
`prompt_cache_retention` as you set them, with one exception. OpenAI takes a `ttl` of `12h` only on
Responses, so the gateway sends it only in a Responses request, or a Chat Completions request
[through Responses](/docs/providers#chat-completions-through-responses), to a deployment that prices
`cache_write_12h_input_tokens` in the catalog. Other requests write the cache for the default `30m`,
which costs less. See [OpenAI's guide](https://developers.openai.com/api/docs/guides/prompt-caching)
for their values.

## Tools

Besides `function` tools, Responses accepts `custom` tools,
[namespaces](/docs/model-tools#group-tools-in-namespaces),
[tool search](/docs/model-tools#tool-search), `web_search` and
[remote MCP servers](/docs/model-tools#remote-mcp-servers). Search models take
`web_search_options` on Chat Completions instead of `tools`.

- A model without tool search returns `400` for deferred tools.
- `max_tool_calls` counts web searches and the calls of remote MCP servers together.
- `web_search` takes `search_content_types`. With `["text", "image"]`, a search can return images
  too.

### Shell and apply_patch

```jsonc title="Responses"
{
	"model": "gpt-5.6-sol",
	"input": "Fix the failing test.",
	"tools": [{ "type": "shell", "environment": { "type": "local" } }, { "type": "apply_patch" }]
}
```

The model returns `shell_call` and `apply_patch_call` items. Run the commands and apply the patches
in your application, then send the conversation again with each call and its `shell_call_output` or
`apply_patch_call_output` after it:

```jsonc
"input": [
	{ "role": "user", "content": "Fix the failing test." },
	{ "type": "shell_call", "call_id": "call_1", "action": { "commands": ["go test ./..."] } },
	{
		"type": "shell_call_output",
		"call_id": "call_1",
		"output": [{ "stdout": "ok", "stderr": "", "outcome": { "type": "exit", "exit_code": 0 } }]
	},
	{
		"type": "apply_patch_call",
		"call_id": "call_2",
		"status": "completed",
		"operation": { "type": "delete_file", "path": "old_test.go" }
	},
	{ "type": "apply_patch_call_output", "call_id": "call_2", "status": "completed" }
]
```

- `shell` runs only in your application: `environment` is `{ "type": "local" }` or left out, with
  optional `skills`. Hosted containers return `400`.
- Both tools cost only tokens. OpenAI adds its own instructions for each tool to the input of
  each request, and your usage counts them.
- `tool_choice` accepts `{ "type": "shell" }` and `{ "type": "apply_patch" }`, also in
  `allowed_tools`.
- See OpenAI's [shell](https://developers.openai.com/api/docs/guides/tools-shell) and
  [apply_patch](https://developers.openai.com/api/docs/guides/tools-apply-patch) guides for the
  call and result fields.

### Computer use

```jsonc title="Responses"
{
	"model": "gpt-5.6-sol",
	"input": "Open the settings page.",
	"tools": [{ "type": "computer" }]
}
```

The model returns a `computer_call` with a list of `actions`. Perform them in your application,
take a screenshot, and send the conversation again with the call and a `computer_call_output` after
it:

```jsonc
"input": [
	{ "role": "user", "content": "Open the settings page." },
	{
		"type": "computer_call",
		"id": "cu_123",
		"call_id": "call_1",
		"status": "completed",
		"actions": [{ "type": "click", "button": "left", "x": 412, "y": 88 }]
	},
	{
		"type": "computer_call_output",
		"call_id": "call_1",
		"output": { "type": "computer_screenshot", "image_url": "data:image/png;base64,iVBORw0KGgo..." }
	}
]
```

- The tool costs only tokens. OpenAI adds its own instructions for the tool to the input of each
  request, and a screenshot counts as an image.
- A screenshot follows the rules of an [image](/docs/input-files#send-an-image): a `file_id` needs
  your own credential, the [hold](/docs/usage#input-estimates) covers the deployment's full input
  limit, and [ASCII-only input](/docs/pii-redaction#ascii-only-input) and
  [PII redaction](/docs/pii-redaction) cannot read it.
- When a call has `pending_safety_checks`, repeat them in the output's
  `acknowledged_safety_checks` to go on.
- `tool_choice` accepts `{ "type": "computer" }`, also in `allowed_tools`.
- `computer_use_preview` returns `400`, because OpenAI retired the model that runs it.
- See OpenAI's [computer use guide](https://developers.openai.com/api/docs/guides/tools-computer-use)
  for the actions and their fields.

## Stored responses

```json title="A request that continues a stored response"
{
	"model": "provider:openai gpt-5.6-sol",
	"previous_response_id": "resp_123",
	"input": [{ "type": "function_call_output", "call_id": "call_1", "output": "42" }]
}
```

`store: true`, `previous_response_id` and `conversation` keep or read content in your OpenAI
account, on the Responses API of OpenAI's models. `store: true` also works on Chat Completions. A
request that no candidate can serve this way fails with `provider_state_unsupported`, and `param`
names the field.

- The gateway sends `store: false` unless the request sends `store: true`. A request with
  `previous_response_id` or `conversation` and no `store` stores its response, as OpenAI does by
  default, so that the next request can continue it. Send `store: true` with the first request of
  a chain.
- A request that reads stored content fails when more than one of your credentials can serve it.
  Name the provider in the model, such as `provider:openai gpt-5.6-sol`, or use a key with one
  credential for the model.
- Tool results in `input` can answer calls of the stored response, and an `mcp_approval_response`
  can answer an approval request of it.
- The [hold](/docs/usage#input-estimates) covers the deployment's full input limit, because the
  gateway cannot count stored content.
- A request that stores content has unknown retention and no zero data retention in
  [data handling](/docs/policies/routing-fields#data-handling), whatever the
  [account options](/docs/byok#account-options). The `request.store` and `request.storedInput`
  [request fields](/docs/policies/routing-fields#request) let a policy refuse such requests.
- [ASCII-only input](/docs/pii-redaction#ascii-only-input) and [PII redaction](/docs/pii-redaction)
  cannot read stored content, so a candidate whose policy sets either refuses a request that reads
  it.
- `metadata` reaches OpenAI only with a request that stores, where it labels what OpenAI keeps.

## Files

OpenAI [reads only the text](https://developers.openai.com/api/docs/guides/file-inputs) of a file
that is not a PDF, so convert a document to PDF to keep its
images and charts. It reads only the first rows of each sheet of a spreadsheet, CSV and TSV
included, and adds a summary that its model writes. To send every row of a spreadsheet, a CSV or
another text file, [extract text](/docs/text-extraction) on OpenAI deployments:

```json title="Policy"
{
	"rules": {
		"openai_full_text": {
			"when": "provider.id == 'openai'",
			"plugins": { "textExtraction": { "text": "always", "office": "always" } }
		}
	}
}
```

## Not available

- Audio and image output, and the `audio` request field.
- Prompt templates (`prompt`) and background mode (`background: true`).
- Async tool calls (`async: true`) and `configuration_update` input items.
- Hosted file search, code interpreter, shell containers and image generation.
- WebSocket mode and the Scale tier.
