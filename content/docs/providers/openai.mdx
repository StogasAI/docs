OpenAI deployments run GPT models on the OpenAI API with your own OpenAI API key. Add the key in
[BYOK](/docs/byok). Chat Completions and Responses requests go to OpenAI's matching endpoints.

## Data handling

Under OpenAI's standard API terms, OpenAI can keep prompts and responses for up to 30 days for abuse
monitoring, and does not use them for training. The gateway always sends `store: false`, so OpenAI
does not store responses for later retrieval. Your own agreement with OpenAI applies to requests on
your account.

API keys from projects with [data residency](https://developers.openai.com/api/docs/guides/your-data)
don't work yet. OpenAI accepts them only at their region's address, such as `eu.api.openai.com`,
and the gateway sends requests to `api.openai.com`.

## Tiers and Pro

OpenAI offers these options for some models. Each is a separate deployment with its own price, and
its ID adds a suffix to the standard deployment ID:

| Option    | Effect                                              | Select it with                                    |
| --------- | --------------------------------------------------- | ------------------------------------------------- |
| Flex      | Lower price, slower responses                       | `service_tier: "flex"` or a `-flex` ID            |
| Fast      | Higher price, faster responses                      | `service_tier: "fast"` or a `-fast` ID            |
| Ultrafast | Highest price, fastest responses, on Responses only | `service_tier: "ultrafast"` or an `-ultrafast` ID |
| Pro       | More compute per request, on Responses only         | `"reasoning": { "mode": "pro" }` or a `-pro` ID   |

You can combine Pro with Flex or Fast, for example `openai-gpt-5.6-sol-pro-fast`. The
[catalog](/docs/models#find-a-model) lists the deployments that exist for each model.
[Service tiers](/docs/service-tiers) explains how to select a tier and check which tier ran, and
[Reasoning](/docs/reasoning#select-pro-mode) explains Pro mode.

The gateway does not offer OpenAI's WebSocket mode, which OpenAI recommends with Ultrafast for agents
that make many tool calls in quick succession. OpenAI's Scale tier is not available.

## Output limit

OpenAI requires at least 16 output tokens. The gateway raises a `max_output_tokens` or
`max_completion_tokens` from 1 to 15 to 16, and the hold covers the raised value. Zero is rejected.
On Chat Completions, `max_tokens` is another name for `max_completion_tokens`.

## Reasoning models

OpenAI sets these limits for its reasoning models, and returns `400` for a request that breaks one:

- `temperature`, `top_p`, `logprobs` and `top_logprobs` work only with effort `none`. GPT-6 Astra
  and GPT-6.1 Sol cannot turn reasoning off, so they never accept these fields.
- On Chat Completions, GPT-6 Astra and GPT-6.1 Sol do not accept function tools, and GPT-6 Sol and
  GPT-6 Luna accept them only with `reasoning_effort: "none"`. Use Responses for tools with
  reasoning.

`max` effort works only on Responses. On Chat Completions, the gateway sends `xhigh` instead. See
[Reasoning](/docs/reasoning).

## Prompt caching

OpenAI caches prompts of 1,024 tokens or more automatically. Send the same `prompt_cache_key` with
prompts that share a prefix to get more cache hits.

Deployments with `explicitPromptCaching` in the catalog also let you mark where the cache ends. Add
`"prompt_cache_breakpoint": { "mode": "explicit" }` to a content block to cache everything up to and
including that block:

```jsonc title="Chat Completions"
{
	"model": "gpt-5.6-sol",
	"prompt_cache_key": "contract-review-v3",
	"prompt_cache_options": { "mode": "explicit", "ttl": "30m" },
	"messages": [
		{
			"role": "user",
			"content": [
				{
					"type": "text",
					"text": "<the long reference document>",
					"prompt_cache_breakpoint": { "mode": "explicit" }
				},
				{ "type": "text", "text": "Which clauses limit liability?" }
			]
		}
	]
}
```

- `prompt_cache_options.mode` is `implicit` or `explicit`. In `implicit` mode, OpenAI also adds a
  breakpoint of its own. In `explicit` mode, OpenAI caches only at your breakpoints.
- `prompt_cache_options.ttl` is `30m`.
- `prompt_cache_retention` is `in_memory` or `24h`, on models that use it.

OpenAI decides which blocks accept a breakpoint, how many breakpoints count, and which retention
each model accepts. It returns `400` for a value that the model does not accept. See
[OpenAI's guide](https://developers.openai.com/api/docs/guides/prompt-caching) for the current
rules.

Cache reads are billed at the cached-input rate, and writes at the cache-write rate where the
catalog lists one. See [Prompt caching](/docs/prompt-caching).

## Tools

| Tool                 | Endpoint                 | Charge                                                                                |
| -------------------- | ------------------------ | ------------------------------------------------------------------------------------- |
| `function`           | Both                     | Tokens only                                                                           |
| `custom`             | Responses                | Tokens only                                                                           |
| `web_search`         | Responses                | $10 per 1,000 searches, plus search content at model rates                            |
| `web_search_preview` | Responses                | Reasoning models: as `web_search`. Other models: $25 per 1,000 searches, content free |
| `web_search_options` | Chat, search models only | $10 per 1,000 requests, one search each                                               |

Dated tool versions, such as `web_search_2025_08_26`, are accepted. Search models, such as
`gpt-5-search-api`, take `web_search_options` instead of `tools`. See [Tools](/docs/model-tools) for
limits and holds.

## Files

GPT models accept images on both endpoints. Chat Completions accepts PDF documents. Responses also
accepts text, code, office documents and spreadsheets, and file URLs. The catalog lists each
route's file types as `documentFormats`. See [Images and files](/docs/input-files).

## Models that need approval

GPT-5.6 Cyber (`gpt-5.6-cyber`) is for organizations that OpenAI has approved for Daybreak Red. It
runs only on Responses, and only with an API key from a project that has Daybreak Red access.
Without access, OpenAI returns `404`.

The gateway does not send `access_programs`, so OpenAI chooses the program from your project's
access: Daybreak Red on `gpt-5.6-cyber`, and Daybreak Blue on mainline models such as `gpt-6-sol`
when your project has it. Daybreak does not turn on zero data retention.

When OpenAI's cyber safeguards block a request or suspend access, the error has code `cyber_policy`
and status `400`. In a stream, it can arrive as an error event after output has started.

## Not available

- Audio and image output, and the `audio` request field.
- Stored conversations: `store: true`, `previous_response_id`, `conversation` and `background`.
- Async tool calls (`async: true`) and `configuration_update` input items.
- Hosted file search, code interpreter, shell, computer use, image generation and remote MCP.
