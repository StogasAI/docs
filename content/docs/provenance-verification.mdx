title: Provenance Verification
description: Verify that a Stogas gateway release was reproducibly built by both Stogas and GitHub Actions.

Stogas release verification is centered on the compiled gateway VM artifact, not a separate catalog file.

The active catalog is embedded into the gateway release. If the release verifies, the catalog inside that release verifies with it.

## What Is Verified

Every gateway release publishes a deterministic `gateway.igvm`, a deterministic `gateway-launch-policy.json`, and a `release-manifest.json`.
The manifest and launch policy record:

- the public repository URL
- the immutable Git commit and tag
- the Git tree hash
- the `gateway.igvm` SHA-256 hash
- the SEV-SNP launch measurement
- the SEV-SNP launch policy comparison values clients must check in node quotes
- the pinned build inputs used by the reproducible build

Clients and auditors accept a release only when two independent parties bind the same IGVM hash, launch measurement, and launch policy values.

## GitHub Release Files

The public GitHub release contains only the files needed for normal client/auditor review:

| File                         | Role                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `LICENSE`                    | Canonical Apache-2.0 terms for the distributed gateway.                                       |
| `NOTICE`                     | Stogas LLC and upstream Bifrost attribution.                                                  |
| `gateway.igvm`               | Hardware-measurable confidential VM launch artifact.                                          |
| `gateway-launch-policy.json` | Canonical signed payload binding source, IGVM SHA-256, launch measurement, and launch policy. |
| `launch-measurement.txt`     | Expected SEV-SNP launch measurement.                                                          |
| `release-manifest.json`      | Deterministic manifest binding source, build pins, artifact hashes, and launch measurement.   |
| `SHA256SUMS`                 | Hashes for the top-level release files.                                                       |
| `github-attestation.jsonl`   | Official GitHub artifact attestation for `gateway.igvm` and `gateway-launch-policy.json`.     |
| `gateway-evidence.tar.zst`   | Advanced audit evidence: UKI, init, kernel, initramfs, pins, Guix, measurement, and hashes.   |

Stogas operator-side signing material is not uploaded as extra GitHub release assets. After reproducing the release, the operator signs the exact canonical `gateway-launch-policy.json` bytes. Control stores that detached signature in `stogas_signature` beside the matching `launch_policy` and GitHub attestation in one `allowed_igvms[]` slot.

## Verification Flow

<Steps>
<Step>

### Check Artifact Hashes

Hash `LICENSE`, `NOTICE`, `gateway.igvm`, `gateway-launch-policy.json`, `launch-measurement.txt`, `release-manifest.json`, `github-attestation.jsonl`, and `gateway-evidence.tar.zst`.
Their hashes must match `SHA256SUMS`; the manifest independently binds its recorded build and launch artifacts.
Advanced verifiers can unpack `gateway-evidence.tar.zst` and compare the contained UKI, init, kernel, initramfs, build pins, and measurement evidence against `release-manifest.json`.

</Step>
<Step>

### Verify The GitHub Actions Provenance

Verify `github-attestation.jsonl` with GitHub's official attestation verifier.

The attestation must prove that GitHub Actions built the canonical `StogasAI/gateway` repository, on the expected release workflow, for the release tag, and that the attested subject digests are the same `gateway.igvm` and `gateway-launch-policy.json` SHA-256 hashes from the manifest.

</Step>
<Step>

### Verify The Stogas Signature

For each `allowed_igvms[]` slot in the confidential bundle, verify `stogas_signature` against the hard-coded Stogas release public key. The signature must name `gateway-launch-policy.json`, and its canonical payload must equal the adjacent `launch_policy`. That policy binds the repository, commit, tree, tag, IGVM hash, launch measurement, launch values, release name, sequence, and measured vCPU count.

Do not verify this signature with application helpers or a key supplied by the bundle. The official Stogas verifier pins the release root, reproduces the exact canonical launch-policy bytes, and requires the independently verified GitHub attestation to bind those same bytes and the IGVM digest.

When auditing an operator-side release directory, the Stogas signature payload is:

```text
stogas gateway launch policy v1\n<canonical gateway-launch-policy.json>
```

The operator-side signature object is an input to Control policy, not an additional GitHub release file.

</Step>
<Step>

### Require Agreement

Accept the release only when Stogas and GitHub Actions independently agree on:

- the source repository
- the immutable tag and commit
- the Git tree hash
- the `gateway.igvm` SHA-256 hash
- the SEV-SNP launch measurement
- the launch policy values in `gateway-launch-policy.json`

If either side is missing or disagrees, reject the release.

</Step>
</Steps>

## Catalog Integrity

The catalog is not verified as a separate downloaded proof object.
It is generated into the gateway source tree and embedded in the measured gateway release.

That means catalog integrity follows the gateway release:

- the generated catalog bytes affect the gateway build
- the gateway build produces the `gateway.igvm` hash
- the IGVM hash is independently bound by Stogas and GitHub Actions
- running nodes must report a launch measurement accepted from that verified release

The public catalog endpoint and catalog page are discovery surfaces. They help users inspect the active gateway behavior, but release acceptance comes from IGVM provenance verification.
