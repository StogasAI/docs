title: Provenance Verification
description: Verify that a Stogas gateway release was reproducibly built by both Stogas and GitHub Actions.

Stogas release verification is centered on the compiled gateway VM artifact, not a separate catalog file.

The active catalog is embedded into the gateway release. If the release verifies, the catalog inside that release verifies with it.

## What Is Verified

Every gateway release publishes a deterministic `gateway.igvm` file and a `release-manifest.json`.
The manifest records:

- the public repository URL
- the immutable Git commit and tag
- the Git tree hash
- the `gateway.igvm` SHA-256 hash
- the SEV-SNP launch measurement
- the pinned build inputs used by the reproducible build

Clients and auditors accept a release only when two independent parties bind the same IGVM hash and launch measurement.

## Release Files

The release artifact set contains:

| File                         | Role                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| `gateway.igvm`               | Hardware-measurable confidential VM launch artifact.                                        |
| `gateway.efi`                | Unified Kernel Image injected into the IGVM.                                                |
| `launch-measurement.txt`     | Expected SEV-SNP launch measurement.                                                        |
| `release-manifest.json`      | Deterministic manifest binding source, build pins, artifact hashes, and launch measurement. |
| `SHA256SUMS`                 | Hashes for the release files.                                                               |
| `github-attestation.jsonl`   | GitHub Actions/Sigstore provenance for the IGVM hash.                                       |
| `sigstore-trust-bundle.json` | Release-time Sigstore trust material authenticated from the pinned TUF root.                |
| `stogas-release-claim.json`  | Stogas claim over the same manifest, IGVM hash, and launch measurement.                     |
| `gateway.sig`                | Stogas signature over `stogas-release-claim.json`.                                          |
| `stogas-trust.json`          | Stogas release-key delegation verified from the bootstrap public key.                       |

## Verification Flow

<Steps>
<Step>

### Check Artifact Hashes

Hash `gateway.igvm`, `gateway.efi`, `launch-measurement.txt`, and `release-manifest.json`.
The hashes must match both `SHA256SUMS` and the values recorded in `release-manifest.json`.

</Step>
<Step>

### Verify The Stogas Claim

Verify `stogas-trust.json` from the hard-coded Stogas bootstrap public key.
Then use the delegated release key to verify `gateway.sig` over:

```text
stogas gateway release claim v1\n<stogas-release-claim.json>
```

The claim must bind the same `release-manifest.json` hash, `gateway.igvm` hash, repository, commit, tag, and SEV-SNP launch measurement.

</Step>
<Step>

### Verify The GitHub Actions Provenance

Authenticate `sigstore-trust-bundle.json` from the pinned Sigstore TUF root hash.
Then verify `github-attestation.jsonl` offline against that authenticated trust material.

The attestation must prove that GitHub Actions built the canonical `StogasAI/gateway` repository, on the expected release workflow, for the release tag, and that the attested subject digest is the same `gateway.igvm` SHA-256 hash from the manifest.

</Step>
<Step>

### Require Agreement

Accept the release only when Stogas and GitHub Actions independently agree on:

- the source repository
- the immutable tag and commit
- the Git tree hash
- the `gateway.igvm` SHA-256 hash
- the SEV-SNP launch measurement

If either side is missing or disagrees, reject the release.

</Step>
</Steps>

## Catalog Integrity

The catalog is not verified as a separate downloaded proof object.
It is generated into the gateway source tree and embedded in the measured gateway release.

That means catalog integrity follows the gateway release:

- the generated catalog bytes affect the gateway build
- the gateway build produces the `gateway.igvm` hash
- the IGVM hash is independently bound by Stogas and GitHub Actions
- running nodes must report a launch measurement accepted from that verified release

The public catalog endpoint and catalog page are discovery surfaces. They help users inspect the active gateway behavior, but release acceptance comes from IGVM provenance verification.
