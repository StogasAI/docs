title: Evidence Bundle
description: Understand the public snapshot used to verify Stogas gateways.

The Stogas evidence bundle is a public, continuously updated snapshot of the confidential gateway fleet. It tells a verifier which gateway releases and connection keys can currently be trusted.

Verification happens locally. A client downloads one JSON file, checks its embedded evidence, and receives a trusted set of gateways without contacting GitHub, AMD, Sigstore, or drand.

## Endpoints

```text
https://evidence.stogas.ai/bundles/latest.json
```

The endpoint supports public browser `GET` and `HEAD` requests.

## What a verified bundle provides

- Gateway releases proven to come from the public Stogas gateway repository and authorized by Stogas.
- Confidential gateway nodes running an approved release on AMD SEV-SNP hardware.
- The attested certificate, TLS, response-signing, and encryption keys for each trusted gateway.
- An `expires_at` deadline after which the snapshot must not be used.

The verifier returns fresh gateways under `nodes`. Cryptographically valid records that are too old for the selected freshness policy appear under `excluded_nodes` and are not trusted for connections.

## Refreshing

Refresh before `expires_at`. That signed deadline is the only bundle lifetime a client needs to schedule around.

[`stogas-verify serve`](/docs/cli) maintains a replacement in the background and keeps using the current verified bundle until a newer one passes. SDK users choose their own retrieval schedule.

If no valid replacement is available by the deadline, the expired bundle must not authorize a new connection.

## Freshness policy

The default verifier policy accepts node evidence that was no more than two minutes old when the bundle was created. Applications may select one to 15 minutes.

Changing this policy affects which gateways enter the local trusted set. It does not change the signed bundle expiry or other verified gateways.

For installation and examples, choose the [CLI](/docs/cli) or an [SDK](/docs/sdk). For the underlying guarantees, see the [security model](/docs/confidential-security-model).
