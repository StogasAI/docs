title: Catalog Verification
description: Understand how the public catalog is tied to the measured Stogas gateway release.
---

The public catalog is embedded in the Stogas gateway release artifact. There is no separate
catalog bundle to download, sign, mirror, or verify.

## Authority

Catalog authority comes from the gateway IGVM release:

1. Gateway source includes readable YAML/CUE catalog source.
2. The build generates deterministic `catalog.json`.
3. The generated JSON is embedded in the Go gateway binary.
4. The binary is packaged into the measured IGVM.
5. GitHub Actions and the local Stogas CLI independently rebuild the same IGVM hash.
6. The release is accepted only when the IGVM hash and SEV-SNP launch measurement match both claims.

The website catalog page calls the active gateway API and displays what the gateway is currently
serving. It is an inspection surface, not a separate trust oracle.

## Public Endpoints

- `GET /v1/catalog`: full active resolved catalog, catalog hash, indexes, pricing, and policy profile descriptions.
- `GET /v1/models`: OpenAI-compatible model list from the same active catalog.
- `GET /health/catalog`: compact operator status with catalog hash and counts.

Responses include `X-Stogas-Catalog-Hash` where useful for audit/debugging. That hash is useful for
comparing gateway responses with `/v1/catalog`, but release authority is the measured gateway IGVM.

## Release Flow

`bun stogas gateway release propose --tag vX.Y.Z` creates/pushes the immutable gateway tag and
dispatches the Stogas-owned GitHub workflow. GitHub builds the deterministic IGVM draft and attaches:

- `gateway.igvm`
- `release-manifest.json`
- `SHA256SUMS`
- `github-attestation.jsonl`

`bun stogas gateway release publish --tag vX.Y.Z` downloads the draft, rebuilds locally with the same
Guix pins, compares IGVM hash and launch measurement, signs `stogas-release-claim.json`, uploads the
Stogas signature/trust material, and publishes the release.
