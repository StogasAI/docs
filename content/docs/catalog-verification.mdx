---
title: Catalog Verification
description: Verify that a catalog bundle is approved by the public signing key and the public GitHub build.
---

Catalog verification is one local check over one downloaded object. The CDN is only a carrier:
it can make the bundle unavailable or stale, but it cannot make a modified catalog verify.

```text
canonical catalog object
  -> SHA-256
  -> releaseManifest.artifacts["catalog.json"].sha256
  -> Stogas keyring authorizes the release key for this sequence
  -> Ed25519 signature over releaseManifest
  -> Sigstore TUF metadata authenticates trusted_root.json from a pinned root
  -> Fulcio/Rekor/DSSE prove GitHub Actions attested the same SHA-256
```

<Callout type="warn">
	Never edit `releaseManifest`. Verifiers canonicalize it and verify the signature over `stogas
	catalog release v1\n` plus those exact canonical bytes.
</Callout>

## Bundle Shape

Fetch and decompress:

```text
https://evidence.stogas.ai/catalog/releases/latest/catalog-bundle.json.gz
```

The result is one JSON object:

```jsonc
{
	// Bundle format. Verifiers reject unknown schemas.
	"schema": "stogas.evidence.catalog-bundle.v1",

	// The compiled catalog object. Verifiers canonicalize this object and hash those bytes.
	"catalog": {
		"graph": {
			"models": {
				"gpt-5.5-2026-04-23": {
					"canonicalSlug": "gpt-5.5-2026-04-23"
				}
			}
		}
	},

	// The manifest is signed by Stogas and independently checked against GitHub's build output.
	"releaseManifest": {
		"schema": "stogas.catalog.release.v1",
		"sequence": 42,
		"git": {
			"repository": "https://github.com/StogasAI/catalog",
			"ref": "refs/heads/main",
			"tag": "catalog-v42",
			"commit": "0123456789abcdef0123456789abcdef01234567",
			"tree": "89abcdef0123456789abcdef0123456789abcdef"
		},
		"build": {
			"command": "bun stogas catalog release build",
			"environment": { "LANG": "C", "LC_ALL": "C", "TZ": "UTC" },
			"toolchain": {
				"bun": "1.3.3",
				"node": "26.4.0",
				"cue": "go run cuelang.org/go/cmd/cue@v0.16.1",
				"canonicalizer": "stogas-json-stable-v1"
			}
		},
		"artifacts": {
			"catalog.json": {
				"sha256": "5502bfc3b49dc7f7ab462d69fbed5099e53a9c9d2da13c2a20fa5fe902513a79",
				"sizeBytes": 96
			}
		}
	},

	// Stogas signature over: "stogas catalog release v1\n" + canonical releaseManifest.
	"stogasSignature": {
		"schema": "stogas.catalog.signature.v1",
		"algorithm": "Ed25519",
		"keyId": "stogas-ed25519-stamp-v1",
		"signed": "release-manifest.json",
		"signature": "base64..."
	},

	// Public release-key keyring. It is signed by the hardcoded Stogas bootstrap key.
	"stogasTrust": {
		"schema": "stogas.trust.v1",
		"keys": [
			{
				"keyId": "stogas-ed25519-stamp-v1",
				"purpose": "release",
				"algorithm": "Ed25519",
				"validFromSequence": 1,
				"publicKey": { "type": "spki", "derBase64": "MCow..." }
			}
		],
		"signatures": [{ "keyId": "stogas-ed25519-stamp-v1", "signature": "base64..." }]
	},

	// GitHub Artifact Attestation bundle. It carries the Fulcio cert, Rekor SET, and DSSE statement.
	"githubAttestation": {
		"mediaType": "application/vnd.dev.sigstore.bundle.v0.3+json",
		"verificationMaterial": {
			"certificate": { "rawBytes": "base64 DER Fulcio certificate" },
			"tlogEntries": [{ "logId": { "keyId": "base64 Rekor log id" } }]
		},
		"dsseEnvelope": {
			"payloadType": "application/vnd.in-toto+json",
			"payload": "base64 in-toto statement",
			"signatures": [{ "sig": "base64 DSSE signature" }]
		}
	},

	// Sigstore public trust material, proven locally from the pinned TUF bootstrap root.
	"sigstoreTrust": {
		"schema": "sigstore.tuf.trust.v1",
		"rootChain": ["raw 10.root.json", "...", "raw current root.json"],
		"metadata": {
			"timestamp": "raw timestamp.json",
			"snapshot": "raw versioned snapshot.json",
			"targets": "raw versioned targets.json"
		},
		"trustedRoot": "raw trusted_root.json"
	}
}
```

| Field               | Meaning                                                                               |
| ------------------- | ------------------------------------------------------------------------------------- |
| `catalog`           | The compiled catalog object. Canonicalize this object, then hash the canonical bytes. |
| `releaseManifest`   | The signed manifest containing the expected catalog hash, repo, tag, and sequence.    |
| `stogasTrust`       | Signed public keyring that says which Stogas release key is valid for each sequence.  |
| `stogasSignature`   | Ed25519 signature over the canonical release manifest payload.                        |
| `githubAttestation` | Sigstore bundle containing Fulcio certificate, Rekor material, and DSSE statement.    |
| `sigstoreTrust`     | TUF metadata plus `trusted_root.json` used to verify Fulcio and Rekor material.       |

## Trust Anchors

Hardcode two stable anchors.

First, hardcode the Stogas bootstrap key. This is the root that signs `stogasTrust`;
release keys may rotate inside the signed keyring without changing verifier code.

```text
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEAByVn3LvWVbf3YkokMZPvir70vcDu0nNflgXoM0Y8aQU=
-----END PUBLIC KEY-----
```

```text
key id: stogas-ed25519-stamp-v1
SPKI DER SHA-256: e8aac1a58efdd441870e565cf0b7df9bbb59531e744556fb46f65ca9d949e121
raw Ed25519 public key hex: 072567dcbbd655b7f7624a243193ef8abef4bdc0eed2735f9605e833463c6905
```

Second, hardcode the Sigstore TUF bootstrap root. This implementation pins root metadata version
10 by the SHA-256 of its canonical signed body. That pinned root contains the TUF role keys and
thresholds. The bundle then carries the sequential root chain and current metadata needed to prove
new Fulcio/Rekor material without a network call.

```text
bootstrap root version: 10
bootstrap root signed-body SHA-256: e708f5c51a3e5168aafe0fb5235be9f711e8f9534f2c4c668e45fa714d900028
sigstoreTrust.rootChain -> raw sequential root metadata from root 10 to current root
sigstoreTrust.metadata.targets -> raw targets metadata containing trusted_root.json hash
sigstoreTrust.trustedRoot -> Fulcio CA chains and Rekor public keys with validity intervals
GitHub OIDC policy: issuer https://token.actions.githubusercontent.com
Certificate SAN: https://github.com/StogasAI/stogas-ai/.github/workflows/catalog-release.yml@refs/heads/main
Subject digest: sha256(canonical catalog)
```

TUF root keys are designed to be long-lived. If Sigstore rotates operational Fulcio/Rekor keys,
clients learn the new public material from the bundle after verifying the TUF chain. If Sigstore
rotates the TUF root itself, TUF root chaining proves the new root from the old pinned root.

## Steps

<Steps>
<Step>

### Decompress

```bash
BASE="https://evidence.stogas.ai"
curl -fsSL "$BASE/catalog/releases/latest/catalog-bundle.json.gz" -o catalog-bundle.json.gz
gunzip -c catalog-bundle.json.gz > catalog-bundle.json
jq -e '.schema == "stogas.evidence.catalog-bundle.v1"' catalog-bundle.json >/dev/null
```

</Step>
<Step>

### Hash the catalog

Canonicalization is stable JSON: object keys sorted lexicographically, no whitespace, trailing newline.

```bash
jq -S -c '.catalog' catalog-bundle.json | sed '$s/$//' > catalog.json
printf '\n' >> catalog.json
CATALOG_SHA="$(shasum -a 256 catalog.json | awk '{print $1}')"
MANIFEST_SHA="$(jq -r '.releaseManifest.artifacts["catalog.json"].sha256' catalog-bundle.json)"
test "$CATALOG_SHA" = "$MANIFEST_SHA"
```

Example hash:

```text
5502bfc3b49dc7f7ab462d69fbed5099e53a9c9d2da13c2a20fa5fe902513a79
```

Do not write `CATALOG_SHA` into `releaseManifest`; that would create a different signed payload.

</Step>
<Step>

### Verify the Stogas keyring and release signature

First verify `stogasTrust` with the hardcoded bootstrap key. Then select
`stogasSignature.keyId` from `stogasTrust.keys` and require that key to be valid for
`releaseManifest.sequence`.

```bash
jq -S -c '.releaseManifest' catalog-bundle.json | sed '$s/$//' > release-manifest.json
printf '\n' >> release-manifest.json
jq -r '.stogasSignature.signature' catalog-bundle.json | base64 -d > catalog.sig.bin
jq -S -c '{keys: .stogasTrust.keys, schema: .stogasTrust.schema}' catalog-bundle.json | sed '$s/$//' > stogas-trust-body.json
printf '\n' >> stogas-trust-body.json

cat > stogas-bootstrap-public.pem <<'KEY'
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEAByVn3LvWVbf3YkokMZPvir70vcDu0nNflgXoM0Y8aQU=
-----END PUBLIC KEY-----
KEY

{ printf 'stogas trust v1\n'; cat stogas-trust-body.json; } > stogas-trust-payload.bin
jq -r '.stogasTrust.signatures[0].signature' catalog-bundle.json | base64 -d > stogas-trust.sig.bin
openssl pkeyutl -verify -pubin -inkey stogas-bootstrap-public.pem -rawin \
	-in stogas-trust-payload.bin \
	-sigfile stogas-trust.sig.bin

{ printf 'stogas catalog release v1\n'; cat release-manifest.json; } > signed-payload.bin
RELEASE_KEY_ID="$(jq -r '.stogasSignature.keyId' catalog-bundle.json)"
RELEASE_KEY_DER="$(jq -r --arg id "$RELEASE_KEY_ID" '.stogasTrust.keys[] | select(.keyId == $id) | .publicKey.derBase64' catalog-bundle.json)"
printf '%s' "$RELEASE_KEY_DER" | base64 -d > stogas-release-key.der
openssl pkeyutl -verify -pubin -inform DER -inkey stogas-release-key.der -rawin \
	-in signed-payload.bin \
	-sigfile catalog.sig.bin
```

</Step>
<Step>

### Verify Sigstore trust and GitHub's attestation

Decode `githubAttestation.dsseEnvelope.payload`. It is an in-toto statement whose
`subject[].digest.sha256` must equal `CATALOG_SHA`.

First verify `sigstoreTrust` locally:

```text
1. Parse each raw JSON string in sigstoreTrust.rootChain and verify the canonical signed body from pinned root 10 to the current root.
2. Verify the raw timestamp.json, snapshot.json, and targets.json strings with the current TUF roles.
3. Hash the raw sigstoreTrust.trustedRoot string and compare it to targets.json trusted_root.json metadata.
4. Extract Fulcio CA chains and Rekor public keys from the verified trusted root.
5. Verify the Fulcio certificate chain and validity at the Rekor integrated time.
6. Verify the certificate SAN and GitHub OIDC issuer match policy.
7. Verify the DSSE signature over DSSE PAE(payloadType, payload) using the certificate public key.
8. Verify Rekor signedEntryTimestamp using the Rekor key valid at logId.keyId and integratedTime.
9. Verify the DSSE payload subject digest equals CATALOG_SHA.
```

No GitHub API, Rekor API, or Fulcio API call is needed when the trust roots are already present.

</Step>
<Step>

### Enforce order

```bash
SEQUENCE="$(jq -r '.releaseManifest.sequence' catalog-bundle.json)"
test "$SEQUENCE" -gt "$LAST_ACCEPTED_SEQUENCE"
```

</Step>
</Steps>

## Language Recipes

All recipes use the same primitives:

```text
canonicalizeCatalog(bundle.catalog) -> catalogBytes
sha256(catalogBytes) -> catalogSha
canonicalize(bundle.releaseManifest) -> manifestBytes
verifyStogasTrust(bundle.stogasTrust, STOGAS_BOOTSTRAP_PUBLIC_KEY)
verifyStogasSignature(bundle.stogasSignature, manifestBytes, bundle.stogasTrust, sequence)
verifySigstoreTrust(bundle.sigstoreTrust, SIGSTORE_TUF_ROOT_10)
verifyGitHubAttestation(bundle.githubAttestation, verifiedSigstoreTrust, catalogSha, GitHub policy)
```

The snippets below are intentionally small. Production verifiers should keep each helper separate
so failures identify exactly which proof failed.

## Acceptance Rule

Accept the bundle only when all checks succeed:

```text
sha256(canonical catalog) == releaseManifest.artifacts["catalog.json"].sha256
stogasTrust is signed by the hardcoded Stogas bootstrap key
stogasSignature key is valid for releaseManifest.sequence
Stogas release signature verifies over the canonical releaseManifest payload
sigstoreTrust verifies from the hardcoded Sigstore TUF bootstrap root
Fulcio certificate chains to trusted_root.json and was valid at Rekor integratedTime
Rekor signedEntryTimestamp verifies with the Rekor key valid at integratedTime
DSSE signature verifies with the Fulcio certificate public key
GitHub/Sigstore subject digest == sha256(canonical catalog)
GitHub OIDC issuer, repository, workflow, and ref identity match policy
Release sequence is greater than the last accepted sequence
```

If any check fails, discard the bundle.
