---
title: Images and files
description: Send images and documents to models that accept them, inline, by URL or by file ID.
icon: Paperclip
---

Add images and documents to a message as content blocks. The gateway sends the request only to
[candidates that can read every attachment](#when-no-candidate-reads-a-file). The provider checks
the file itself.

| Input    | Chat Completions | Responses     |
| -------- | ---------------- | ------------- |
| Image    | `image_url`      | `input_image` |
| Document | `file`           | `input_file`  |

## Send an image

```json tab="Chat Completions"
{
	"model": "gpt-5.6-sol",
	"messages": [
		{
			"role": "user",
			"content": [
				{ "type": "text", "text": "What does this chart show?" },
				{
					"type": "image_url",
					"image_url": { "url": "https://example.com/chart.png", "detail": "high" }
				}
			]
		}
	]
}
```

```json tab="Responses"
{
	"model": "gpt-5.6-sol",
	"input": [
		{
			"role": "user",
			"content": [
				{ "type": "input_text", "text": "What does this chart show?" },
				{ "type": "input_image", "image_url": "data:image/png;base64,iVBORw0KGgo..." }
			]
		}
	]
}
```

An image can be an HTTP(S) URL or a base64 data URL. On Responses, `file_id` also works[^sources].

## Send a document

```jsonc tab="Chat Completions"
{
	"model": "gpt-5.6-sol",
	"messages": [
		{
			"role": "user",
			"content": [
				{ "type": "text", "text": "List the deadlines in this contract." },
				{
					"type": "file",
					"file": {
						"filename": "contract.pdf",
						// A base64 data URL that names the MIME type.
						"file_data": "data:application/pdf;base64,JVBERi0xLjcK..."
					}
				}
			]
		}
	]
}
```

```jsonc tab="Responses"
{
	"model": "gpt-5.6-sol",
	"input": [
		{
			"role": "user",
			"content": [
				{ "type": "input_text", "text": "List the deadlines in this contract." },
				// The provider downloads the file. The gateway does not.
				{ "type": "input_file", "file_url": "https://example.com/contract.pdf" }
			]
		}
	]
}
```

Give each document exactly one source:

| Field       | Contents                                                     | Works on                                 |
| ----------- | ------------------------------------------------------------ | ---------------------------------------- |
| `file_data` | A base64 data URL, such as `data:application/pdf;base64,...` | Every deployment that accepts documents  |
| `file_url`  | An HTTP(S) URL                                               | Responses[^sources]                      |
| `file_id`   | A file that you uploaded to the provider                     | [BYOK](/docs/byok) credentials[^sources] |

If the data URL has no MIME type or uses `application/octet-stream`, `filename` must end in an
extension that the route accepts.

## Supported formats

Each catalog route lists the document types that it reads as `documentFormats`, and each
deployment lists its input types as `inputModalities`. Search the
[catalog](https://stogas.ai/catalog) to find them:

| Search                                  | Finds                        |
| --------------------------------------- | ---------------------------- |
| `deployment.inputModalities:image`      | Deployments that read images |
| `route.documentFormats.extensions:.pdf` | Routes that read PDFs        |

The provider can convert a document before the model reads it, so a model that reads only text can
still accept a PDF. The [provider pages](/docs/providers) list each provider's file rules.

## When no candidate reads a file

[Routing](/docs/policies/routing) leaves out each candidate that cannot read an attachment. This
uses none of the [fallbacks](/docs/policies/routing#retries-and-fallbacks). A candidate cannot read
an attachment when:

- Its deployment or route does not take the input type or the [source](#send-a-document). See
  [Supported formats](#supported-formats).
- The attachment is a `file_id`, and the candidate's credential is not [BYOK](/docs/byok).
- Its policy sets [ASCII-only input](/docs/pii-redaction#ascii-only-input) or
  [PII redaction](/docs/pii-redaction). These need text, so they refuse URLs, file IDs and files
  that the gateway does not [extract](/docs/text-extraction).

When no candidate is left that can read an attachment, the request fails at once with
`attachment_unsupported`, and `param` names the attachment. If a candidate that can read it left
for another reason, such as a disabled credential, the error gives that reason. If every attachment
has a candidate but no candidate reads them all, the error names them; send them in separate
requests.

## Limits

- URLs, file IDs and files that the gateway does not extract reserve the deployment's full input
  limit in the [hold](/docs/usage#how-a-request-is-charged), because the gateway cannot count their
  tokens.
- Base64 and JSON encoding count toward the [128 MiB request limit](/docs/reference/security#limits).
  The provider applies its own file, page and size limits.
- Audio input (`input_audio` on Chat Completions) works only on deployments that list `audio` in
  `inputModalities`.
- Models return text, tool calls and citations. Image and audio output are not available.

[^sources]:
    Anthropic models also take `file_url` on Chat Completions, and do not take an image
    `file_id`. Claude that AWS or Google runs takes neither URLs nor file IDs.
